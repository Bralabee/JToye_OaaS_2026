## Instrument notes

- **A paths-filtered job reports SUCCESS when skipped**, by design, so it stays a satisfiable required
  check. When recording evidence that the gate runs, read the step's output. A green check in six
  seconds means nothing ran.
- **Re-measure the non-vacuity counts.** RESEARCH's a11y baseline is valid only to 2026-08-22 and four
  plans have changed markup since. Assert the SHAPE (a non-zero content count), not yesterday's number.
- **Rebuild before any E2E claim.** `docker compose start` does not rebuild. Prove parity by content:
  compare each image's `.Metadata.LastTagTime` (NOT `.Created`, which survives a fully cached rebuild)
  against the newest commit touching that image's build paths. `scripts/check-runtime-freshness.sh`
  fails closed at exit 2 and VOIDs per service.
- **A rebuild reds `check-alert-metrics`** — a known consequence of restarting core-java, not a
  finding. Run `scripts/seed-order-metric.sh` rather than investigating.
- **Run the runtime-freshness and config-drift gates from the MAIN checkout**, not from a worktree —
  the compose project name comes from the directory and they VOID otherwise.
- **Commit before any break arm.** `git checkout` restores from the INDEX and discards post-staging
  edits. Verify each restore by `git hash-object` against `git rev-parse HEAD:<path>`, never by
  `git diff --stat`, which is empty both when a file is restored and when it was never written.
- **Bracket the arms: clean -> break -> clean.** The closing clean run is the only proof the restores
  happened.
- **`git log HEAD..origin/main` must be empty** before opening the PR, or a merge from the base must
  be recorded. A branch behind its base ships a runtime missing already-merged work.
- **Backticks inside double quotes execute.** The PR body and commit messages here will quote command
  names and file paths; pass prose via a quoted heredoc or `-F <file>`, never an interpolating `-m`
  string, then read back what was stored with `git log -1 --format=%B`.
</verification>
