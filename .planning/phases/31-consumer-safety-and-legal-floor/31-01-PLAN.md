elsewhere in the phase means nothing.

the `img` element and assert it is in the document before scanning. A scan over an unmounted tree
returns zero violations and looks identical to a pass.

## Instrument notes

- **`grep -c` exits 1 on a zero count**, i.e. on the DESIRED state of an absence check, and
  `cmd | grep -q X` under `pipefail` INVERTS on match. Always
  `out=$(grep -cF X f || true); grep -qx 0 <<< "$out"`.
- Capture `rc` on the same statement as its command; `$?` read after an intervening command reports
  the wrong command's status. Task 3's verify uses `${PIPESTATUS[0]}` for exactly this reason.
- **Commit before running any break arm.** `git checkout` restores from the INDEX and silently
  discards post-staging edits. Verify the restore by content (`git hash-object`), never by
  `git diff --stat`, which is empty both when a file is restored and when it was never written.
- `docs/metrics.json` is a GENERATED artefact and is deliberately absent from every plan's
  `files_modified`. Regenerate with `scripts/docs-freshness.sh --write`, never by arithmetic.
</verification>
