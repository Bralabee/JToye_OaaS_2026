SHELL IDIOM — REQUIRED FORM. `cmd | grep -q X` under `set -o pipefail` INVERTS on match (grep exits
at the first hit, the writer takes SIGPIPE, pipefail promotes it to 141). And `grep -c` exits **1**
on a zero count — i.e. on the DESIRED state for an absence check. Measured during planning:

  grep -c ABSENT_TOKEN f   -> stdout "0", rc=1      <- rc is 1 when the check should PASS

So never write `grep -c X f | grep -qx 0`. This repo's hook BLOCKS it. Always:
  out=$(grep -c X f || true); grep -qx 0 <<< "$out"
Verified both directions during planning: rc=0 on absent, rc=1 on present.

## Instrument notes

- **Never `grep -c X f | grep -qx 0`.** `grep -c` exits 1 on a zero count, i.e. on the DESIRED state
  for an absence check, and under `pipefail` the pipeline reports failure when the check should pass.
  This repo's hook blocks the shape. Use `out=$(grep -c X f || true); grep -qx 0 <<< "$out"`.
- `grep` here is **ugrep**: `{`/`}` are metacharacters and `\|` is not portable alternation. Use
  `grep -F` for literals and `grep -E` for alternation.
- Capture `rc` on the same statement as the command; `$?` after an intervening `echo` reports the
  echo's status.
- This plan is `autonomous: false` — Tasks 2 and 4 both block on the owner.
</verification>
