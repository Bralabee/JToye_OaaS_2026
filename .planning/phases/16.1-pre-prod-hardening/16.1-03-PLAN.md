From `core-java/src/main/java/uk/jtoye/core/storefront/PublicStorefrontController.java:91-104` (THE BUG — current state):
```java
@GetMapping("/orders")
public ResponseEntity<List<PublicOrderStatus>> getCustomerOrders(
        @RequestParam String email,
        @RequestParam(name = "verify", required = false) String verifyOrderNumber) {
    if (verifyOrderNumber != null && !verifyOrderNumber.isBlank()) {
        storefrontService.trackOrder(verifyOrderNumber, email);   // ← only runs when verify present
    }
    return ResponseEntity.ok(storefrontService.getCustomerOrders(email));   // ← always runs
}
```

`PublicStorefrontService.trackOrder(orderNumber, email)` already throws `ResourceNotFoundException` on mismatch (existing behaviour, mapped to 404 by `GlobalExceptionHandler`). The fix re-uses that.

`PublicStorefrontService.getCustomerOrders(email)` returns `List<PublicOrderStatus>` (existing).

Spring 6 default: a missing `@RequestParam` (no `required = false`) yields `MissingServletRequestParameterException` → mapped to 400 by Spring's default handler. We exploit that — no custom exception needed.

For blank-but-present `verify` (e.g. `?email=x&verify=`), Spring still binds an empty string. We handle that with an explicit `if (verifyOrderNumber.isBlank()) throw new ResponseStatusException(...)` to keep the 400 surface uniform.

    @GetMapping("/orders")
    @Operation(summary = "Customer order history",
            description = "List all orders for a customer by email address. The 'verify' parameter (a recent order number for this customer) is mandatory — without it the request is rejected to prevent email-based enumeration.")
    public ResponseEntity<List<PublicOrderStatus>> getCustomerOrders(
            @RequestParam String email,
            @RequestParam(name = "verify") String verifyOrderNumber) {
        // AUDIT-W0-02: 'verify' is mandatory. Spring's missing-required-param exception
        // already returns 400 for the absent case; we add an explicit guard for the
        // present-but-blank case so both surfaces look the same to the client.
        if (verifyOrderNumber == null || verifyOrderNumber.isBlank()) {
            throw new ResponseStatusException(
                    HttpStatus.BAD_REQUEST,
                    "'verify' (a recent order number) is required");
        }
        // Throws ResourceNotFoundException → 404 if the (verify, email) pair does not
        // resolve to a real order — that is the proof-of-ownership gate.
        storefrontService.trackOrder(verifyOrderNumber, email);
        return ResponseEntity.ok(storefrontService.getCustomerOrders(email));
    }
