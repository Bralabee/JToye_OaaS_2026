   ```java

   public void configureMessageBroker(MessageBrokerRegistry config) {
       if ("relay".equals(brokerMode)) {
           config.enableStompBrokerRelay("/topic", "/queue")
                 .setRelayHost(relayHost)
                 .setRelayPort(relayPort)
                 .setClientLogin(clientLogin)
                 .setClientPasscode(clientPasscode)
                 .setSystemLogin(systemLogin)
                 .setSystemPasscode(systemPasscode);

           config.enableSimpleBroker("/topic");
       }
       config.setApplicationDestinationPrefixes("/app");
   }
   ```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Information Disclosure | STOMP relay credentials in plaintext env vars | accept | Standard pattern for this project (same as RABBITMQ_USER/PASSWORD); k8s Secrets handle prod. Sealed-secrets deferred to PLAT-02 (milestone 4+). |
| T-11-02 | Elevation of Privilege | Cross-tenant message leakage via RabbitMQ relay | mitigate | Existing TenantChannelInterceptor validates SUBSCRIBE destination against session tenant_id -- unchanged by this plan. No new subscription paths added. |
| T-11-03 | Information Disclosure | RabbitMQ STOMP port 61613 exposed to Docker host | mitigate | Port binding only in docker-compose (dev). k8s does not expose 61613 via ingress -- internal ClusterIP only. |
| T-11-04 | Spoofing | STOMP relay using guest/guest default credentials | mitigate | application.yml defaults to ${RABBITMQ_USER:guest} and ${RABBITMQ_PASSWORD:guest}; docker-compose overrides with real credentials from .env. k8s uses Secret-injected values. guest/guest only applies if no env override (localhost dev only, which is acceptable per RabbitMQ's localhost restriction). |
</threat_model>
