Append a new alert group `messaging_alerts` at the END of `infra/monitoring/prometheus/alerts.yml`, after the closing of the `business_alerts` group. Follow the exact same YAML structure as the existing groups (name, interval, rules with alert/expr/for/labels/annotations).

Add this block:

```yaml
  - name: messaging_alerts
    interval: 30s
    rules:
      # STOMP broker relay lag -- undelivered messages in subscription queues
      # Queue name regex is runtime-adjustable: after first relay-mode startup,
      # verify actual queue names at http://localhost:15672/#/queues and adjust if needed.
      # Default RabbitMQ 3.12 uses stomp-subscription-<random>; some configs use amq.gen-<random>.
      - alert: StompBrokerLag
        expr: |
          sum(rabbitmq_queue_messages_ready{queue=~"stomp-subscription.*|amq\.gen-.*"}) > 0
        for: 5s
        labels:
          severity: warning
          component: messaging
          service: rabbitmq
        annotations:
          summary: "STOMP broker message lag detected"
          description: "Undelivered messages in STOMP subscription queues: {{ $value }}. Kitchen display clients may experience delayed order updates."
```

This alert:
- Uses `rabbitmq_queue_messages_ready` metric filtered by a broadened queue name regex (`stomp-subscription.*|amq\.gen-.*`) that covers both the default RabbitMQ STOMP naming pattern and the alternative `amq.gen-` pattern. This regex is a runtime-adjustable parameter (per RESEARCH.md Open Question 1 resolution).
- Fires after 5 seconds of undelivered messages (per STMP-05 requirement: "lag > 5 seconds")
- Labels with `severity: warning`, `component: messaging`, `service: rabbitmq` to match the project's label convention
- Routes through the existing Alertmanager receiver (Phase 9 SECR-04 routes all alerts to the email-default receiver)

**Runtime discovery step (MANDATORY):** After Plan 11-01 is complete and the stack has been started in relay mode at least once (during the 11-02 smoke test), the executor MUST:
1. Open `http://localhost:15672/#/queues` in the RabbitMQ Management UI
2. Identify the actual STOMP subscription queue names (look for auto-delete queues bound to `amq.topic`)
3. If the queue names do NOT match `stomp-subscription-*` or `amq.gen-*`, update the `queue=~"..."` regex in the alert rule to match the actual pattern
4. Document the verified queue naming pattern in the SUMMARY

Or if promtool is available locally: `promtool check rules infra/monitoring/prometheus/alerts.yml`
