WHAT THE SPEC ASSERTS (and why it is stricter than the plan's filter)
------------------------------------------------------------------------------
1. Discovery reads served HTML only: the /shop listing in order, then the first
   shop page whose SERVER-RENDERED HTML has an <img> whose src starts with
   STORAGE + "/". So discovery does not depend on the store being up.
   STORAGE = PLAYWRIGHT_STORAGE_PUBLIC_URL, default
   http://localhost:10000/devstoreaccount1/jtoye-images. That is the same value
   as docker-compose.full-stack.yml:361 STORAGE_PUBLIC_URL.
2. Browser: goto (domcontentloaded, not networkidle), walk to the bottom in steps
   and back, then poll every storage-origin <img>'s `complete` against a 20 s
   deadline.
3. VOID: zero storage-origin <img> in the DOM fails, naming the filter.
4. Every storage-origin <img> must be complete with naturalWidth > 0.
5. ADDED BEYOND THE PLAN: every storage src the server rendered must be a loaded
   <img> in the browser. SafeImage (components/ui/safe-image.tsx) swaps a failed
   <img> for a fallback <div> via onError, so the failed image LEAVES the DOM and
   check 4 cannot see it. Arm B below measures that hole.

Pre-measurement (throwaway probe /tmp/claude-3613/probe.cjs, not committed):
  /shop renders only 3 <img>, all /brand/logo-*.png (frontend-served).
  /shop/mama-ades-kitchen: 1 /brand logo + 9 storage-origin <img>, all nw > 0.
  The storage-origin <img> srcs in the served HTML equal the browser set on all
  three shops (7 unique each: brixton-village-grill, mama-ades-kitchen,
  peckham-jollof-co).
