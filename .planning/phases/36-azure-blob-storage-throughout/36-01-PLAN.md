<objective>
Swap core-java's object storage from the S3 SDK to the Azure Blob SDK behind the UNCHANGED
StorageService surface, and prove the new spine end to end against a real Azurite before any
other plan builds on it.

Purpose: this is the phase's architectural risk. Everything else in Phase 36 (compose, k8s,
backup, reseed, frontend) is a consumer of the path proven here: SDK -> emulator ->
split-horizon public URL -> anonymous browser-style GET. If that path has a dead end, it must
show up after one commit, not after eighteen plans.

Output: the Blob adapter and config switch, StorageService routed by key to a public and a
private container, the four compile-bound unit tests ported, a shared Azurite fixture, and the
tracer integration test with the #626 rule proven in both directions.

Spec-less probe fallback: SKIPPED, visibly. The phase had no requirement IDs when the probe ran
(ROADMAP said "TBD"); BLOB-01..BLOB-10 were derived at plan time from 36-RESEARCH.md and every
must_have here is derived from the ROADMAP goal, CONTEXT D-01..D-10 and the research.

Scope note on the tracer: the phase touches config consumers (compose, k8s, backup, CSP) that
cannot share one thin path with the storage seam. The tracer covers the seam, the only layer
where an architectural dead end is plausible; the consumers are wired by 36-02..36-10 against
this proven path.
</objective>

<assumption_delta_decision>
The assumption-delta detector fired (signal: "additional", from the column name
additional_image_urls). The genuine pluralisations this phase introduces are a second container
(public + private, where there was one bucket), a second auth path (emulator connection string +
Workload Identity) and a second storage account (media + backup).

- Primary noun: the object KEY stays the primary identity. The container is DERIVED from the key
  (second segment 'quarantine' -> private container), never persisted and never chosen by a
  caller. Decision: no-change to the identity model. Rationale: persisting a container would
  need a migration and would let application code choose an access level per object, which is
  exactly what quarantine privacy must not allow. What would force a promote: a key that can
  legitimately live in two containers.
- Auth: promote. Workload Identity is the primary real-Azure path; the connection-string path is
  demoted to "Azurite emulator only" (36-06 refuses any non-emulator connection string), so there
  is no second way to reach a real account.
- Invariant test (accepted): AzuriteStorageIntegrationTest round-trips a key through StorageService
  for EACH container, so a future change that reintroduces a single-bucket assumption goes red.
</assumption_delta_decision>
