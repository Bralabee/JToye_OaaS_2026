<objective>
Move the Postgres logical dump from the AWS CLI to blobctl and Azure Blob, and make the restore
drill an executable, nightly-wired, two-arm gate.

Purpose: BLOB-06 and D-01/D-10. Today's pipeline passes on a schema-only, zero-row dump (the size
floor and the TOC listing both pass); only restore-and-count falsifies it, and until now that
recipe existed as prose. The restore path also never had standing coverage: the pg-backup image
is not built anywhere in CI.

Output: the rebuilt image (built locally as :15-blob), the rewritten script, the drill gate wired
into the nightly, the rewritten runbook with the old evidence archived, and horizon sites for the
new Go build stage. The CronJob manifest, the parity-tracked tag references and the goldens move
together in 36-09 (D-10), so this plan does NOT touch k8s/.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| database -> backup job | the dump carries every tenant's PII |
| backup job -> Blob | the dump leaves the database host |
| drill script -> docker | credentials cross into containers |

| T-36-29 | Tampering | existing dumps | high | mitigate | No prune, no delete in the script; blobctl never overwrites; WORM + soft delete in staging per the provisioning runbook (D-01) |

| T-36-SC | Tampering | golang builder image | medium | mitigate | Builder stage only (not shipped), pinned golang:1.27-alpine tracked by the golang horizons row with this new site |
