<objective>
Rewrite the shared dev database so it points at the new store: reseed, don't migrate (D-04), with
the tenant loop and non-zero proof D-05 requires.

Purpose: BLOB-05's data half. A URL rewrite alone is insufficient (36-RESEARCH.md): 
ProductService.resolveAssetFirst serves a product's primary ACTIVE media_asset ahead of
products.image_url, and every pre-existing asset key now points at bytes that no longer exist,
so those assets must be marked FAILED or they shadow even a correctly rewritten URL.

Ordering constraint: DemoDataSeeder rewrites demo products' image URLs on its first boot against
Azurite. This plan therefore runs with ONLY postgres (and azurite) up, before 36-12 boots core-java.

Output: scripts/dev-media-reseed.sh, a recorded dry run, an owner approval, and the recorded apply.
</objective>

<displaced_goods>
Incremental Betterment -- user-visible goods this plan touches:
- Demo storefront imagery -- PRESERVED: seed URLs are rewritten to Azurite and DemoDataSeeder re-uploads the
  same deterministic seed objects on the next boot; 36-12's URL gate and 36-13's browser spec prove it.
- Hand-uploaded dev images (non-seed) -- LOST by owner decision D-04 (their bytes are in an on-disk format that
  is not migrated); the rows stop pointing at dead URLs instead of rendering broken images.
- Previously ACTIVE vendor media -- shown honestly as FAILED with a reason and the existing Re-upload action
  (IMG-04), rather than silently shadowing product images with 404s.
</displaced_goods>
