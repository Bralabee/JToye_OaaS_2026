<objective>
Move the request/response-side Jackson users to Jackson 3 and close the production defect the spike
found: under Boot 4, tenant offboarding PUTs a Jackson-2 ObjectNode serialized as a Jackson-3 bean,
so Keycloak receives garbage and the user stays ENABLED (a stolen token keeps minting).

Purpose: D-01 requires the Keycloak body asserted by content; only KeycloakAdminClientTest caught
the defect, and only because the spike looked. The other four classes are small, independent
Jackson users whose behaviour (problem bodies, model-output tolerance, the vendor-facing envelope)
must not drift.

Output: KeycloakAdminClient/KeycloakDeprovisionService, RateLimitInterceptor, ImageAnalysisService,
DemoImageManifest and WebhookFanoutListener on tools.jackson, with by-content and tolerance tests.
The live offboard against the compose Keycloak is 38-17.
</objective>
