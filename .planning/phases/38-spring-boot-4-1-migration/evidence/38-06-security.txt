=== Owner decision (checkpoint:decision, blocking-human; AskUserQuestion, 2026-10-05)
Options put: 404-for-all | anon-401-parity (recommended) | exact-parity.
Owner's answer, exact words: "anon-401-parity (Recommended)"
Implemented as:
  - no credentials on the request  -> 401, WWW-Authenticate exactly "Bearer", the 401 problem document,
    produced by ProblemDetailAuthenticationEntryPoint.commence (the chain's own entry point), so the
    same status, headers and body bytes as any other protected route;
  - credentials present            -> 404 errors/not-found, GlobalExceptionHandler's NoResourceFoundException
    document, instance = request path;
  - D-05's core unchanged: no corrected metadata served; the false claim unreachable for every caller;
    the filter is not a bean; it runs ahead of the framework's metadata filter; with the registration
    removed the path answers 200 + the false claim (arm R).
"Credentials", as built (executor's operationalisation, recorded for review): a bearer token as the
resource server's DefaultBearerTokenResolver resolves it (the chain configures no other resolver: before
this task, rg -uu for BearerTokenResolver in core-java/src/main -> rc=1; at HEAD, rg -uu
'BearerTokenResolver|bearerTokenResolver' core-java/src/main finds only this filter's own five lines, so no
resolver bean exists for the configurer to pick up), OR a SecurityContext that is already
authenticated and not anonymous (this is what spring-security-test's jwt() produces, the 38-02 harness).
Consequences, each pinned by a test:
  - Authorization: Basic ...   -> anonymous to this API -> 401 Bearer (as on every other route)
  - malformed bearer ("Bearer not a token") -> the resolver's own error through the same entry point:
    in Security 7.1.1 that is invalid_token "Bearer token is malformed", 401 (javap: DefaultBearerTokenResolver
    -> BearerTokenErrors.invalidToken). Integration-compared with GET /api/v1/products: same status, every
    header, body bytes.
  - well-formed bearer, valid or not -> 404 (see RESIDUAL).

=== RESIDUAL (recorded; contract note for ADR-0006 in 38-16 and the phase PR body in 38-18)
The suppression filter answers BEFORE authentication. A well-formed but invalid or expired bearer on
/.well-known/oauth-protected-resource[/**] therefore gets 404 errors/not-found here, where Boot 3.5.16
gave 401 with WWW-Authenticate: Bearer error="invalid_token", error_description=..., error_uri=...
Pinned (so any change to it is deliberate) by
  UnauthenticatedProblemDetailIntegrationTest.wellKnownProtectedResource_invalidBearer_returns404_recordedResidual
  (GET with Authorization: Bearer not-a-jwt -> 404, no WWW-Authenticate, type errors/not-found).
Other observable differences from Boot 3.5.16 on this path, none an assertion change:
  - body key order is Jackson 3's alphabetical order (owner decision "jackson3-defaults", 38-05);
  - the anonymous 401 no longer saves the request (3.5's ExceptionTranslationFilter put
    SPRING_SECURITY_SAVED_REQUEST in the session, 38-02 MockMvc print), so this path creates no session.
