<objective>
Keep idempotency continuous across the deploy: a client that reserved a key against a Boot-3.5 pod
and retries against a Boot-4 pod must get its original response, not a 422.

Purpose: IdempotencyService stores sha256(objectMapper.writeValueAsString(request)). Jackson 3
changes default bytes (alphabetical property order, among others), so a naive migration makes every
pre-deploy reservation look like "same key, different body" until it expires, a client-visible
regression on order and customer creation, MCP write tools included. D-01 did not list this hazard;
research found it. The fix decouples the persisted format from the app-wide mapper permanently.

Output: IdempotencyJson, IdempotencyService and DsarIntakeService on Jackson 3, golden-hash and
NOSUPERUSER replay proofs, DSAR and jsonb continuity.
</objective>
