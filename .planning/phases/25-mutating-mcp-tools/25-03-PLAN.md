<objective>
Extend the Phase-20 read-only MCP server with the two write tools. Add a `corePost` sibling to `coreGet` (same fixed `CORE_BASE_URL` / SSRF guard / verbatim Bearer / 10s timeout / never-logs-body), then `create_order` + `create_customer` (D-07) as thin forwarders that mirror `read-orders.ts` verbatim — each exposing `idempotencyKey` as a REQUIRED tool input (Zod `.min(1).max(64)`, D-05), splitting it out of the JSON body and forwarding it as the `Idempotency-Key` header so the tool has NO non-idempotent path (a replay returns the original, never a duplicate). Register both in `buildServer`. Cover them with vitest mirroring `read-orders.test.ts` (header/body split, PII-never-logged, `toToolError` delegation on 403/404/409/422) plus a `corePost` unit test. Finally, prove AC-2 at the HTTP-adjacent boundary: a tenant-A write token targeting a tenant-B `shopId` resolves 404/empty under FORCE RLS — proven under the NOSUPERUSER `rls_test_role` downgrade (a superuser Testcontainers role bypasses FORCE RLS and would falsely pass).

Purpose: Discharges AI-02's core deliverable — the write tools + idempotent-replay proof + the RLS-scoped cross-tenant proof under the MCP credential. Depends on 25-01 so the RLS proof exercises a token that genuinely passes the `orders:write` gate before reaching RLS.
Output: `corePost`, two write tools, their registration, three vitest files, and the cross-tenant RLS integration test.
