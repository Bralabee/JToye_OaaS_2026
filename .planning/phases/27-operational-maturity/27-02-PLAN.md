**TEN base directories: NINE orphaned + ONE live.** The draft said "nine node directories" *including*
the live one, which implies eight orphans and is wrong by one; D-11 and the compose comment in Task 4
both say **nine orphaned**, which is right. Every figure in this plan now reads *ten total, nine
orphaned, one live*, and the compose comment quotes the same numbers so the shipped artifact and the
plan cannot drift apart.

RabbitMQ keys its data directory by node name = `rabbit@$(hostname)`, and compose sets **no
`hostname:`**, so Docker uses the container ID. **Every previous `--force-recreate` orphaned a node
directory and booted an empty broker**, and nobody noticed because nothing ever asserted message
survival. Consequence for this plan: *restoring the tarball is not sufficient*. A restore that
lands `rabbit@53955960a605/` into a container whose hostname is something else boots **clean and
healthy on the right version with zero messages** — green, and wrong. D-11 and AC-13 handle this.

**And the corollary the draft got backwards (D-L).** The same mechanism means the `hostname:` pin
**cannot be applied before the snapshot is restored**. The tarball is taken from the *unpinned*
runtime, so it contains `mnesia/rabbit@53955960a605/`. Pin the hostname first and the very next
recreate looks for `rabbit@jtoye-rabbitmq`, finds nothing, and boots empty — which is how the draft
managed to write a rollback proof whose PASS arm and BREAK arm returned the *same* answer (empty) and
whose "depth is still 9" restart check would have aborted the phase on a correct tree. **Order
matters and it is the whole fix**: snapshot unpinned → destroy → fresh 4.3.4 install → *then* pin.

- **PIT-13 the node-name trap TURNED ON ITSELF — the D-L inversion.** PIT-12's *fix* (pin
  `hostname:`) becomes PIT-12's *cause* if it is applied before the snapshot is restored. A tarball

  hostname is a property of the TARBALL, not of the compose file**, so it is recorded in a sidecar
  file beside the tarball at snapshot time and read back at restore time — never typed from memory
  and never assumed to be the current compose value. Renaming the directory in-place is *not* an

  node still refuses to adopt. The pin therefore goes on **after** the fresh install (Task 4), and
  every snapshot taken from that point forward restores under `jtoye-rabbitmq` — which is the
  permanent good the pin buys.
- **PIT-14 `grep` here is ugrep, and it does not emit the `./` prefix.** `grep` is a **bash function**

  `git ls-files --cached --others --exclude-standard`, which emits repo-relative paths with no `./`
  under any implementation, and match exclusions as path **prefixes** in shell (`case`), not as
  anchored regexes. Record `grep --version` in the SUMMARY. Cousin of PIT-5 and PIT-11: the tool is
  not what the command assumes it is.
