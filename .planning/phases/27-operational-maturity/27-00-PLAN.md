Phase 27 was reframed from "Messaging Layer Hardening" to **"Operational Maturity — messaging as the
first instance"**. The four sibling plans each fix a messaging-specific instance of a gap that is not
messaging-specific. This plan is the layer that turns each of them into an instance of a policy
applied once, so the same class of defect is caught everywhere instead of being fixed four more
times.

It delivers three mechanisms, each grounded in a defect verified live on the unmodified tree:

- **GAP 1 — a detection contract for terminal failure states.** A register of every state where work
  is permanently stopped and no human is told, plus gates that fail when a new one appears without a
  detection path, when an alert selector matches nothing, when an alert matches the *wrong subject*,
  when a scrape target is down, when an exporter is up but blind, and when a notification never
  leaves the box.
- **GAP 2 — a dependency lifecycle mechanism.** A support-horizon manifest per pinned image and
  toolchain, checked against a machine-readable EOL source at gate time via a **recorded, proven
  slug**, so the dates cannot rot and the gate cannot be permanently VOID.
- **GAP 3 — the minimum honest load baseline.** Two arms (HTTP and AMQP consumer), status-code
  asserted, committed dated, against a declared budget — enough to unblock 27-04 and no more.
  This is the first third of issue **#115 [P3-13]**; the other two thirds are explicitly declined
  here and re-filed by **27-06** (D-J/D-14).

### F-3b — `pg_up = 0` while `up{job="postgres"} = 1`. NEW (D-G), and the cause in the brief is WRONG.

```
pg_up{job="postgres", instance="jtoye-postgres-exporter:9187"}  = 0
up{job="postgres"}                                              = 1
```

`DatabaseDown` (`alerts.yml:69-70`) alerts on `up{job="postgres"} == 0`, which is **1**, so it
reports healthy while no PostgreSQL metric is being collected at all. `pg_up` — the correct signal,
present and 0 right now — is referenced by **no rule**. `TooManyDatabaseConnections`
(`pg_stat_database_numbackends > 100`) matches **zero series** for the same reason.

**Correction to the brief:** the brief attributes this to DNS. Measured cause is **not** DNS. The
exporter resolves and connects, then fails the version query:

```
caller=server.go:74     level=info  msg="Established new database connection" fingerprint=postgres:5432
caller=collector.go:176 level=error msg="Error opening connection to database"
                        err="error querying postgresql version: pq: SSL is not enabled on the server"
caller=postgres_exporter.go:682 level=error
   err="...(postgresql://jtoye:PASSWORD_REMOVED@postgres:5432/jtoye?sslmode=require): pq: SSL is not enabled on the server"
```

The DSN is built at `infra/monitoring/docker-compose.monitoring.yml:118` with
`sslmode=${POSTGRES_EXPORTER_SSLMODE:-require}`; `.env` does not set it, so it defaults to `require`
against a compose Postgres with SSL off. **Credentials are fine** — control:
`PGPASSWORD=placeholder psql -h 127.0.0.1 -U jtoye -d jtoye -c "select 1"` inside `jtoye-postgres`
returns `1`. `.env.example:14` ships `POSTGRES_EXPORTER_SSLMODE=require`, which is the *committed*
source of the local breakage.

So this is the **same shape as F-3**: one config serving two runtimes with different topologies. It
gets the same treatment — a one-line local fix plus a durable gate. And it generalises the gate's
core lesson: **a target being UP is not evidence the thing behind it is healthy.**

### House style for all three gates (non-negotiable, copied from the existing set)

### Known vacuous shapes this plan must avoid (each has bitten this repo)

1. **Already-0 grep.** Never assert `count == 0` without first proving the pattern can match ≥1 on a
   deliberately broken input. **And note `grep -c` exits 1 when it prints 0** — under `set -e` that
   kills the harness. Every expected-0 count in this plan is written
   `n=$(grep -c PAT file || true); [ "$n" -eq 0 ]`, or as a `| wc -l`.
2. **`cmd | grep -q X` under `pipefail` inverts** — SIGPIPE→141 on match. Use here-strings:
   `grep -q X <<<"$out"`.
3. **`promtool check rules` passing a rule whose metric does not exist.** Syntax validity is not
   liveness — that is F-1. (And promtool is not installed here; the image ENTRYPOINT is
   `/bin/prometheus`, so `docker run … promtool` exits 1. Use `docker exec jtoye-prometheus promtool`
   or `--entrypoint=promtool` **if** it is ever needed. It is not needed by this plan.)
4. **A selector matching ≥ 1 series is NOT proof it matches the right series.** F-3c. See L-2b.
5. **Gradle `UP-TO-DATE` executing nothing.** Any Gradle verification here runs `cleanTest` first.
6. **Reading stale `core-java/build/`.** The live output dir is `build-local`.
7. **A gate that fails OPEN.** Missing tooling / empty output must exit 2.
8. **Sorted-output blindness.** `kubectl kustomize` sorts map keys; do not assert on ordering.
9. **An expected-0 `git diff` grep with no control.** If the pattern never appears in *any* diff of
   that file, the 0 was already true. Every "nothing was removed" claim in this plan is written
   **set-wise** (`comm -23 <old-set> <new-set>` must be empty) with a control that deletes a real

### GAP 2 — where the EOL dates come from, and how they stay honest

**Source:** `https://endoflife.date/api/<eol_slug>.json` — one object per cycle with an `eol` field
that is either an ISO date or `false`. Slug behaviour measured in F-6; **`eol_slug` is a mandatory
recorded field, never derived from the image name.**

**The four honesty mechanisms** — a hand-maintained date nobody refreshes is the same failure in a
new costume, so the manifest's date is never the authority:

1. **Re-fetch and compare.** The gate fetches the live `eol` for the recorded `eol_slug` +
   `eol_cycle` and **fails if it disagrees with the cached `eol_date`**. The cached copy exists only
   so the manifest is readable and diffable offline; it can never drift silently.
2. **Offline is VOID.** Fetch failure, non-200 after redirects, unknown slug, or cycle-not-found →
   exit **2**. Never a pass. A `--offline` flag is deliberately **not** provided.
3. **Redirects are followed, but only within `endoflife.date`.** `curl -L` with
   `--max-redirs 3`, then assert the effective URL's host (`curl -w '%{url_effective}'`) is exactly
   `endoflife.date`. Cross-host → **exit 2**. The body is untrusted data feeding a gate that decides
   whether CI passes: parse strictly with `jq`, never `eval` a field.
4. **`--refresh` writes the cache**, mirroring `scripts/docs-freshness.sh --write`, so the correction
   path is one command and the diff is reviewable.

**Vendor-vs-catalogue disagreement is classified, not smoothed over.** Two distinct shapes:

- **Date-vs-date, both past** (rabbitmq 3.12: catalogue `2024-02-21`, vendor `2024-02-29`) → **NOTE**.
  Failing on an 8-day cataloguing difference trains the operator to ignore the gate.
- **Catalogue says `false`, vendor names a date** (rabbitmq 4.3: catalogue `false`, vendor
  **2026-11-30**) → **FAIL**. A `false` is a *missing horizon*, and here it lands on the exact pin
  27-02 is adopting. `vendor_eol` wins; the row must carry it, and the gate evaluates the horizon
  against `vendor_eol` when present.

**Products with no EOL feed** (`minio`, `minio/mc`, `ollama` — all 404, measured) get
`eol_slug: null` plus a mandatory `manual_review: {last_checked, expires, url}`, and an expired
`manual_review` is a FAIL. **Unpinned `:latest` tags are a distinct state**: `pin: "latest"` requires
`unpinned: true` with a reasoned dated exemption, because a floating tag is not a pin and its horizon
is unknowable by construction.
