<objective>
Make a dead message impossible to lose silently.

Today four dead-letter queues fill with nobody watching, the single messaging alert in the repo is
provably incapable of firing, `DatabaseDown` is structurally incapable of detecting a database
outage, and the two JVM alerts measure Keycloak's heap while telling you it is core-java's. Nine
tenant-bearing messages sit dead on the dev broker — the oldest since 2026-07-15, the **newest since
2026-07-26T15:33:51Z, hours before this plan was written** — and no signal exists that would have
said so.

This work-item closes the **detection** and **triage** halves — alerts on proven series, a runbook,
a non-destructive inspection CLI — deliberately **defers redrive**, deliberately **does not purge**
the real dead letters (that is 27-02 Task 2's human checkpoint, D-C), deliberately **does not
diagnose them** (that is 27-05, D-13), and — the load-bearing part — adds an executable gate that
fails both when a live rule references a series that does not exist *and* when a dormant rule's
series starts existing. The "syntactically perfect rule that can never fire" class cannot come back,
and neither can its twin, "the disabled rule nobody re-enabled".

**This plan is not shippable without 27-05, and that is a design constraint, not a note.** Its
headline rule `DeadLetterQueueNonEmpty` fires at depth ≥ 1 on a queue that has **no consumer**; the
producing fault is live (5 arrivals in ~25 h) and 27-02's purge would reset the depth only for it to
refill within hours. A rule that pages permanently for a bug the phase declined to fix is alert
fatigue manufactured on purpose. This plan applies that exact reasoning to itself for the exporter
DSN in D-11 ("otherwise the corrected `DatabaseDown` pages permanently from the moment it merges")
and must apply it here too. **27-05 (wave 1) removes the producer; the post-27-05 steady-state
baseline for `webhook.deliveries.dlq` is 0, not 9**, so the alert is a real signal rather than a
standing red. See D-13.

Scope boundary: no consumer, no HTTP endpoint, no auth gate. One Java file (a counter plus a
signature fix), three monitoring config files, one runbook, three bash gates, three unit-test files.
**No `.env.example` edit** (D-P — the key already exists there; 27-00 owns the modification).

**What this plan does NOT own**: the `core-java:9091 → 9090` scrape fix (27-00 Task 1, D-B); any
`.github/workflows/ci-cd.yaml` edit — **`check-alert-rules.sh` is wired into CI by 27-06** (D-K/D-J:

**I-7 — regex escaping. [BRIEF CORRECTION — the brief's `m8` claim is FACTUALLY WRONG and the
draft's T2.10 was written to it. Measured on the live Prometheus, 2026-07-26.]**

The brief asserted that `queue=~".*\\.dlq"` inside a YAML `expr: |` block "survives as two
characters, RE2 reads literal-backslash + any-char, so it matches nothing". **The opposite is true.**
PromQL unescapes `\\` → `\` *before* RE2 sees it, so `\\.` means a literal dot — exactly like `[.]`:

| probe | result |
|---|---|
| `{rabbitmq_version=~"3\\.12.*"}` | **1 series** |
| `{rabbitmq_version=~"3[.]12.*"}` | **1 series** — identical |
| `{rabbitmq_version=~"9[.]99"}` (control) | **empty** — so the probe *can* return empty |
| `{rabbitmq_version=~"3\.12.*"}` (single backslash) | **hard parse error**: `bad_data: unknown escape sequence U+002E '.'` |

Two consequences, both binding:
1. **`\\` is NOT forbidden and is NOT a correctness defect.** This plan still writes every regex with
   the `[.]` character class — but **as house style** (it is byte-identical under block, plain and
   double-quoted scalars, so it cannot be broken by a later reformat), **not as a fix**. Anyone
   "correcting" a `\\.` regex elsewhere in this repo on the strength of the old claim is changing
   working code for no reason.
2. **The real trap is the single backslash**, and it fails *loudly*, not silently: `\.` is rejected
   at parse time with `bad_data`. That is the control T2.10 now uses. **The danger the draft created
   was worse than the bug it imagined**: T2.10 as drafted demanded the `\\` form return **0 series**,
   which fails on a correct tree, and the obvious way for an executor to "fix" that failure is to
   rewrite correct regexes.

The genuine defect this plan exists to fix (F-3) was never an escaping bug at all — it was a
`queue=~` selector against a series family that **carries no `queue` label**. Escaping is a red
herring; label existence is the thing, and D-09's gate checks label existence.

**D-06 — Redrive is DEFERRED. This is the recommendation, not a scope compromise.**
Cheapest sufficient scope for "messages die silently and nobody is told" is *tell somebody* + *give

- **An automatic redrive consumer re-poisons by construction.** The message is in the DLQ *because*
  a deterministic handler failed it 3×; republishing to `x-death[0].exchange` re-enters the same
  handler, fails again, and returns — a hot loop bounded only by `x-death.count`, which nothing
  reads. Auto-redrive needs a poison-detector, a bigger design than the alerting.
- **A manual admin endpoint collides with an architectural fact: this platform has no cross-tenant
  operator identity.** All admin is tenant-scoped (`@PreAuthorize("hasRole('admin')")` in
  `TenantAdminController`, `GdprController`, `RefundController` all resolve *within* a tenant). A DLQ
  is inherently cross-tenant — one queue, every tenant's payloads — and AMQP basic-get is FIFO, so
  you **cannot** selectively fetch "only my tenant's messages". A tenant-scoped inspection endpoint
  would mean pulling other tenants' payloads into the JVM and filtering: a cross-tenant read path
  with no identity authorised to use it.
- **The recorded `@PreAuthorize` trap makes it disproportionately expensive.** Adding a scope gate
  has twice silently reddened existing `integrationTest` classes a per-plan executor never runs
  (Phase 25: 10 failures across 4 classes). A new gated endpoint costs a full
  `:core-java:test :core-java:integrationTest` (~40 min) plus a blast-radius grep — for a capability
  nobody has yet needed twice.

**Deferred with a named trigger, not "later":** build redrive when either (a) a
`DeadLetterQueueNonEmpty` alert has fired 3+ times in one quarter, or (b) the manual
