<objective>
Establish the WebP transcode toolchain and the pure-transform normalizer — the one genuinely non-precedented piece of Phase 24 — and de-risk it FIRST with an in-container musl smoke test before any pipeline is wired to it.

Purpose: Every WebP encoder on the JVM is native; the runtime image is `eclipse-temurin:21-jre-alpine` (musl) where the bundled glibc `cwebp` will not exec (RESEARCH Pitfall 1 / Assumption A1). This is the phase's #1 execution risk. Locking the library choice AFTER a passing container smoke test (fallback: switch base image to glibc `eclipse-temurin:21-jre`) prevents a green-unit-tests / every-asset-FAILED-in-compose disaster.

Output: `MediaProperties` config budget (`jtoye.media.*`), `MediaNormalizer` (magic-byte sniff + decompression-bomb header guard + decode-verify + WebP encode + thumbnail), the Dockerfile/build/multipart wiring, and the two Wave-0 test artifacts (musl smoke + normalizer unit test). Self-contained — no DB dependency; parallel-safe with 24-02.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| raw upload bytes → normalizer | Untrusted quarantine bytes cross into the decode/transform stage; the derivative crossing back out is trusted |
| build/CI → runtime image | Third-party image libraries + apk package enter the deployed artifact |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Denial of Service | `MediaNormalizer` decode | mitigate | ImageReader header-only dimension read + `maxMegapixels` cap before `read()` (RESEARCH Pitfall 2) — no pixel buffer allocated for a bomb |
| T-24-02 | Spoofing/Tampering | `MediaNormalizer` format gate | mitigate | Magic-byte sniff (reuse `detectContentType`) + jpeg/png/webp allowlist + decode-to-verify; never trust `file.getContentType()` |
| T-24-03 | Information Disclosure | derivative output | mitigate | Decode→WebP re-encode drops all EXIF/GPS metadata (cwebp omits metadata by default); Task 3 asserts no EXIF on output |
| T-24-04 | Tampering | malicious polyglot (valid JPEG + embedded script) | mitigate | Re-encode to WebP produces fresh bytes — embedded payloads do not survive transcode |
| T-24-SC | Tampering (supply chain) | Maven scrimage/twelvemonkeys + apk libwebp-tools | accept | RESEARCH §Package Legitimacy Audit verified all coordinates on Maven Central (Apache-2.0/BSD-3/MIT, all `Approved`, none `[ASSUMED]`/`[SUS]`); Maven has no postinstall-script risk; libwebp-tools is the Google/Alpine OS-vendor package. No blocking checkpoint required (ecosystem is Maven, not npm/pip/cargo) |
</threat_model>
