<objective>
Deliver the async worker half of the safe pipeline (IMG-02 worker side + IMG-03 gate strictness): a GUC-pinned `@RabbitListener` that magic-byte-sniffs, header-guards the decompression bomb, decode-verifies, EXIF-strips, normalizes to a WebP derivative (via the 24-01 `MediaNormalizer`), stores ONLY the derivative, deletes the raw quarantine object on success, and drives the asset state machine PENDING → ACTIVE / FAILED (+ the flagged sub-state). Plus the crashed-worker reaper and the BulkImportService unification onto the ONE pipeline.

Purpose: This is where "store only a validated, normalized derivative — never the raw bytes" becomes true, where a FAILED normalization is rejected with a vendor-visible reason (D3 hard veto), and where a below-threshold vision confidence flags-not-blocks (D3 review queue). The CoW safety property (D-04a) is load-bearing: minting the new ACTIVE asset + repoint happens ONLY on worker success, so a failed replacement never clobbers the live image.

Output: `MediaProcessingWorker`, `MediaPendingReaper`, the `BulkImportService` reroute, and the three IMG-02/03 Wave-0 integration tests (worker pipeline + gate strictness + CoW safety) plus the extended `BulkImportServiceTest`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| quarantine raw → worker | Untrusted raw bytes are decoded/transformed off the request thread; only the derivative is trusted |
| worker thread → FORCE-RLS tables | The worker runs off-request, so the tenant GUC must be pinned explicitly or RLS hides the row |
| vision provider (Ollama) → pipeline | An unreliable/absent provider must never block or fail an upload |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-13 | Spoofing / Tampering | content-type spoof (`.jpg` that is a PDF/HTML/SVG) | mitigate | Magic-byte sniff + jpeg/png/webp allowlist + decode-to-verify in the worker (via MediaNormalizer); a mismatch → FAILED, never a served object |
| T-24-14 | Denial of Service | decompression bomb reaching the worker | mitigate | ImageReader header-only megapixel cap (MediaNormalizer, 24-01) runs before decode; bomb → FAILED, no OOM |
| T-24-15 | Information Disclosure | EXIF/GPS PII in the served image | mitigate | Decode→WebP re-encode drops all metadata; worker stores only the re-encoded derivative |
| T-24-16 | Tampering | malicious polyglot | mitigate | Re-encode to WebP produces fresh bytes; embedded payloads do not survive transcode |
| T-24-17 | Information Disclosure / Tampering | cross-tenant asset write from the worker thread | mitigate | `set_config('app.current_tenant_id', …)` pinned before any DB write (RESEARCH Pattern 3); `#workerPinsTenantGuc` proves visibility under NOSUPERUSER |
| T-24-18 | Tampering | raw upload served as the object | mitigate | Stored object is ALWAYS the normalized WebP derivative; raw lives only in quarantine and is deleted on success (SPEC Q2 stage 4) |
</threat_model>
