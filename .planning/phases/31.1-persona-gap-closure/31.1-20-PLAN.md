Make the "confirm your data request" link open a friendly page that works on every runtime (#839, D-04).

Purpose: on compose the emailed link pointed at localhost:8080 (nothing listens there), and where it
did reach the API it showed raw JSON. A non-technical requester could not confirm, so on the canonical
runtime no DSAR could ever be verified.

Output: mailer link format, the confirm page, every runtime's link base corrected (plus the 31.1-16
download base), a config contract test, the route declaration and the compose-stack Playwright spec.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-31.1-71 | Spoofing | a mail scanner auto-confirming an erasure lodged against the victim | high | mitigate | Confirmation requires an explicit press; the token lives in the fragment (never fetched by a GET of the page) |
| T-31.1-72 | Information disclosure | token captured in access logs or history | medium | mitigate | Fragment only, cleared on load, sent in a POST body |
| T-31.1-73 | Spoofing (open redirect / host injection) | link base derived from a request Host header | medium | mitigate | Base remains config-injected; contract test pins each runtime to its own web origin |
| T-31.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installed |
