Evidence that nulls are written today (ALWAYS inclusion), and are therefore what breaks:
- `responses/OrderDto.json` carries `"paymentReference":null` (1 null; ProductDto 6, ShopDto 1).
- `idempotency/storefront.guest-order.request.json` carries `"addressLine2":null`.
- Jackson3WireContractTest is tree-equal on all of these (`build-local/boot4/jackson-wire-diff.tsv`: `responses/OrderDto.json false true -`).

**"Extend Phase 38's goldens, not its Jackson-2 fixtures", made concrete.** The fixtures are fixed, so
an additive field must keep the comparison green in one of two ways. Each owning plan picks one and
records the choice:
- **(a)** annotate the new field `@JsonInclude(JsonInclude.Include.NON_NULL)`. The field is then absent when null, every golden comparison is unchanged, and it appears only when set. The cost is an API-shape choice: absent rather than `null`, so TS types are `field?: T`.
- **(b)** extend the TEST, never the fixture. Add a declared additive-field set to `Jackson3WireContractTest` (for example `ACCEPTED_ADDITIVE_NULL_FIELDS` = {fixture → pointers}), and assert that the only tree differences are exactly those pointers with value `null`. This route is not available for `IdempotencyFingerprintGoldenTest`, whose bytes are frozen. Request fields that enter a fingerprint MUST use (a).

## 3. Idempotency fingerprint (Assumption A1)

- Golden test: `uk.jtoye.core.common.idempotency.IdempotencyFingerprintGoldenTest`, against `jackson2-golden/idempotency/request-hashes.tsv`.
- Serializer: `uk.jtoye.core.common.idempotency.IdempotencyJson`, built as `JsonMapper.builderWithJackson2Defaults()` + `DETECT_PARAMETER_NAMES` + no date/duration timestamps + `FAIL_ON_UNKNOWN_PROPERTIES` off + `DEFAULT_VIEW_INCLUSION` off. No inclusion override, so the default is ALWAYS.
- The `storefront.guest-order` fingerprint is `GuestCheckoutIdentity(UUID shopId, GuestOrderRequest request)` (a private record in `PublicStorefrontService`, line 742). The `.legacy` fingerprint is the bare `GuestOrderRequest`. A new `GuestOrderRequest` field therefore enters BOTH.

**A1: MEASURED (out-of-tree replica); TO-MEASURE-IN-31.1-03 in-tree.** A replica of `IdempotencyJson`'s exact
builder was compiled against the same jars the tree resolves (jackson-databind/core 3.1.7,
jackson-annotations 2.22), with `javac -parameters` on JDK 25.0.4.1. Output:

```
IDEM before            = {"customerName":"Ada","qty":1}
IDEM plain null field  = {"customerName":"Ada","qty":1,"acknowledgedAllergenMask":null}  equal_to_before=false   <- fail direction
IDEM NON_NULL null     = {"customerName":"Ada","qty":1}  equal_to_before=true
IDEM NON_NULL set=65   = {"customerName":"Ada","qty":1,"acknowledgedAllergenMask":65}
IDEM record before     = {"customerName":"Ada","qty":1}
IDEM record NON_NULL   = {"customerName":"Ada","qty":1}  equal_to_before=true
J3 default plain null  = {"acknowledgedAllergenMask":null,"customerName":"Ada","qty":1}
J3 default NON_NULL    = {"customerName":"Ada","qty":1}
```

So `@JsonInclude(JsonInclude.Include.NON_NULL)` from `com.fasterxml.jackson.annotation` is honoured
by Jackson 3.1.7. It works on both a class field and a record component, and on both the frozen
idempotency mapper and a default Jackson-3 mapper. A null field leaves the bytes, and so the hash,
unchanged. Without the annotation, the bytes change.

31.1-03 still owes the in-tree confirmation: after adding the annotated fields to `GuestOrderRequest`,
`IdempotencyFingerprintGoldenTest` must stay 15/0/0. Its fail direction is the same field without the annotation,
which must red the two `storefront.guest-order*` rows.
