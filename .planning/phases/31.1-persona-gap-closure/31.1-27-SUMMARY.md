## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The parity test read the wrong `.env.example`**
- **Found during:** Task 2, on the first run of the parity test.
- **Issue:** `IntegrationTestSupport.locateRepoFile` walks up from the working directory, so from `core-java/` it found `core-java/.env.example` before the root file. The ENV_EXAMPLE arm failed with "found 0". Worse, `envExampleHasNoSecondSource` passed vacuously against the wrong file.
- **Fix:** a `repoFile()` helper anchors every lookup at the repository root (the directory holding `docker-compose.full-stack.yml`) and fails closed if the file is missing.
- **Files modified:** `RegisteredOfficeParityTest.java`, before its first commit.
- **Verification:** 12/12 green, and the four break arms each go red.

**2. [Rule 1 - Bug] An existing test pinned the old decision**
- **Found during:** the full Jest run after Task 3.
- **Issue:** `company-contact.test.tsx` asserted that `.env.example`'s registered office is the empty string, which is the phase 31 decision D-14 reversed. Task 2 made it fail: 1 failed, 2225 passed.
- **Fix:** it now asserts the shape the consumers read: one double-quoted value with no `#`, trimmed, longer than 10 characters, without 13434105. The exact string stays pinned once, in the parity test.
- **Commit:** `b89b6053`.
- **Verification:** the break arm (a trailing comment) goes red; 11/11 after restore.

**3. [Rule 1 - Bug] The dates test lost its non-vacuity control**

- **Fix:** the control now requires every exception's description, JSON-encoded, in the serialisation.

**4. [Rule 2 - Correctness] Stale published statements corrected**
