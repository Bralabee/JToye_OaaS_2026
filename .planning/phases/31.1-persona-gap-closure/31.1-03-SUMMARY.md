# Phase 31.1 Plan 03: Server-enforced allergen acknowledgement (#784, #785) Summary

**A storefront order now has to carry the allergen set the customer was shown. The server refuses a missing one (422) and refuses a stale one (409). The stale refusal carries the current set, attributed per line. An accepted order records the mask, the time and the STOREFRONT channel. Vendor, API and MCP orders record VENDOR with a NULL acknowledgement. The tests are red-then-green through the real endpoint, and a break arm proves the comparison is equality, not containment.**

## Accomplishments

**#784 at the server.** On the unfixed tree, a POST with no acknowledgement returned **HTTP 201**. Now:
- The same POST returns 422 `allergen-acknowledgement-required`, keyed or keyless.
- Order count is unchanged and no reservation row is left.

**#785 at the server.** On the Task-1 tree, the persona race was **accepted with 201**. In that race the customer reads Gluten/Fish/Peanuts, the vendor PUT adds Milk, and the customer submits what they read. Now:
- The race gets 409 `allergen-acknowledgement-stale` with:
  - `currentAllergenMask` 89;
  - `currentAllergens` `["Gluten","Fish","Peanuts","Milk"]`, in bit order;
  - `acknowledgedAllergenMask` 25;
  - `lines` `[Satay → Peanuts, Fish Pie → Gluten/Fish/Milk]`, in basket order, not bit order.
- Re-acknowledging under the SAME Idempotency-Key then returns 201, so the refused submit did not hold the key.

**Recorded by construction (D-06).** The union is accumulated in the product loop that calls `OrderAllergenSnapshot.capture`. So on every accepted storefront order, `orders.allergen_ack_mask = bit_or(order_items.allergen_mask)`. The test asserts this by SQL on `orders` and on the `orders_aud` mirror.

**V69:** the three nullable columns on `orders` and `orders_aud`, plus two CHECKs on `orders`. There is no backfill and no DEFAULT, and the header comments explain why NULL ≠ 0.

**Golden contract kept (D-21).**
- `IdempotencyFingerprintGoldenTest` stays 15/0/0, and nothing under `jackson2-golden/` changed.
- This also closes the in-tree A1 confirmation 31.1-01 owed: with the field un-annotated, exactly the two `storefront.guest-order*` rows go red.

**Every caller migrated.** Six caller classes send the CURRENT mask through `GuestOrderAcknowledgements`, and `seed-order-metric.sh` sends it too. The OpenAPI snapshot diff is +7 lines on one schema.
