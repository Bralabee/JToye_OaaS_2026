# Phase 31.1 Plan 06: Save-time and read-time allergen reconciliation (#787) Summary

**A product whose ingredients write an allergen in CAPITALS or `**bold**` without ticking it now saves with a typed `UNDECLARED_INGREDIENT_ALLERGEN` warning naming it. Every vendor and public product DTO carries the disagreement, all computed by the one `OrderAllergenAggregator` the kitchen ticket already uses. The declared mask is stored exactly as sent.**

## Accomplishments

- **#787 reproduced and closed at the backend.** The persona's exact text, `rice, butter (MILK), pepper` with mask 0, gets these results:
  - `POST /api/v1/products` returns 201 with `allergenWarnings: [{code: UNDECLARED_INGREDIENT_ALLERGEN, allergenBit: 6, allergen: "Milk", message: "The ingredients name Milk, but it is not ticked as an allergen. Tick it, or check the ingredients."}]`.
  - `products.allergen_mask` reads 0 by SQL.
  - The public menu row carries `undeclaredIngredientAllergens: ["Milk"]`.
  - A PUT with Milk ticked clears both.
- **Capitals count as emphasis.** `collectFlags` now runs a second pass over the parser's plain text: a single linear character walk with no regex. It picks up words of 3 or more ASCII capitals bounded by non-letters, resolves each through `AllergenCatalog.resolveBits`, and shares the per-item de-duplication. Flags come out in catalogue bit order. `IngredientMarkupParser` is untouched (its diff over the plan range is empty), so the PPDS label golden is unchanged.
- **Pitfall 11 covered.** The warning comes from a `ProductMapper` `@AfterMapping`, so every `toDto` site carries it: create, update, get-by-id (including the cached loader), list, search and the image mutations. The vendor products list can show the disagreement instead of "No allergens".
- **The kitchen ticket sees capitals too.** `OrderAllergenSnapshot.capture` goes through the same aggregator, so the V63 `allergen_flag_mask` for `butter (MILK)` is now Milk, with the declared line mask still 0.
- **A7 measured.** Over 57 products (21 `DemoDataSeeder` items and 36 live dev rows, read-only), flags went from 0 before to 1 after. The one new flag is `ade-Party Jollof`, the #787 product itself, and it is a true undeclared allergen. The two other live products written in capitals declare their allergens, so they gain nothing.

## Decisions Made

- **Whole-word capitals only.** A word written wholly in 3 or more ASCII capitals is emphasis. Title Case is not: vendors capitalise every ingredient, and reading that as emphasis would flag nearly every product. A capital run that continues into lower case (`MILKy`) is not a word in capitals. Over-flagging stays bounded by `AllergenCatalog`'s conservative synonym list.
- **Bit-ordered flags per item.** The emission order changed from discovery order to catalogue bit order, so `**sesame**, WHEAT` reads Gluten then Sesame. Existing assertions were already bit-ordered within a span, and kitchen flags are a bitmask.
- **Route (a) from 31.1-01 §2 for `ProductDto`.** Route (b), declaring additive nulls in the wire test, would have meant editing Phase 38's test. NON_NULL keeps both the golden and the test untouched, and the mapper guarantees a list on every real response.

- **Pre-deploy cache entries.** A `products` by-id entry cached under `v4:` by a build without this change has no `allergenWarnings`.
