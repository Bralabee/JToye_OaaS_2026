# Phase 31.1 Plan 26: My account data-rights page and honest email statements Summary

**A signed-in customer now has `/shop/account`, reached from "My account" in the storefront menu. "Download my data" and "Delete my account" each lodge one request through the existing public DSAR intake, with the address read-only and an Idempotency-Key per action, and both are still confirmed by email. Deletion first opens a dialog listing what will happen. The shop slug `account` is reserved in both config sources. The privacy notice (v1.1) and `/unsubscribe` now say what J'Toye actually emails, including password resets, state that no marketing is sent, and link to real routes instead of "contact the vendor".**

## Accomplishments

- `/shop/account` is a server page (noindex, title "My account — J'Toye"). It mirrors My Orders: with no session cookies it serves the sign-in wall returning to `/shop/account`, and otherwise it renders `AccountClient` with the email from the ID token. A live refresh cookie alone is enough, because this page calls no authenticated API.
- `AccountClient` sends both actions to `POST /api/v1/public/gdpr/dsar` through `publicApiClient` with no bearer token. Each action keeps its own key in a ref, minted on its first press and reused on retry, and its own in-flight ref and busy state. The success copy is a constant and nothing the API returns is rendered. A 429 gets its own message. A token with no email shows an explanation and no buttons.
- The deletion dialog (Radix, from `components/ui/dialog`) lists four consequences: details removed from orders and reviews at every shop; the sign-in account deleted (31.1-11); order and tax records kept without your details; nothing happens until you confirm by email. Cancel lodges nothing, and the dialog cannot be closed while a request is in flight.
- `account` is reserved in `ShopService`'s `@Value` default and in `jtoye.shop.reserved-slugs`. No compose or k8s file overrides `SHOP_RESERVED_SLUGS`. The dev DB was checked: 5 shops visible, none slugged `account`.
- `lib/email-scope-copy.ts` holds the statement, and both pages render it. The privacy notice gains an "Emails" section (anchor `#emails`) with a My account link, goes to v1.1, and records the change. `/unsubscribe` shows the statement and both links under every state, its per-state copy drops every "contact the vendor", and MARKETING is no longer given a label.
- `ssr-routes.conf` declares `shop/account/page.tsx` as SSR, bound to `frontend/e2e/customer-account.spec.ts`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The planned email statement would have been untrue**
- **Found during:** Task 3 GREEN
- **Issue:** the plan's wording was "we email you only about your orders and about data requests you make". `infra/keycloak/realm-export-customers.json` sets `resetPasswordAllowed: true` with an `smtpServer` block, so a customer who resets a password receives an email from J'Toye, and a legal notice would have said "only" falsely.
- **Fix:** the statement now reads "J'Toye only emails you about your orders, about data requests you make, and about your sign-in account when you ask us to (for example, to reset your password)." The content pins in both RED tests were updated to match after the RED commit. The senders were enumerated from the tree: EmailNotificationService / EmailChannel for ORDERS and FINANCIAL, DsarVerificationMailer, DsarOutcomeMailer, and Keycloak's reset email. MARKETING is refused by ConsentGate without an opt-in that no surface records.
- **Files modified:** `frontend/lib/email-scope-copy.ts`, both test files
- **Committed in:** `349c8a12`

**2. [Rule 3 - Blocking] Shared copy module instead of constants exported from `privacy/page.tsx`**
- **Found during:** Task 3
- **Issue:** the plan asked for "exported copy constants", but a Next.js App Router page may only export its reserved names, and the build's page-type check refuses others. Two pages also had to carry the same statement.
- **Fix:** added `frontend/lib/email-scope-copy.ts`, which is not in `files_modified`. Both pages render from it.
- **Committed in:** `fd581e91` (skeleton), `349c8a12`

**3. [Rule 2 - Missing critical] Route-table drift arm and real Spring binding in the slug test**
- **Found during:** Task 2
- **Issue:** the existing `ShopServiceTest` reserved-slug tests inject a hardcoded set by reflection, so they could not detect `account` missing from either source.
- **Fix:** `ShopReservedSlugAccountTest` builds `ShopService` in an `ApplicationContextRunner` with `ApplicationConversionService`, the converter Boot installs, so the comma-list-to-`Set` binding is the production one. It runs once against the bare `@Value` default and once against application.yml's base document with the OS environment source removed. It also walks `frontend/app/shop/`. The drift arm fails loudly (no skip) if that directory cannot be read.
- **Committed in:** `d715045a`

**4. [Rule 2 - Missing critical] Privacy version raised to 1.1 with a change note**
- **Found during:** Task 3
- **Issue:** the notice's own "Changes to this notice" section promises to raise the version and say what changed for a material change.
- **Fix:** `VERSION = "1.1"`, `LAST_UPDATED = "7 October 2026"`, and the line "Version 1.1 (7 October 2026) added the section on the emails we send." is asserted by a test.
- **Committed in:** `349c8a12`

**5. [Rule 2 - Missing critical] MARKETING unsubscribe category no longer labelled**
- **Found during:** Task 3
- **Issue:** a link carrying `category=MARKETING` rendered "You won't receive any more marketing emails", which describes the platform as sending marketing and breaks the plan's own prohibition.
- **Fix:** removed from `CATEGORY_LABEL`, so it falls back to "these". The token flow itself is unchanged.
- **Committed in:** `349c8a12`

**6. [Rule 2 - Missing critical] Rate-limit-aware spec shape**
- **Found during:** Task 2
- **Issue:** the intake allows 5 requests per IP per hour. Running the click-through on both projects (4 lodges) plus dsar-verify-link.spec.ts (2) would hit 429 inside one suite run.
- **Fix:** the click-through is `@desktop-only` and uses a fresh registered customer each run, which also keeps the per-address limit of 3 per day clear. The served-HTML arm runs on both projects, because it lodges nothing.
- **Committed in:** `e37d1478`
