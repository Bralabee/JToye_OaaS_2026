# Phase 31.1 Plan 24: Who the customer is buying from (#789) Summary

**The public shop endpoint now carries the seller's statutory identity, read from one tenant's FORCE-RLS row on an anonymous request without ever setting TenantContext. One `SellerBlock` shows it, with the platform-not-seller and CCR reg 28(1)(c) no-cancellation statements, in the server-rendered shop page, at checkout before Place order, on the cash confirmation and on the card payment step.**

## Accomplishments

### Backend: `GET /api/v1/public/shops/{slug}` now returns `seller`

The `seller` object carries:
- `legalName` and `entityType`;
- `companyNumber`, only for a COMPANY;
- `vatNumber`, when the trader is VAT-registered;
- `addressLines`, the geographic address;
- the shop's `email` and `phone`.

It carries nothing else: no id, no tenant, no version. If the tenant has no identity, the field is absent. The list, near and search endpoints are unchanged and still run one query per page.

`TraderIdentityService.findPublicSeller` reads the tenant's identity like this:
- It pins the SHOP's tenant in its own REQUIRES_NEW read-only transaction.
- Every query also carries an explicit tenant predicate.
- It reads through the EntityManager, not a repository.
- It never touches TenantContext on the request thread.

### Frontend: one `SellerBlock` for every customer surface

`SellerBlock` uses one fixed field order on every surface:
1. legal name and entity type
2. company number
3. VAT number
4. address
5. email (as a `mailto:` link)
6. phone (as a `tel:` link)
7. the platform statement
8. the cancellation statement

A field the trader does not have is not rendered at all, so no label is left with nothing after it. With no seller on file, the block says "The seller has not provided their legal details yet." and links to J'Toye's own `/legal` page.

Where the block appears:
- **Shop page.** The server component renders it from the shop it has already loaded. It is in the served HTML, needs no client fetch and causes no layout shift. The title, meta tags, canonical link and JSON-LD are untouched.
- **Checkout form.** It sits above the allergen panel, so the allergen panel is still the last thing read before Place order.
- **Cash confirmation.** It appears before "Track your order".
- **Card payment step.** It appears before the card form.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1: Unfalsifiable criterion] The "TenantContext is empty after the request" assertion could not fail**
- **Found during:** Task 1, break arm C.
- **Issue:** The security filter chain clears TenantContext in a `finally` at the end of every request. So `assertThat(TenantContext.get()).isEmpty()` after `mockMvc.perform` passed with a deliberate `TenantContext.set` and no clear (8/0/0).
- **Fix:** A `@MockitoSpyBean` on `TraderIdentityService` records TenantContext on the request thread the moment `findPublicSeller` returns. A non-vacuity check confirms the read actually ran. Both the original and the replacement are recorded here and in the evidence file.
- **Files modified:** `PublicSellerIdentityIntegrationTest.java`
- **Verification:** Arm C2 reds 2 of 8; the clean tree is 8/0/0.
- **Committed in:** `9991e877`

- **Issue:** `text-slate-500` gives 4.43:1 on cream; AA needs 4.5.

- **Files modified:** `seller-block.tsx`
