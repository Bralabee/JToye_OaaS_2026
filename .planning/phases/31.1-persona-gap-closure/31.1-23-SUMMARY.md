# Phase 31.1 Plan 23: Per-dish allergens in the basket and at checkout Summary

**Every basket line, on the basket page and in the cart drawer, now states that dish's own allergens, read from the live catalogue: "Contains: Milk", "No allergens declared", or "Ingredients name: MILK – check with the shop". At checkout the combined set is unchanged, and beneath it the panel says which dish carries each allergen ("Milk — Jollof Rice, Puff Puff"). Each dish's D-09 flag appears as its own advisory Check line. The order the checkout submits is byte-identical to before.**

## Accomplishments

- **#860 at checkout (Task 1).**
  - `lib/basket-allergens.ts` holds one set of pure functions over the basket and the live catalogue:
    - `basketAllergenAttribution` lists allergens in catalogue bit order and dishes in basket order, and a shared allergen appears once;
    - `lineAllergens` and `basketAllergenFlags` give each line's statement and its D-09 flags;
    - `attributionAgreesWith` checks the attribution against the set the panel states.
  - NOT RECORDED propagates. One unresolved line makes the whole answer `null`, never a partial list.
  - The panel shows "Which dishes contain them:" with one line per allergen, beneath the chips and above the acknowledgement. It shows them only when they name exactly the set the panel states.
  - The checkout now passes each line's server-computed `undeclaredIngredientAllergens` as the panel's advisory Check lines. They used to be `null`.
- **#860 in the basket (Task 2).** `components/storefront/basket-line-allergens.tsx` provides:
  - `useCatalogueIndex(slug)`: `undefined` while loading, `null` for NOT RECORDED;
  - `BasketLineAllergens`: the menu card's rule, `productAllergenStatement`.

  The basket page reads the catalogue once. The drawer's line list is its own component inside the sheet content, so it reads the catalogue on each open and never while closed.
- **Goods kept:**

  - **The mask the checkout sends:** the same declared union.

- **No new client storage.** The cart's JSON is asserted byte-identical before and after the lines render. No new key, so the 31.1-05 registry is unchanged.

### Auto-fixed Issues

**1. [Rule 1 - Test correctness] The byte-identity tests must seed the provider's canonical shape**
- **Found during:** Task 2 GREEN.
- **Issue:** On hydration, `CartProvider` stamps `owner: null` into the stored payload. This is pre-existing #459 behaviour. A seed without `owner` therefore differed from storage whatever the basket did.
- **Fix:** Both new byte-identity tests seed `{shopSlug, owner: null, items}`. Any later difference is then a write by the basket. The WRITES_STORAGE arm proves the assertion still goes red.
- **Files modified:** `cart.test.tsx`, `cart-drawer.test.tsx` (new tests only).
- **Committed in:** `26641656`.

- **Assertions:** the existing assertions are unchanged.
