# Phase 31.1 Plan 21: Storefront cards and dish modal name allergens before Add Summary

**Every menu card now states its allergens in words above the price and Add row: "Contains: Gluten, Milk", "No allergens declared", or "Ingredients name: MILK – check with the shop". The Add button's accessible description carries that line, so a screen-reader user hears it before adding. The bare "△2" is gone. The dish modal now opens with a named "Allergen Information" section directly under the dish name, in every state. It holds a "Contains" list, a separate "May contain: Sesame" line and the ingredients line, and none of the three is ever merged into another.**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - One rule, one place] `lib/product-allergens.ts` is a new file, and `allergen-copy.ts` gained `containsCopy`**
- **Found during:** Task 1.
- **Issue:** The card and the modal both need the same three-state decision, and neither file in the plan's list can host it for the other. The "Contains:" phrase was not in the copy module, and the plan's own rule is that all wording comes from it.
- **Fix:** One rule module, plus `containsCopy` and `CONTAINS_LABEL_COPY` in `allergen-copy.ts`, pinned verbatim in `allergen-copy.test.ts` first. None of these three files is in `files_modified`.
- **Commits:** `4a69bfbf` (RED skeleton), `10b4250a`.

**2. [Rule 1 - Unfalsifiable as written] "200% zoom via deviceScaleFactor"**
- **Found during:** Task 2 (e2e).
- **Issue:** The plan says "deviceScaleFactor/CSS zoom per the spec's existing approach". The spec has no existing approach, and `deviceScaleFactor` changes only the pixel ratio, not the CSS layout. A placement check run under it would pass on the unfixed tree too.
- **Fix:** The spec emulates 200% zoom by halving the CSS viewport (195×422). A control assertion checks that `innerWidth` is 195. The reasoning is recorded in the spec header.
- **Committed in:** `8bf45bcf`.

**3. [Rule 2 - Data integrity] The e2e restore uses a dedicated fixture product, not an edit to a demo dish**
- **Found during:** Task 2.
- **Issue:** No seeded dish carries a may-contain mask. An existing dish's NULL may-contain cannot be restored through the API (31.1-14), so editing one would fabricate a "0" vendor statement on a demo dish.
- **Fix:** The spec finds the fixture product by SKU or creates it, shows it for the test, and in a `finally` hides it again. It verifies the hide by content: the vendor read-back shows `available: false`, and the public menu is non-empty and no longer lists the id.
- **Committed in:** `8bf45bcf`.

**4. [Rule 2 - Contract] Modal boundary amber-200 → amber-600**
- **Issue:** The 31 UI-SPEC requires allergen panel boundaries of amber-600, for 3:1 non-text contrast.
- **Fix:** The section and the chip borders now use amber-600, and the chip text is amber-800.
- **Committed in:** `3fd77895`.

### Notes, not deviations

- The plan's `<interfaces>` says the fields are `string[]`. They are typed optional and nullable (`?: string[] | null`) for old-backend tolerance, matching the file's convention. A test covers the absent case.
- The plan suggests a "+2" overflow for a space-constrained card line. The line wraps instead, so nothing is hidden and the overflow form is unnecessary.
