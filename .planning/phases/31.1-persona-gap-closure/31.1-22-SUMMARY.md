# Phase 31.1 Plan 22: The kitchen sees the allergy note and marks it read Summary

**A customer's allergy note now shows on the kitchen board card. It sits in a solid black-and-white "ALLERGY NOTE" block directly under the allergen banner, above the items, with a large "Mark allergy note as read" button. "Read by you at 18:05" or "Read by a member of staff at 18:05" appears only after the server records it. The printed ticket carries the note and whether anyone has read it. The vendor order detail shows the same block, plus one line saying how the order was placed: what the customer confirmed and when, "Placed by the shop", or "not recorded". Every order-record date on those surfaces is now en-GB in London time ("4 October 2026, 00:10"), through one helper, `lib/uk-datetime.ts`.**

**Task 1: the kitchen sees the note first and marks it read**
- `AllergyNoteBlock` renders the note as plain text. It keeps the customer's line breaks and never truncates.

- A burst of presses sends one request. The read line appears only from the server's `allergyNoteAcknowledgedAt`/`By`, and a 200 without them counts as a failure.

## Decisions Made

See `key-decisions` in the frontmatter. Two of them answer questions 31.1-13 left open:

- **How to show who.** 31.1-13 records the JWT subject, a Keycloak UUID. STAFF cannot read the staff directory (`/api/v1/staff` is GROUP_ADMIN-only), and the session does not carry the subject on `session.user` at runtime (Auth.js copies only name, email and picture). So the block decodes the viewer's own access token, for display only, and the reader is shown as:
  - "you" for the viewer's own account;
  - "a member of staff" for any other UUID;
  - a non-UUID principal as plain text (which would also surface a machine client by name).
  - The audit record itself is unchanged.
- **STOMP.** I did not add a STOMP event. The kitchen board already polls every 60s and refetches on every order event. Adding a new event type means a Java change plus the outbox `publishRow` extension (memory: outbox flusher dispatch trap), which is outside a frontend-only plan.
