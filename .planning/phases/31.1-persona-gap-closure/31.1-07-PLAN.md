Give the DSAR worker a way to reach the subject that does not create a readable personal-data store (D-19).

email, and Article 15 needs a "we hold nothing" reply — all need the address, and V62 stores only a

row and tests. Wiring the key into compose, k8s, the nightly and the hybrid runtime is 31.1-08.
</objective>

    - encrypt(SUBJECT_ADDRESS, id, "a@b.test") then decrypt(SUBJECT_ADDRESS, id, ct) -> "a@b.test"
    - two encryptions of the same plaintext differ (random IV)
    - one flipped ciphertext byte -> decrypt throws (tag check)
    - decrypt with a different request id or purpose -> throws (AAD binding)
    - key of 63 hex chars, non-hex, or blank -> IllegalStateException whose message names jtoye.gdpr.dsar.encryption-key and contains no key material

    - lodge -> dsar_request.subject_email_ciphertext non-null; its bytes do not contain the ASCII bytes of the address; decrypt -> the trimmed address
    - worker completes the request -> status COMPLETED and ciphertext NULL
    - exhausted request -> FAILED and ciphertext NULL
    - PENDING_VERIFICATION with verification_expires_at in the past -> sweep -> EXPIRED, completed_at set, ciphertext NULL
    - a direct UPDATE setting status COMPLETED while the ciphertext is non-null -> rejected by the CHECK
  </behavior>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public intake -> dsar_request | an anonymous lodger's address enters a non-RLS platform table |
| database <-> key | the key lives outside the database (env/secret), the ciphertext inside |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-31.1-20 | Information disclosure | a database dump or backup revealing subject addresses | high | mitigate | AES-256-GCM with the key outside the database; only ciphertext stored; IT asserts the plaintext bytes are absent |
| T-31.1-21 | Information disclosure | key leaked in logs or exception messages | high | mitigate | Validation message names the property only; DsarCipher never logs; grep for key-shaped literals in resources |
| T-31.1-22 | Tampering | ciphertext swapped between rows or reused for another purpose | medium | mitigate | GCM tag + AAD binding purpose and request id; unit cases for wrong id and wrong purpose |
| T-31.1-23 | Information disclosure (retention) | an unverified request keeping an address indefinitely | medium | mitigate | DsarRequestExpirySweep + V70 CHECK + retention row with named enforcement |
| T-31.1-24 | Denial of service | core-java refusing to boot without a key | low | accept | Intended (D-19 fail fast); 31.1-08 wires the key into every runtime before any rebuild |
| T-31.1-25 | Information disclosure | no key rotation | low | accept | Data is transient (bounded by verification TTL + processing); rotation = drain the queue then swap the key; recorded in the SUMMARY |
| T-31.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | JDK javax.crypto only; no package installed |
