<objective>
Make the coverage rule enforceable: a static, default-deny manifest gate that fires at the moment a
route becomes server-rendered without a raw-HTML assertion — and that also records, per route, why
every remaining client component is one.

ROADMAP criterion 1, verbatim: *"A route-interception stub is never the coverage story for a
server-rendered route (#542, #507). #507's 25 queued conversions each silently drop their spec
coverage under the current approach; the phase must produce a pattern that does not, shown to fail
against a stubbed SSR route. #463's premise is recorded as wrong — `/shop` is client-rendered too —
so scope from measurement, not from #463."*

Purpose: plan 34-01 built the instrument. Without a gate, the next conversion is free to ship with a
browser stub as its only coverage, which is the exact silent regression #542 was filed for. This is
#542's option 4, made falsifiable, built on the idiom of `check-e2e-skip-budget.sh` — which already
carries default-deny, stale-entry-fails, a both-directions self-test and VOID-on-unparseable.

The manifest also discharges #507's last acceptance criterion: every route left as a client
component is listed WITH A REASON. Measured on this tree 2026-08-28 with a strict directive parser:
38 `page.tsx` files — 21 CLIENT, 17 not; of the 17, exactly 4 load data server-side (`/`, `/shop`,
`/shop/[slug]`, `/shop/orders`). Re-measure rather than trusting those numbers, and never count with
`git grep -l '"use client"'`, which is measurably wrong by 4 because four already-converted pages
document their own conversion in prose (RESEARCH Pitfall 1).

Output: the gate, the manifest, and the CI wiring plus the honest statement of what the per-PR
stack-free E2E job's green does and does not cover.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository contents → CI verdict | The gate's inputs are files in the tree; its verdict gates merges |
| a declared exemption → coverage claim | A CLIENT entry is a standing statement that this route needs no server-render coverage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-07-01 | Repudiation | a classifier that silently stopped working | mitigate | R-3 self-test runs first with a known server page and a known client page, VOIDs on a wrong verdict OR a missing fixture, and was exercised with a licence-header variant |
| T-34-07-02 | Repudiation | a gate that passes over nothing | mitigate | Zero-discovery is VOID (exit 2), exercised by pointing discovery at an empty directory |
| T-34-07-03 | Tampering | a gate satisfied by its own prose | mitigate | Comment stripping before every content match (the `check-playwright-mobile-contract.sh:57-62` fix), plus the strict first-statement directive rule that Pitfall 1 measured as necessary |
| T-34-07-04 | Information Disclosure | an SSR conversion using a service identity | mitigate | Every dashboard CLIENT reason states the ASVS V3/V4 requirement (forward the caller's token; RLS is the enforcement point), so the next converter meets the constraint in the manifest before writing code |
| T-34-07-05 | Repudiation | the stack-free CI job read as SSR coverage | mitigate | The `frontend-e2e` job now states, with measured byte and occurrence counts, exactly what its green does and does not cover |
| T-34-07-06 | Denial of Service | a required job made permanently VOID | mitigate | The gate is static and needs no runtime, so it cannot VOID on a hosted runner for environmental reasons; every VOID path names a real defect in the conf or the tree |
| T-34-07-SC | Tampering | package installs | mitigate | The gate uses bash, find, awk and sed only — no jq requirement is introduced unless the script actually needs it, in which case its absence must VOID. `git diff --name-only -- frontend/package.json frontend/package-lock.json edge-go/go.mod` must be empty |
