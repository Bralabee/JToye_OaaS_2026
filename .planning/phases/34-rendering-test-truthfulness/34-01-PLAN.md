<objective>
Build the instrument criterion 1 needs: a shared raw-HTML coverage helper, a committed proof that a
browser route stub cannot answer for it, and the missing served-HTML assertion for `/shop/orders`.

ROADMAP criterion 1, verbatim: *"A route-interception stub is never the coverage story for a
server-rendered route (#542, #507) ... the phase must produce a pattern that does not [silently drop
coverage], shown to fail against a stubbed SSR route."*

Purpose: `page.goto` + `expect(locator)` sees the union of the server and browser render paths and
therefore cannot tell them apart — measured on the pre-#507 tree, the DOM assertion stayed green
against a server that rendered nothing. `request.get()` sees only the server path. This plan makes
that distinction a reusable, self-proving instrument.

Output: `frontend/e2e/helpers/served-html.ts`, `frontend/e2e/ssr-coverage.spec.ts`, and a
re-pointed `storefront-ssr-seo.spec.ts` carrying the newly measured stack-free fail arm.
</objective>
