<objective>
Remove two of the four `#99 follow-up` mount-time `setState`-in-effect suppressions by replacing the
sidebar's and the mobile tab bar's private theme state with one shared `useTheme()` built on
`useSyncExternalStore`.

ROADMAP criterion 2, verbatim: *"The four mount-time `setState`-in-effect hydration sites are gone
(#202), with the resurrected ESLint gate shown to fail against a reintroduced one."*

Purpose: these two components currently share theme state THROUGH A DOM CLASS — the tab bar reads
`document.documentElement.classList.contains("dark")`, which is only correct if the sidebar's effect
has already run. Extracting one hook removes both suppressions and the implicit mount-ordering
dependency in the same change; copying the logic into a second private hook would remove the
suppressions and keep the bug. The #457 precedent is explicit: extract, do not copy.

Output: `hooks/use-theme.ts`, its Jest suite, and two rewired components.

<feature>
  <name>Shared theme state on an external store</name>
  <files>frontend/hooks/use-theme.ts, frontend/hooks/__tests__/use-theme.test.tsx</files>
  <behavior>
    `useTheme()` returns `{ dark: boolean, setDark(next: boolean): void, toggle(): void }`.

    Cases:
    - `localStorage["theme"] === "dark"`, `matchMedia("(prefers-color-scheme: dark)")` false -> `dark === true`
    - `localStorage["theme"] === "light"`, system prefers dark -> `dark === false` (an explicit preference wins)
    - no stored value, system prefers dark -> `dark === true`
    - no stored value, system prefers light -> `dark === false`
    - `localStorage.getItem` throws (private mode / blocked storage) -> `dark === false`, no exception escapes
    - server snapshot (no `window`) -> `false`, and rendering must not throw
    - `setDark(true)` -> writes `localStorage["theme"] === "dark"`, adds the `dark` class to `document.documentElement`, and every mounted subscriber re-renders with `dark === true`
    - `setDark(false)` -> writes `"light"`, removes the class, subscribers see `false`
    - `toggle()` -> inverts the current value and has the same two side effects
    - a `storage` event for key `theme` from another tab -> subscribers observe the new value
    - a `storage` event for an unrelated key -> no re-render is triggered by this store
    - two components mounted simultaneously observe the SAME value after either one toggles
  </behavior>
  <implementation>
    `useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)` exactly as
    `components/marketing/reveal.tsx:34-58`. `getServerSnapshot` returns `false` — it is mandatory,
    not optional: `app/layout.tsx` sets `dynamic = "force-dynamic"` app-wide, so every one of these
    renders on the server on every request, and `useSyncExternalStore` throws during SSR without it.
    Guard every browser access with the repo's `canEnhance()` predicate shape from
    `lib/gsap-gate.ts:40-42`, and wrap the `localStorage` read in try/catch returning the default,
    as `hooks/use-cart-count.ts:16-36` does. `subscribe` keeps a module-level listener Set plus a
    `storage` listener and a `matchMedia` change listener; the returned teardown removes exactly
    what it added.
  </implementation>
</feature>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser storage → DOM | `localStorage["theme"]` is attacker-writable by any script already running on the origin and is read on every dashboard render |
| server render → client hydration | The dashboard shell renders on the server on every request (`dynamic = "force-dynamic"`) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-02-01 | Tampering | `use-theme.ts` snapshot → `classList` | mitigate | Only a boolean reaches `classList.toggle("dark", next)`; the stored string is never interpolated into a class name or any DOM sink, and any value other than `"dark"`/`"light"` is treated as absent |
| T-34-02-02 | Denial of Service | `getServerSnapshot` | mitigate | `useSyncExternalStore` throws during SSR without a server snapshot, and every dashboard render is a server render — the suite asserts a server render produces markup and throws nothing |
| T-34-02-03 | Denial of Service | listener leak | mitigate | `subscribe`'s teardown removes exactly what it added (cleanup symmetry, `use-cart-count.ts:65-71`); a mount/unmount cycle in the suite asserts no listener survives |
| T-34-02-04 | Information Disclosure | theme preference | accept | A light/dark preference is not personal data and never leaves the browser |
| T-34-02-SC | Tampering | npm installs | mitigate | `useSyncExternalStore` is React 19 core; nothing is installed. `git diff --name-only -- frontend/package.json frontend/package-lock.json` must be empty at plan end |
</threat_model>
