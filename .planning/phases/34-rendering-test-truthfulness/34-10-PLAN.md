<objective>
Close the phase: reconcile the counts, record what was deliberately not done, and prove the
delivered runtime matches the branch — then re-earn the skip-budget gate on a fresh full-suite run.

This plan exists because three of this project's standing contracts are end-of-phase obligations
that no individual plan can discharge: `docs/metrics.json` is the single source of truth for test
counts and must be regenerated ONCE on the assembled tree (the Phase 31 lesson — four worktrees each
wrote a different total and every one was wrong); the skip-budget gate VOIDs until a report exists
whose spec digest matches the tree, and EVERY spec edit in this phase invalidates it again (RESEARCH
Pitfall 4, which is why the full run is sequenced last); and a phase is not done until the delivered
runtime matches the branch.

Purpose: this phase edited specs in five plans and added Jest suites in two, changed
`core-java/build.gradle.kts` and the frontend source. Every one of those facts has a consequence
outside the source tree.

Output: regenerated metrics with reconciled prose, a deferred/N-A register, a green skip-budget gate
on a fresh report, and a rebuilt, content-verified runtime.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| built image → running container | A rebuild that is only `start`ed leaves the old code serving |
| test report artefact → gate verdict | The skip-budget gate's verdict is only as fresh as the report's spec digest |
| published counts → reader | `docs/metrics.json` and the prose are the project's standing claim about how much is tested |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-10-01 | Repudiation | a stale runtime passing as current | mitigate | Rebuild with `--build`, then prove by content and identity — image ids, `LastTagTime` (not `.Created`), the running container's image id, and a changed value read out of both running artefacts |
| T-34-10-02 | Repudiation | a stale report satisfying the skip gate | mitigate | The gate's own `specDigest` check must match the tree; the full run is sequenced AFTER every spec edit in the phase, and the S-3 stale-ALLOW arm is executed against the same report |
| T-34-10-03 | Repudiation | hand-computed test counts | mitigate | `docs-freshness.sh --write` is the only writer; the loop-declaration trap is named in the action, and both runner oracles must agree |
| T-34-10-04 | Information Disclosure | `E2E_VENDOR_PASSWORD` in logs or artefacts | mitigate | Sourced from `.env` as the nightly does; never echoed. `git status --porcelain` must show no `.env` or report artefact staged for commit |
| T-34-10-05 | Denial of Service | a red `check-alert-metrics` misdiagnosed as a defect | mitigate | Predicted in the action with its cause and its remedy, and recorded as rc=1 then rc=0 |
| T-34-10-SC | Tampering | package installs | mitigate | Nothing is installed anywhere in this phase; `git diff --name-only origin/main -- frontend/package.json frontend/package-lock.json edge-go/go.mod edge-go/go.sum mcp-server/package.json` must print nothing, and that command is the phase-wide supply-chain assertion |
