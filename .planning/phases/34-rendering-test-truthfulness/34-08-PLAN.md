<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build artefacts → CI verdict | Coverage profiles and reports decide whether a build passes |
| threshold constants → merge decision | A number in version control is the standing claim about how much of the code is exercised |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-08-01 | Repudiation | an empty or unparseable coverage profile read as 0% or as clean | mitigate | Both are VOID (exit 2) in `check-go-coverage.sh`, and both VOID arms are executed and recorded |
| T-34-08-02 | Repudiation | a threshold that has never been observed failing | mitigate | Each Jest counter and the Go floor are raised above the measurement once, the red is recorded, and the change is reverted with a hash-verified restore |
| T-34-08-03 | Tampering | a threshold lowered to make a red build green | mitigate | Thresholds live in version control beside their measurement, date and margin, so a lowering is visible in review; the config comment names the anti-pattern explicitly |
| T-34-08-04 | Denial of Service | breaking the count oracle by editing its Jest run | mitigate | `--json --outputFile` is preserved and the oracle is re-run locally against the `--coverage` report as an acceptance criterion |
| T-34-08-05 | Information Disclosure | coverage artefacts carrying source or secrets | accept | The profile and the summary contain file paths and counters only; the artefact upload path is unchanged |
| T-34-08-SC | Tampering | package installs | mitigate | `coverageThreshold` is built-in Jest config and `go tool cover` is stdlib; nothing is installed. `git diff --name-only -- frontend/package.json frontend/package-lock.json edge-go/go.mod edge-go/go.sum` must be empty |
</threat_model>
