`DatabaseConfigurationValidator` (`core-java/src/main/java/uk/jtoye/core/config/`) emits, on the
`ApplicationReadyEvent` path:
- `DATABASE SECURITY CONFIGURATION CHECK`
- `Database username: {}`
- `User '{}' is NOT a superuser (RLS will be enforced)`
- `DATABASE SECURITY VALIDATION PASSED` on success
- `DATABASE SECURITY VALIDATION FAILED` on failure (which also refuses to start)
So the positive assertion is `grep -c "is NOT a superuser"` >= 1 AND
`grep -c "DATABASE SECURITY VALIDATION PASSED"` >= 1, and the negative is
`grep -c "DATABASE SECURITY VALIDATION FAILED"` == 0.

`26-VALIDATION.md`):

2. Pin evidence to code identity — record the four image identities with the results.
3. Assert negatives with COUNTS, not eyeballs — a missing log line and an absent grep hit look
   identical otherwise.
4. Falsify the backup, don't confirm it — show a `jtoye_app` dump restoring to `products = 0` AND the

   compose apps were up and the XOR guard was bypassed, and the run does not count.
