Split-horizon contract (D-13), resolved at source level during planning against the installed
`@auth/core@0.41.3`:
- `keycloak.issuer.uri` = the POD-REACHABLE issuer (JWKS fetch host). Consumed as core `KC_ISSUER_URI`,
  edge `KC_ISSUER_URI`, frontend `KEYCLOAK_ISSUER_INTERNAL`.
- `keycloak.public.issuer.uri` = the issuer Keycloak STAMPS into tokens (browser-reachable).
  Consumed as core `JWT_EXPECTED_ISSUER`, edge `JWT_EXPECTED_ISSUER`, frontend `KEYCLOAK_ISSUER`.
- Auth.js performs OIDC discovery at exactly two call sites and BOTH are gated:
  `lib/actions/signin/authorization-url.js:14` only when `authorization.url` is absent, and
  `lib/actions/callback/oauth/callback.js:35` only when BOTH `token.url` and `userinfo.url` are
  absent. `frontend/auth.ts:55-59` sets all three, so **no discovery request is made and no
  `auth.ts` change is required**. In the non-discovery branch Auth.js sets
  `as.issuer = provider.issuer`, which is what the id_token `iss` is validated against — hence
  `KEYCLOAK_ISSUER` must be the STAMPED (public) issuer and `KEYCLOAK_ISSUER_INTERNAL` the
  pod-reachable one. `frontend/auth.ts:47` already falls `kcPublicBase` back to
  `KEYCLOAK_ISSUER`, so no `NEXT_PUBLIC_*` runtime env is needed for the authorize redirect.
- edge-go reads both names already: `edge-go/cmd/edge/main.go:139,141`
  (`expectedIssuer := getEnv("JWT_EXPECTED_ISSUER", keycloakIssuer)`).

D-18 evidence gathered during planning: `.github/workflows/ci-cd.yaml:443-449`'s
`docker/build-push-action` step passes **no `build-args` at all**, so every CI-built frontend
image has `NEXT_PUBLIC_API_URL` unset and inlined as undefined, while

build arg for a correctly-baked local image (the image itself is built when plan 26-07 runs it).
