PIT-2 (reproduced with kubectl v1.33.3 / kustomize v5.6.0, the CI-pinned version):
a kustomize strategic-merge patch that adds `valueFrom` to a container env item that already
has `value:` renders an EnvVar with BOTH fields. `kubectl kustomize` accepts it; the API server
rejects it with `env[i].valueFrom: Invalid value: "": may not be specified when 'value' is not
empty`. Therefore the `value: "5432"` line at `k8s/base/core-java-deployment.yaml:72` must be
DELETED in the base — there is no overlay shortcut.

D-17 fix mechanism (built and diffed with kustomize v5.6.0 during planning — use this exact
shape). Replacing `includeSelectors: true` with `includeSelectors: false` +
`includeTemplates: true` + an explicit `fields:` list naming only
`Deployment spec/selector/matchLabels`, `Service spec/selector` and
`PodDisruptionBudget spec/selector/matchLabels` (each `create: true`) produced a full-render
diff of exactly 39 removed lines, EVERY one of them inside a `kind: NetworkPolicy` document.
Deployment / Service / PDB selectors came out byte-identical (so no immutable-selector apply
failure on a live cluster), `default-deny`'s `podSelector: {}` stayed empty, and the kube-dns
egress selector reduced to a bare `k8s-app: kube-dns`. NetworkPolicy `spec` is mutable, so
this is safe to apply to an existing cluster.
