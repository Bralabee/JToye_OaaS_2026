<objective>
Deliver the imperative half of INFRA-01: a shared guard library, an idempotent secret/role/bucket
bootstrap, and `scripts/k8s-local-up.sh` as the single bring-up entry point that replaces the
2026-07-14 rehearsal's multi-step imperative sequence — plus the two adjacent defects that make that
entry point trustworthy (`scripts/deploy.sh`'s phantom `dev` target and the Playwright cookie-domain
hardcode).

Purpose: an overlay that only a human can apply correctly is not a durable replacement for imperative
patches. Three environment facts research verified make the guards load-bearing rather than
decorative: `kubectl config current-context` is UNSET and the only context present is
`sipbihs2aks` (EMPLOYER infrastructure); the compose APP containers are running right now, sharing
the dev Postgres the cluster is about to write to; and neither the `jtoye_backup` role nor the
`jtoye-db-backups` bucket exists, so an un-bootstrapped backup rehearsal would either fail at upload
or "pass" on a zero-row dump.

**Static/live boundary (this plan is the STATIC side — read this before writing any verification).**
`26-VALIDATION.md` splits every proof into (a) a static assertion CI can re-run and (b) a live
observation captured as named evidence. This plan owns (a) only. It AUTHORS the tooling and proves
every property that is falsifiable **without mutating shared state**: syntax, source-level
invariants, the secret inventory's completeness against the rendered overlay, and — the load-bearing
half of D-04 — the guards' **refuse** paths, which are provable *today* precisely because the compose
app containers are up and the minikube profile is stopped. It does NOT start minikube, does NOT stop a
compose container, does NOT create the elevated DB role, the bucket, or any Secret, and does NOT
apply anything. Every one of those mutations, and every criterion that depends on one, belongs to plan
26-07 behind its `checkpoint:human-action` — because this checkout can be driven by a second
concurrent session (`env_concurrent_working_tree` memory), so an unattended plan that stops the dev
stack can disrupt work that is not its own. A guard whose *proceed* path is unproven here is not a
gap: it is the deliberate split, and 26-07 closes it with real state.

Output: `.env`/`.env.example` keys, `scripts/lib/k8s-local-guards.sh`,
`scripts/k8s-local-secrets.sh`, `scripts/k8s-local-up.sh`, a corrected `scripts/deploy.sh`, and a
parameterised cookie domain in `frontend/e2e/stomp-relay.spec.ts`.
