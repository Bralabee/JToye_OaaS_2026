<objective>
Tracer slice, layer 2 of the DPLY-01 path. Under the enforcing engine D-01 puts on the cluster (Cilium, plan 29-01),
today's NetworkPolicies would deny the login path outright — measured on main:
- Blocker F: core-java-allow admits 9090 only from frontend/edge-go pods and two namespaces that do not exist; NOT
  from the ingress controller (so every browser API call to api-staging and the SSE stream is dropped) and NOT on
  9091 (so the Prometheus scrape is dropped).
- Blocker D: the Postgres egress rule targets a jtoye-infrastructure namespace; a public-access Flexible Server is a
  public IP on db.port, which the 443-only public rule denies. Redis/RabbitMQ/Keycloak/Mailpit will live in
  jtoye-staging itself (plans 29-10, 29-22), not in any infrastructure namespace.
- D-29(c): frontend-allow and edge-go-allow name the ingress-nginx namespace; the controller of record is Traefik in
  namespace traefik.

This plan rewrites the base policies for the real topology, keeps the #271 single-port Postgres rule at index 1, makes
the controller namespace config-driven the way #271 made db.port config-driven (local keeps ingress-nginx because its
minikube addon lives there — the displaced good, a local render that names its own controller, is preserved), adds the
ACME solver policy cert-manager needs under default-deny, and rewrites INV-7 so the whole allow-list is asserted
exactly rather than one namespace's port set.

Purpose: DPLY-05 (policies that are correct under enforcement, asserted statically before the live denial capture in
plan 29-17); DPLY-01 (the login path is admitted); DPLY-02 #271 (the mechanism extended, not reopened).
Output: rewritten 10/20/30/40 policies, new 60-acme-http01-solver.yaml, config-driven controller namespace,
INV-7 rewrite, regenerated goldens.
</objective>
