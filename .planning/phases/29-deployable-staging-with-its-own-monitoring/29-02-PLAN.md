<objective>
Fix the three staging-overlay defects that are individually invisible to every gate that exists
today, and wire the one-click unsubscribe header that has zero references under `k8s/`.

- **Blocker A** — `k8s/base/configmap.yaml:212` sets `keycloak.client-id: "frontend"`, and the realm
  template has NO client named `frontend` (measured: the complete client list is `account`,
  `account-console`, `admin-cli`, `broker`, `core-api`, `edge-api`, `realm-management`,
  `security-admin-console`, `integration-catalog-ro`, `integration-orders-rw`). The base file
  *says so in as many words*. Only `k8s/local` patches it. Staging inherits the broken value, and
  DPLY-01's login dies at the authorize request. No gate sees this: the render is valid, the key
  exists, the value is a non-empty string.
- **Pitfall 6** — `k8s/staging/kustomization.yaml` declares `replicas: 2`, but the kustomize
  `replicas:` transformer does not touch HPA or PDB. The base HPAs carry `minReplicas` 3/5/3, so
  staging schedules 11 app pods, not 6 — ~2.6 vCPU / ~4.1 GiB of requests before a single platform
  service. Nothing inside the £150 ceiling fits that. Phase 26 measured this and built
  `k8s/local/scale-patch.yaml`; staging has no equivalent.
- **Pitfall 7** — Azure Cache for Redis Basic disables the plaintext 6379 port and serves TLS on
  6380. `application.yml`'s `spring.data.redis` block has host/port/password/timeout/pool and **no
  `ssl:` block**. `check-env-contract.sh` is blind to a capability absent from BOTH sides.
- **#592** — `notification.unsubscribe.one-click-base-url` has zero references under `k8s/`, so
  `List-Unsubscribe` degrades to RFC 2369 in every deployed environment. The issue's own text
  demands the fail-direction arm first.

Purpose: DPLY-01 cannot be attempted until the login client is real and the pods can schedule.
Output: a staging overlay that is capable of a successful login and a Redis-TLS connection.

Branch: `phase-29-research`. Never commit to main.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
