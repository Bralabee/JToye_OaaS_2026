<objective>
Create the estate, and prove each piece by reading the fact off the running thing rather than off the
command that was supposed to create it.

This plan RUNS what plan 29-05 wrote. It carries three measurements the research could not make and
that everything downstream depends on:

- **Blocker C, closed by version choice.** `infra/backups/create-backup-role.sql` runs
  `CREATE ROLE jtoye_backup LOGIN BYPASSRLS`, and on Azure Flexible Server the admin login is
  `azure_pg_admin`, a pseudo-superuser. Microsoft documents that on **PostgreSQL 15 and earlier you
  cannot create non-admin users with BYPASSRLS**, and that **PostgreSQL 16 removed the superuser
  requirement**. Without `jtoye_backup`, the logical dump runs as a FORCE-RLS-subject role and
  captures **zero rows from every tenant-scoped table** — which is DPLY-04's arm A shape exactly.
  So the server is version 16, and the proof is `rolbypassrls = t` read out of `pg_roles`, not the
  fact that a `CREATE ROLE` command exited 0.
- **Assumption A2, unmeasured.** Node allocatable (~1.9 vCPU / ~2.4 GiB per B2s after kubelet and
  system reservations) is REASONED in the research, not measured, and the whole pool sizing rests on
  it. Measure `kubectl describe node` on the first node and re-derive before accepting the count.
- **`azure.extensions`.** `V1__base_schema.sql:6` runs `CREATE EXTENSION IF NOT EXISTS "uuid-ossp"`
  and it is the sole exemption in `scripts/check-no-create-extension.sh`. It must be on the server's
  allowlist BEFORE the first Flyway run, or V1 fails and nothing else runs. The live `snackpass-pg`
  reads `vector,pgcrypto` — do not copy that value.

Purpose: everything from plan 29-11 onward needs a real cluster, a real database and real DNS.
Output: a provisioned estate and a dated evidence record of what was measured, not what was intended.

Branch: `phase-29-research`. Never commit to main.
