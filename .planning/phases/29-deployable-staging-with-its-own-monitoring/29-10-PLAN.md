<objective>
Tracer slice, in-cluster platform layer of the DPLY-01 path: the three services the login path needs that run inside the
cluster — Keycloak (D-02), Redis (D-24 resolved by measurement to in-cluster), RabbitMQ via the operator (D-09) — as
kustomize Components that only the staging overlay includes.

Why Components, not k8s/base: the local overlay reaches Keycloak/Redis/RabbitMQ on the host compose stack and minikube has
no RabbitMQ operator CRDs; production opts in deliberately in Phase 32 rather than inheriting a half-configured platform
render now. Components at k8s/components/<name>/ sit at depth 3, so the depth-2 target discovery of the render gates does
not treat them as targets, while every gate still sees them inside the staging render.

The auth host returns under the exact rule k8s/base/ingress.yaml wrote for this moment: the host rule and its TLS come back
together with the Service and Deployment, never before (INV-6 enforces the order).
Output: three components, the copy-parity gate (generalising the branch's alert-corpus gate; plan 29-23 adds the alert and
dashboard pairs), INV-7 rows, horizon updates, regenerated staging golden.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → auth-staging (Keycloak via Traefik) | login, token and account endpoints are public |
| core-java ↔ Redis / RabbitMQ inside jtoye-staging | cache data and messages, plaintext on the pod network |
| Keycloak → managed Postgres | identity data leaves the cluster |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-35 | Elevation of privilege | Keycloak admin console | high | mitigate | Public Ingress routes only /realms/ and /resources/ (render-asserted); admin only via port-forward (plan 29-04) |
| T-29-36 | Tampering | theme drift | low | mitigate | Byte-parity gate in CI over every committed copy |
| T-29-37 | Information disclosure | Redis/RabbitMQ plaintext in-cluster | low | accept | Staging holds no real customer data; NetworkPolicies admit only core-java and the exporters; Phase 32 decides production transport |
| T-29-38 | Spoofing | broker default user | medium | mitigate | Default user from rabbitmq-default-user (Key Vault, plan 29-12), never operator-generated defaults or a committed value |
| T-29-39 | Denial of service | Keycloak start on burstable nodes | low | accept | Generous startupProbe; measured in plan 29-14; node SKU is the D-03 cost trade |
| T-29-SC | Tampering | npm/pip/cargo installs | high | accept | None; images pinned by tag with existing horizon rows (Keycloak, Redis) or the updated rabbitmq-k8s row |
