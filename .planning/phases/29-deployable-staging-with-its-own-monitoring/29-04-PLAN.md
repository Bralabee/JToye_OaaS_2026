<objective>
Tracer slice, layer 4 of the DPLY-01 path: a realm a public host can safely serve. Blocker H measured the template as
dev-shaped — realm jtoye-dev, core-api redirect URIs all localhost/app.jtoye.local, webOrigins "*", four seed users sharing
one templated password, SMTP to mailhog without TLS. D-27 requires that no git-committed credential can sign in to a
public host, so the seed users must not exist in staging at all.

Design choice (recorded): the staging realm is imported by an operator-run script through a port-forward, not by
`--import-realm` inside the pod. Reasons: (1) the templates live outside k8s/, and kustomize's load restrictor forbids
reading them, so an in-pod import would need a second committed copy; (2) the customer template is not valid JSON until
its fragment placeholders are substituted (`[ ${CUSTOMER_STOREFRONT_REDIRECT_URIS} ]`, an unquoted boolean), and Keycloak's
own env placeholder resolution says nothing about unset variables or coexistence with its i18n `${...}` tokens
(keycloak.org importExport, fetched 2026-10-18) — the compose stack protects i18n tokens with an explicit envsubst list for
the same reason; (3) the proof that matters is what Keycloak HOLDS, read back from its admin API, not what a file says.
Keycloak is Postgres-backed, so an imported realm persists across pod restarts.

Purpose: DPLY-01 (a realm the login can use), DPLY-02 (#299 customer realm imported; #296 hardening: the admin console is
never exposed on the public host).
Output: infra/keycloak/staging-realm.jq, scripts/staging-realm-import.sh, a corrected infra/keycloak/README.md.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → auth-staging (public realm endpoints) | anyone can reach the login page and token endpoint |
| operator host → Keycloak admin API (port-forward) | the realm is written through a cluster-internal path |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-12 | Spoofing | dev seed users in a public realm | critical | mitigate | Transform strips every non service-account user; assertion suite refuses a realm with any; re-asserted against the live realm after import |
| T-29-13 | Spoofing | redirect/webOrigins wildcards | high | mitigate | core-api URIs exact to app-staging; no `*` webOrigins in any client; assertion-enforced |
| T-29-14 | Elevation of privilege | Keycloak admin console on the public host | high | mitigate | Admin calls only via port-forward; the public Ingress (plan 29-10) routes /realms/ and /resources/ only |
