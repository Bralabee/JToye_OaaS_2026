<objective>
Put Prometheus and the two exporters in Kubernetes, reproducing the compose scrape corpus so
exactly that `check-alert-liveness.sh` and `check-alert-metrics.sh` need no knowledge of which
runtime they are pointed at.

DPLY-03 fails on the current tree by construction: `k8s/` ships **zero** monitoring manifests. The
entire stack lives in `infra/monitoring/docker-compose.monitoring.yml`, recorded in Phase 27's
`deferred-items.md` §5 — everything Phase 27 built is compose-scoped, so a staging deploy today is
wholly unmonitored.

The hard part is not the Deployments. It is that `check-alert-liveness.sh` maps rules to jobs
through three hard-coded data blocks and **VOIDs on any job it does not recognise**. Rename a job
and the gate VOIDs; keep the names and the gate runs unchanged. So this plan changes the target
ADDRESS and nothing else.

D-16 says one rule corpus, mounted verbatim. kustomize cannot read a `configMapGenerator` file from
outside its own root, so "one corpus" becomes a committed copy plus a **byte-equality gate** — the
invariant made executable rather than hoped for.

Purpose: DPLY-03's two gate scripts have to have something real to point at.
Output: a scraping Prometheus in the base render, plus the parity gate that keeps the corpus single.

Branch: `phase-29-research`. Never commit to main.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Prometheus -> scraped workloads | Metrics endpoints, some of which expose internal detail |
| exporters -> managed Postgres / Redis | Credentialed connections leaving the cluster |
| anyone in-cluster -> Prometheus | Prometheus has no authentication of its own |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-06-01 | Information Disclosure | A publicly reachable Prometheus | mitigate | ClusterIP Service and NO Ingress; asserted at zero Ingress documents in the monitoring render, and made a standing invariant in plan 29-07 |
| T-29-06-02 | Information Disclosure | Exporter DSNs carrying credentials as literals | mitigate | Every credential-bearing env is `valueFrom` a Secret; INV-2 and check-no-plaintext-secrets both assert it, with a scratch-Secret arm proving the gate fires |
