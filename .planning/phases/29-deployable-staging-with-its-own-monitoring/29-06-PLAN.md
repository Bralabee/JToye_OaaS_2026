<objective>
Tracer slice, seed layer of the DPLY-01 path. DPLY-01 requires "real seeded rows", and D-26 requires that every row be made
the way a first tenant's would be — so the seed doubles as a smoke test of the onboarding paths Phase 32 needs. D-27
requires the login to use a staging-only test vendor whose credential lives only in Key Vault.

The tenant-creation path is measured, not assumed (RESEARCH Open Question 2): POST /api/v1/admin/tenants is
`@PreAuthorize("hasRole('admin')")`, the realm has registrationAllowed false, and access.strict-scoping is "true", so the
first JIT user becomes the bootstrap GROUP_ADMIN. J'Toye has no platform-operator identity (recorded architecture), so the
script creates a short-lived realm user holding the realm `admin` role for the duration of one run and deletes it on exit.

This plan writes and offline-tests the vendor stage. It runs live in plan 29-14 (the tracer). The order stage, which needs
Stripe TEST settlement (D-31), is added by plan 29-18.
Output: scripts/staging-seed.sh.
