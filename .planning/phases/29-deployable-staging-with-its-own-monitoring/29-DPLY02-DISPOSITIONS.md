# Phase 29 — DPLY-02 dispositions

DPLY-02: "the deploy knot closed or explicitly deferred with a reason recorded per issue". Silence is the defect.

This table is the record plan 29-28 acts on, after the owner approves it by quoting the sha256 of
`evidence/29-27-approval.sha256`. The required list is not typed here: `scripts/check-dply02-dispositions.sh` derives it
from the `#N` references in the ROADMAP's Phase 29 section, unions `#101 #296 #297 #859`, prints the list and its count,
and holds this table to exact set equality with it (no missing row, no extra row). Run it with no argument to check.

How to read a row:

- **State at phase start** is the live state re-read 2026-10-20 (the research measured the same on 2026-10-18); plan 29-28
  re-reads it with `--pre-close` and stops on any drift. The only row that differs from the 2026-10-18 measurement is #100.
- **Disposition** is one of `fixed-in-phase`, `already-closed`, `deferred: <reason>`, `superseded: <reason>`,
  `pr-reference`. Anything after the colon on a `fixed-in-phase` row is scope the owner should see; on `deferred` and
  `superseded` rows it is the written reason and must not be empty.
- **Evidence** is one or more `path:line` entries; the gate checks the path exists and the line lies inside the file.
  `evidence/29-27-measurements.txt` carries the measurements no earlier plan's evidence file does, each absence paired with a
  control that hits.
- **Comment file** is the exact text plan 29-28 posts on the issue (for #99 a placeholder token, `RUN_URL`, is substituted into a
  temporary copy; the committed file never changes). `pr-reference` rows are merged PRs the ROADMAP section cites for
  ADR-0002's Accepted status: no comment, no state change, ever.
- **Expected state after 29-28** is what `--post-close` checks. A deferral leaves the issue OPEN.
