<objective>
DPLY-05: NetworkPolicies **enforced, not merely rendered** — with a denied connection captured as the
positive proof.

Phase 26 recorded enforcement explicitly **NOT PROVEN**, and the ROADMAP says that record must not be
quietly inherited as a pass. #297's original scope was installing Calico on local minikube; D-01
satisfies the intent differently, on AKS, with enforcement enabled at cluster level — so #297 is
close-or-retarget with a reason, not silently satisfied.

The instrument was built in plan 29-03 and shown able to produce 0, 1 and 2. This plan runs it
against the real cluster, and the ordering is the entire discipline:

**The control arm runs FIRST.** A probe that cannot connect to anything reads as a perfect security
posture. On this project that failure class has a name and a count — roughly fifteen instrument
defects to zero product defects in one session — and the rule that came out of it is that a negative
finding is a hypothesis about your tooling until a positive control says otherwise. A bad control arm
is worse than none.

Layer on the Cilium-specific hazard the research found: `ipBlock` **cannot select pod or node IPs**,
and Microsoft's FAQ states that even `cidr: 0.0.0.0/0` still blocks them. So a policy can look
tighter than it is, or block traffic it appears to permit, and only a live probe distinguishes them.

Purpose: this is DPLY-05.
Output: a captured denial, a proven-working control, and a gate wired where a runtime exists.

Branch: `phase-29-research`. Never commit to main.
</objective>

<!-- The two arms, from Microsoft's own verification recipe. -->

Image: k8s.gcr.io/e2e-test-images/agnhost:2.33
Probe:  /agnhost connect <ip>:<port> --timeout=3s --protocol=tcp
Output: the literal string TIMEOUT when DENIED · NOTHING AT ALL when ALLOWED.
        Silence is the success signal, which is why the control arm has to run first — a probe that
        never runs is also silent.

The arms for this phase (research Blocker D):
  ALLOWED arm: a probe pod carrying the app=core-java labels connects to the managed Postgres
               FQDN:5432 and SUCCEEDS (silence).
  DENIED arm:  the SAME probe image from an UNLABELLED pod, or to a port outside the allow-list,
               returns TIMEOUT.
  CONTROL:     run the denied arm's shape where NOTHING should block it (a permitted target from a
               permitted pod) and confirm it SUCCEEDS — proving the probe can connect at all.

⚠ The only kube context on this host is sipbihs2aks — EMPLOYER infrastructure. Every kubectl passes
--context explicitly.

⚠ agnhost is a minimal image. Assert on the tool's own exit code and output, not through a piped
filter inside the pod: a missing grep/sed/awk inside a minimal image has already broken a
verification on this project AFTER the mutation succeeded.

⚠ Never `cmd | grep -q X` under `set -o pipefail` — grep exits at the first hit, the writer takes
SIGPIPE, pipefail promotes it to 141, and the guard fails OPEN. Use a here-string.

Wiring: check-gate-enforcement.sh is DEFAULT-DENY. From plan 29-15 the deploy-staging job has cluster
access via the Azure OIDC federated credential, so WIRING beats exempting — the conf's own note
records that as the intended direction of travel.
