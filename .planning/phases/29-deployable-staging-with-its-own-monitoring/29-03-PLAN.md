authoritative; the live fidelity probe in plan 29-15 decides.

<assumption_delta_decision>
Noun now primary: the INGRESS CONTROLLER is Traefik v3 with its Ingress-NGINX provider; the IngressClass name stays
`nginx` and the nginx.ingress.kubernetes.io/* annotations stay the configuration source of truth (D-29).
Decision: add-alongside. Rationale: the provider's defaults are ingressClass "nginx" / controllerClass
"k8s.io/ingress-nginx", so keeping the existing class and annotations means no manifest outside k8s/platform changes and
the retired controller's vocabulary keeps working on a maintained implementation. (PATTERNS.md suggested
`ingressClassName traefik`; not adopted — it would require reconfiguring the provider and buys nothing.)
Accepted debt: annotation semantics are now an emulation — an annotation the provider does not implement is not
guaranteed to be rejected (the docs state only that load-balance is silently ignored), and partial ones (enable-cors)
may behave differently. Paid down by: supported-annotations.txt + the render invariant in plan 29-08 (an unsupported
annotation fails CI), and the live fidelity probes in plan 29-15 (headers, CORS preflight, 429 on burst, each shown
failing first).
</assumption_delta_decision>
