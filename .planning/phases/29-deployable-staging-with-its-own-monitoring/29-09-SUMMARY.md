## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The AKS and Key Vault read-backs compared against `True`**
- **Found during:** Task 2, live run 1. The cluster had already been created.
- **Issue:** azure-cli 2.91.0 prints tsv booleans as `true`. The script refused a correctly created cluster with `REFUSED [aks] … 'overlay cilium cilium 10.244.0.0/16 true true true true true'`. This is the tsv-layout open item that 29-01 recorded.
- **Fix:** both read-backs lower-case the value before comparing, as the storage script already did.
  - Fake-az arms that pass: lower-case booleans, capitalised booleans.
  - Arms that refuse: policy `azure`, local accounts on, purge protection off, access-policy mode.
- **Files modified:** scripts/azure-staging-provision.sh
- **Commit:** c5aed4ab

**2. [Rule 1 - Bug] The quota check refused every re-run once the cluster existed**
- **Found during:** Task 2, live run 2.
- **Issue:** the script demanded 8 free vCPU, while the cluster's own 6 vCPU were already in use: `standardBSFamily has 4 free vCPU`.
- **Fix:** when `jtoye-stg-aks` exists, only the surge node (2 vCPU) must fit. The aks stage still asserts every one-way property.
  - Arms: absent cluster with 4 free refuses. Absent with 10 free passes. Present with 4 free passes. Present with 0 free refuses.
  - The dry-run made 57 of 57 calls pinned.
- **Commit:** edc118f0

**3. [Rule 1 - Bug] The custom role's apostrophe broke az's OData name filter**
- **Found during:** Task 3, storage run 1, at runbook §6.
- **Issue:** the run failed with `UnsupportedFilter … roleName eq 'J'Toye Backup Blob Writer'`. The OData escape `J''Toye` was measured live and refused the same way.
- **Fix:** the role is counted and its id read with a client-side JMESPath filter (`J\'Toye`). It is then assigned by definition id, which `_resolve_role_id` uses without any name lookup. A bounded wait covers a role that does not list yet.
  - Live control: the filter counted 0 for the role and 1 for `Storage Blob Data Contributor`.
  - The dry-run made 19 of 19 calls pinned. The pin gate reports `findings=0`.
- **Commit:** e3b32c79

**Total deviations:** 3 auto-fixed bugs, all inside the plan's own scripts. Each script is re-runnable, and re-runs read existing resources back instead of recreating them (shown live: runs 2 and 3, and storage run 2).
