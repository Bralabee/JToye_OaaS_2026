<objective>
Tracer slice, datastore layer of the DPLY-01 path (and the PITR substrate DPLY-04 drills): scripted, guarded, dry-run-proven
creation of the managed Postgres and the two Blob accounts, plus the role bootstrap a FRESH managed database needs.

Blocker E is the reason the bootstrap is ordered: k8s never wired the Phase 28 runtime/migrator split, and on a fresh
database DatabaseConfigurationValidator refuses a DB user that owns any public table while Flyway as the DML-only runtime
role cannot migrate. So the owner (jtoye_app) and the runtime role (with default privileges granted FOR ROLE jtoye_app) must
exist before the first boot; create-runtime-role.sql cannot simply run first because its `GRANT TRUNCATE ON
postcode_centroid` fails on an empty database (V61 creates that table). The post stage re-runs the two existing,
idempotent role files unchanged after the first migration.

D-25: PostgreSQL 18 (highest Azure-supported major ≤ 18, = dev 18.6; ≥ 16 is required for an azure_pg_admin-created
BYPASSRLS role). D-10: jtoye_backup BYPASSRLS on the managed server. Phase 36: Blob via Workload Identity, keys nowhere.
Output: three scripts and one SQL file; nothing is created until plan 29-09 runs them.
</objective>
