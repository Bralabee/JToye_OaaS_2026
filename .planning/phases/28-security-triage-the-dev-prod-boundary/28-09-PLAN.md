<objective>
Close #270 and the exposure RESEARCH found while measuring #488 (DEC-5, filed by plan 28-03): the
MinIO bootstrap runs an unpinned `minio/mc` holding root object-storage credentials, and the bucket
policy it applies grants anonymous `s3:ListBucket` alongside `s3:GetObject`.

Purpose: `mc anonymous set download local/jtoye-images` is a two-privilege shortcut. Verified live,
`curl "http://localhost:9000/jtoye-images?list-type=2&max-keys=1000"` returns 200 with a KeyCount of
768 and NO credential — the entire object inventory is enumerable by anyone who can reach the port.
`MediaProperties`' own javadoc already records the READ half of this ("a quarantine object is
anonymously readable by key"); the LIST half means an attacker does not need the key. That is why
D-06's "non-public quarantine prefix" is not achievable by a naming convention, and why this is
worth fixing now rather than deferring with the sweep.

Both changes live in the same compose bootstrap block, so they ship together.

Output: a digest pin reviewable as one line in `.env`, an anonymous policy that keeps the storefront
working and stops the enumeration, and both proven in both directions against the running stack.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous internet -> the object store | the bucket is deliberately anonymously READABLE; it was accidentally anonymously LISTABLE |
| a mutable public image tag -> a container holding root object-storage credentials | whatever `latest` resolves to next runs with full bucket authority |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-44 | Tampering (supply chain) | `minio/mc:latest` executing with root object-storage credentials (#270) | mitigate | digest pin via `MINIO_MC_IMAGE_TAG`, resolved image ID echoed by the bootstrap, and a wrong-digest arm proving the pin fails loud instead of degrading to `latest` |
| T-28-45 | Information Disclosure | anonymous `s3:ListBucket` exposing the entire object inventory (DEC-5) | mitigate | explicit GetObject-only anonymous policy; before/after status codes recorded on the same request |
| T-28-46 | Information Disclosure | a quarantine prefix assumed private because of its name | mitigate | the bucket-wide grant is the reason a prefix cannot be private by convention; this fix is the precondition D-06's deferred sweep depends on, and the dated plan from 28-03 says so |
| T-28-47 | Denial of Service (regression by omission) | storefront images silently 404/403 after the policy change | mitigate | anonymous GET measured on the SAME real key before and after, asserting 200 and a non-zero body — no existing test covers this path |

| T-28-49 | Repudiation | a policy change asserted from the compose file rather than the running service | mitigate | the effective policy is read back from the running MinIO, and the read-back is itself proven to differ before and after |
