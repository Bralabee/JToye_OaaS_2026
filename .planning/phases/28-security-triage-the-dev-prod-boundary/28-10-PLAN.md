**Two services ignore a config-only rotation, and both fail in the direction that looks like
success.** Grafana applies `GF_SECURITY_ADMIN_PASSWORD` ONLY when it first creates the admin user,
so editing the compose file changes nothing and the login that still works is the OLD password.

`kc.sh import --override true` plus a restart. In both cases every file is edited, the stack comes
up healthy, and nothing rotated. That is why #552's acceptance shape is not "the new value works" —
it is **the superseded value FAILS and the current value SUCCEEDS, in the same run**.

Output: the owner's confirmation on record, six rotated credentials each with a two-direction arm,
one Keycloak import carrying both payloads, and a runbook Phase 29 can follow.
