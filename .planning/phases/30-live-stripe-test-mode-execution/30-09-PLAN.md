<objective>
D-02: clear the abandoned staging card orders and their payable TEST intents by hand.

**Re-routed 2026-10-24/25 (issue #1038).** Plan 30-08 found the targets gone. `ScheduledCleanupService` deletes DRAFTs
older than 24 h at 03:00Z and, until the issue #1038 fix, never touched their intents. So the 2026-10-19 swarm DRAFTs and plan

cancels a card DRAFT's intent before deleting the order. The listing runs after that deploy, so anything it finds is
history, not a live leak.

Stripe TEST mode only (D-06): every evidence object that carries livemode reads false.
Output: scripts/staging-seed.sh (two stages + selftest arms) and evidence/30-09-d02-drafts.txt.

    Add two stages that reuse the existing helpers. Both refuse anything not in TEST mode.

    **`list-orphan-intents`** (read-only):
    - Pages `GET /v1/payment_intents?limit=100` (follow `has_more`/`starting_after`).
    - Keeps intents in requires_payment_method|requires_confirmation|requires_action that carry a `metadata.order_number`.
    - Reads the vendor's orders across ALL eight statuses (`orders_in_status` per status).
    - Prints `ORPHAN-INTENT intent=… order_number=… status=… created=… amount=…p`, with no customer field, for each intent whose order_number is absent.
    - Prints a control line `VENDOR-ORDERS total=N` and then `LIST-ORPHANS count=… at=…`.
    - VOIDs (rc 2) when the vendor read returns 0 orders across all statuses, because an empty read can be blindness (the `Page.empty` no-grant path).

    **`cancel-orphan-intents --intents pi_a,pi_b`**: the argument is validated like `--orders` (no empty entries, no duplicates). For each intent in its own errexit subshell:
    - GET it and assert test mode.
    - Refuse [paid] if succeeded|processing|requires_capture.
    - Refuse [not-orphan-candidate] if there is no metadata.order_number.
    - Re-read the vendor's orders across all statuses and refuse [order-exists] if the order_number is present (that order's route is cancel-drafts).
    - Skip the write if the intent is already canceled.
    - Otherwise `POST /v1/payment_intents/{pi}/cancel` with cancellation_reason=abandoned and Idempotency-Key `d02-orphan-cancel-{pi}`.
    - Read it back: it must be canceled with livemode false.
    - Print `SEED-ORPHAN-CANCEL intent=… order_number=… intent_status=canceled livemode=false at=…`.
    - Last, print `CANCEL-ORPHANS requested=… cancelled=… refused=…`, with rc 1 if anything was refused.

    Extend the dry-run plan text, the USAGE block, the stage-flag checks (`--intents` is accepted only by this stage) and the --selftest stubs.
  </action>
