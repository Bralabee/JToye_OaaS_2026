<objective>
Update Go edge gateway routes and Next.js frontend API calls to use /api/v1/ paths, completing the end-to-end API versioning migration started in Phase 1.

Purpose: Phase 1 added /api/v1/ prefix to Spring Boot endpoints. Without updating the Go edge and frontend callers, all API calls return 404. This plan completes the coordinated multi-service migration.
Output: Working end-to-end request flow from browser -> Go edge -> Spring Boot using /api/v1/ paths.
</objective>

<threat_model>
## Threat Model (ASVS Level 1)

| Threat | Severity | Mitigation |
|--------|----------|------------|
| Old paths remain accessible without auth after prefix change | LOW | Spring Boot SecurityConfig already covers /api/v1/** via anyRequest().authenticated(). Old unprefixed paths return 404 (no backward compat redirects per D-04). |
| Edge gateway forwards to wrong path, bypassing auth | MEDIUM | Path changes are mechanical string replacements in edge code. Go unit tests verify correct paths. No new auth surfaces introduced. |
| Public storefront paths accidentally prefixed with /api/v1/ | LOW | Public paths (/public/**) use publicApiClient which is NOT modified in this plan. Only apiClient calls in dashboard pages are updated. |

No HIGH severity threats. All changes are path string updates with no new authentication, authorization, or data handling logic.
</threat_model>
