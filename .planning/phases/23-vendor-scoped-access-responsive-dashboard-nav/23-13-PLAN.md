<objective>
Close CR-08 — the frontend's GROUP_ADMIN detection disagrees with the backend's authority model,
making "All shops" unreachable for most admins and silently pinning every non-realm-admin to
their first shop. Fold in WR-06 (two switcher instances hold independent state), WR-12 (staff
screen joins identity by email instead of `sub`), IN-02 (wrong 409 copy on the grant path) and
the misleading revocation-timing copy noted in plan 23-11.

Purpose: `isGroupAdminFromSession()` derives GROUP_ADMIN **solely** from the Keycloak realm
`admin` role in the access token. The backend's model is broader: a GROUP_ADMIN is anyone
holding a `NULL`-shop `GROUP_ADMIN` row — which under the default `strict-scoping = false` is
every JIT-provisioned user. Realm `admin` is only the *bridge*, not the definition.

The consequence is a regression, not just a missing affordance:
`shop-switcher.tsx:44-45` computes `fallback = ga || fetched.length === 0 ? ALL_SHOPS_CONTEXT :
fetched[0].id`, and line 57 **persists it**. With `ga === false` and a non-empty shop list, the
default day-one user is silently pinned to their first shop on first load — the dashboard
narrows from "all shops" to one shop with no user action — and line 130 renders the
`All shops` option only when `isGroupAdmin`, so they cannot select it back. This is exactly the
regression-by-omission the Incremental Betterment Doctrine names as a defect: a working
cross-shop view removed by default, with a passing test suite.

Output: a switcher whose authority model matches the server's, and a staff screen that
identifies people and describes its own behaviour accurately.

**Scope discipline:** VSA-03 otherwise PASSES verification and was live browser-verified in
23-05. Do not rework the switcher's layout, styling, mobile placement, or the 375px behaviour
that MOBL-01 depends on. This plan changes where the authority answer comes from and where the
selection state lives — nothing else.
</objective>
