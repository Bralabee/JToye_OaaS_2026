<objective>
Fix a CONFIRMED deployment blocker in migration V57 found by the phase-23 gap-closure code review.

V57's grant_source backfill (lines 46-48) is a bare `UPDATE shop_staff SET grant_source = ... WHERE grant_source IS NULL;`
with no tenant GUC. `shop_staff` is ENABLE+FORCE ROW LEVEL SECURITY (V52) with policy `USING (tenant_id = current_tenant_id())`.
Flyway runs as the RLS-bound app role (`jtoye_app`; there is NO `spring.flyway.user` override), so during the migration
`current_tenant_id()` returns NULL → the policy hides every row → the backfill updates ZERO rows. Then line 64
`ALTER COLUMN grant_source SET NOT NULL` FAILS on any database that already holds `shop_staff` rows (the pre-V57 `DEFAULT 'JIT'`
on line 63 only affects future inserts, not existing rows).

Impact: V57 bricks boot on the canonical Compose dev DB and any staging/prod where V52 shipped and a user has since made a
write request (creating a JIT `shop_staff` row). Testcontainers never catches it because every test DB is fresh — V52 and V57
run back-to-back on an empty table, so there is nothing to backfill and `SET NOT NULL` passes trivially.

This is the exact defect class this repo's V44 header documents ("V25's backfill UPDATE ran as the RLS-bound migration role with
NO tenant GUC set, so under FORCE RLS it saw zero rows and silently no-opped ... must not be repeated"). V44 fixes it with a
tenant-loop `set_config` pattern. V57 must adopt the same pattern.

Output: V57 backfills every pre-existing row under RLS enforcement, applies cleanly on a non-fresh DB, and carries a regression
test that proves it on the exact scenario Testcontainers otherwise misses.
</objective>

<the_fix>
Replace V57 step 2 (the bare `UPDATE`, lines 46-48) with a tenant-loop DO block that mirrors V44:26-125 exactly in idiom —
walk `tenants` (no RLS), set the standard app GUC transaction-locally per tenant, UPDATE that tenant's rows WITH the policy
enforced, then defensively reset the GUC. Preserve the `created_by IS NULL → 'JIT' ELSE 'OPERATOR'` CASE verbatim, and keep the
idempotent `WHERE grant_source IS NULL` guard:

```sql
DO $$
DECLARE
    t          RECORD;
    n          BIGINT;
    backfilled BIGINT := 0;
BEGIN
    FOR t IN SELECT id FROM tenants LOOP
        PERFORM set_config('app.current_tenant_id', t.id::text, true);   -- transaction-local, like TenantSetLocalAspect
        UPDATE shop_staff
           SET grant_source = CASE WHEN created_by IS NULL THEN 'JIT' ELSE 'OPERATOR' END
         WHERE tenant_id = t.id
           AND grant_source IS NULL;
        GET DIAGNOSTICS n = ROW_COUNT;
        backfilled := backfilled + n;
    END LOOP;
    PERFORM set_config('app.current_tenant_id', '', true);               -- defensive reset
    RAISE NOTICE 'V57: backfilled grant_source on % pre-V57 shop_staff row(s).', backfilled;
END $$;
```

Update the step-2 comment block to explain the RLS-safety (cite V44/V25 the way V57's other comments cite V51/V52). Do NOT touch
steps 1, 3, 4 (the ADD COLUMN, the CHECK/DEFAULT/NOT NULL, the _aud mirror) — only step 2 changes.
