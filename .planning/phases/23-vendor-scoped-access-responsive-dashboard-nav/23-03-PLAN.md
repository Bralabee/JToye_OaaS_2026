<objective>
Insert the `ShopAccessService` gate at the top of every shop-scoped service method per the
RESEARCH §3 enforcement inventory (the deliverable). Writes get `require(shopId, minRole)`
(deny-by-default); reads get grant-set filtering (D-01: genuinely narrow lists server-side).
Resolve both §3-FLAG endpoints explicitly: bulk product import does a per-CSV-row
`require(rowShopId, SHOP_MANAGER)` (deny the batch if any row is ungranted), and the KDS SSE
order stream filters its in-memory fan-out to the caller's granted shops. Prove it under
Testcontainers: cross-shop write → typed 403 (distinct from the RLS 404), STAFF read-only,
read-scope narrowing.

Purpose: This is the behaviour the phase exists to introduce — a SHOP_MANAGER scoped to one
shop, STAFF to operational-read + order-state-only, and every list narrowed to grants. RLS
stays the tenant wall; this gate sits strictly inside it.

Output: `require()`/read-scope inserts across Shop/Product/Order/Promotion/Announcement services
+ the two FLAG mitigations + `ShopAccessEnforcementIntegrationTest`. Out-of-scope controllers
(public storefront, customer, admin-gated, webhook/sync) are NOT touched.
</objective>

ShopAccessService (@Service):
  - void require(UUID shopId, ShopRole minRole)   // throws ShopAccessDeniedException (typed 403) below minRole
  - void requireGroupAdmin()
  - boolean isGroupAdmin()
  - Set<UUID> grantedShopIds()                    // read-scope filter source

ShopRole: GROUP_ADMIN > SHOP_MANAGER > STAFF.

Read-scope pattern: in a list/search service method, `if (shopAccessService.isGroupAdmin()) { existing query }
else { filter by shopAccessService.grantedShopIds() via a repo finder e.g. findByTenantIdAndShopIdIn(...) }`.
