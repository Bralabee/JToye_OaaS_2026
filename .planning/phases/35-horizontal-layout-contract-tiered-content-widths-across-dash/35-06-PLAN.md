<objective>
Bring the landing page's content bands up to the Marketing tier so the page agrees with the chrome
already wrapped around it, and declare that tier on both shared public rails.

The defect, measured in PATTERNS.md F-2: `app/page.tsx` renders its four content bands at 1152px
(`max-w-6xl`) while `components/public/public-header.tsx:79` and `public-footer.tsx:83` render their
rails at 1280px (`max-w-7xl`). **The landing content is inset 128px from its own header rail** — the
nav and the hero do not share a left edge. This is user decision D-04, and it is the argument for the
change: moving `/` to the Marketing tier does not invent a number, it makes the landing page agree
with the chrome around it and with its three sibling marketing routes, all of which are already at
1280. That is an additive alignment, not a re-layout.

Purpose: `/` is the ONE surface in this phase whose width value actually changes (1152 to 1280). It
is also the most-measured route in the repo — CLS, LCP, bundle size, motion and overflow assertions
all point at it. So it gets its own plan with its own regression arms rather than riding along with
surfaces where nothing moves.

Output: four landing bands and two chrome rails declaring the Marketing tier, with the existing
mounted tests extended and the landing's measured baselines re-run.
</objective>

The Marketing tier value is 1280px, which is EXACTLY the value the stock scale token on the two
chrome rails already produces. So the rail edits are a byte-identical rename: same rendered width,
newly declared. The landing edits are a real change: 1152 to 1280, plus 128px.

THE FOUR LANDING BAND SITES, measured — each is an existing element already carrying an auto margin,
the narrower stock token and horizontal padding:
  app/page.tsx  ~187  hero band
  app/page.tsx  ~276  the kitchen row (near-you) band
  app/page.tsx  ~292  how-it-works band
  app/page.tsx  ~318  trust-strip band

Do NOT touch the hero sub-paragraph measure inside the hero band, nor the landing search form's own
width. Those are typographic measures and a control, not page bands (PATTERNS 1c), and the search
form is explicitly CLS-sensitive.

APPLICATION SHAPE — in place on each existing band element. Swap the narrower token for the marketing
utility from WIDTH_TIER_CLASS and add the tier attribute. Keep the auto margin and every padding
class. Add NO wrapper node: this page is dense with scroll-reveal and motion hooks, and a new DOM
node between a section and its band is exactly the kind of change that moves a boundingBox assertion
for no reason.
</interfaces>
