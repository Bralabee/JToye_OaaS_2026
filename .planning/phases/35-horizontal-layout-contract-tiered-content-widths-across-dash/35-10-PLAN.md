<gate_assertions>
Six assertions. Each names the defect it catches, because a gate whose purpose is not written down is
the next thing someone deletes.

G-1 SCATTERED LITERALS. The three tier class literals appear in exactly one source file, the tier
    component. Catches: a developer typing the class directly onto an element, which works today and
    breaks silently the moment a tier value changes.

G-2 THE RETIRED SCAFFOLD CLASS. The shadcn container class appears in no class context under the
    frontend's app and components trees. Catches: the 1400px default being reintroduced. Match in a
    CLASS CONTEXT, never as a bare substring — PATTERNS measured this: a naive search returns 269 hits
    across 55 files against exactly 1 real one, because dialog, card and tab content components all
    contain the word.

G-3 THE CONFIG, BOTH HALVES. `frontend/tailwind.config.ts` declares no container theme block AND
    disables the container core plugin. Catches: a future edit reinstating either half. Deleting the
    theme block alone is not enough — measured, the plugin then emits its DEFAULT five media queries,
    which is worse than the single one the tree had before this phase. A gate that checks one half is
    half a gate.

G-4 SKELETON AND CONTENT PARITY. For each declared route FAMILY, every member's band width token is
    equal. Catches: the exact defect plan 35-07 fixed on the shop detail route, where the skeleton was
    384px wider than the content and the page narrowed on hydration. This assertion is OWED — plan
    35-07 ran its break arm and recorded that it produced no red because this gate did not exist yet.
    Closing that is a required outcome of this plan.
    Note it is a FAMILY, not a pair: the `/shop/[slug]` family has THREE members (loading skeleton,
    detail client, not-found panel), all at 896. A check hard-coded to compare two files would silently
    leave the third free to drift while reporting the route as covered.

G-5 NO WIDTH LITERAL IN THE BUILD CONFIG. The Tailwind config carries no raw pixel max-width band
    value; it must import them. Catches: the config and the constants module drifting, which is the
    same failure the cart-identity module's docblock records for a different string.

G-6 MANIFEST COMPLETENESS, BOTH DIRECTIONS. Every source file listed in the tier manifest declares the
    tier the manifest assigns it, AND every file in the frontend that declares a tier appears in the
    manifest. Catches, in the first direction, a tier silently dropped by a refactor; in the second, a
    surface tiered by someone who did not update the contract. One direction alone is half a check.

FAIL-CLOSED. Exit 2 (VOID) on: missing tooling, an unreadable or empty manifest, zero source files
discovered, or a scan that found nothing to check. "Found nothing" is never "clean" — this repo has
rediscovered that failure mode repeatedly, most recently in a deny-list guard that could not fire.

TWO TRAPS THE GATE MUST NOT FALL INTO ITSELF.
  - A gate that fires on its own definition. The gate names the tokens it forbids, and so will the
    contract document. Exclude the gate script and the contract document from the scanned set, and say
    so in the header.
  - A comment satisfying a grep. Strip block comments and line comments from each source file BEFORE
    counting. A bare occurrence count over an unfiltered file is forbidden — the tier component's own
    docblock explains the tokens in prose, and every application site carries a comment naming its tier.
</gate_assertions>
