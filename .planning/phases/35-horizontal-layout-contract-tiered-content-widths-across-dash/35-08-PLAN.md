<the_four_traps>
Each of these has already cost this repo a real defect. The spec must be written against all four.

TRAP 1 — ASSERTING A CONSTANT WHERE THE TIER IS FLUID. The validated arithmetic model is
`band = min(parent content width, TIER)`, and it reproduces all three of CONTEXT's measured cells
exactly. At a 1920 viewport the dashboard shell's parent offers 1664px (viewport minus the 256px
sidebar), so the correct measured band is **1664 — fluid, no cap binds**. An assertion written as
"expect the band to be 1700" REDS AT 1920 ON A PERFECTLY CORRECT BUILD. Always compare against
`Math.min(availableWidth, TIER)`.

TRAP 2 — THE VACUITY PASS. A band selector that matches nothing measures 0, and 0 is less than or
equal to every tier. `e2e/public-layout.spec.ts:319-375` documents the identical failure over a table
and the fix: assert the element was FOUND and that its parent's client width is greater than zero
BEFORE comparing anything to a tier. The measurement helper must return null rather than zeros when
the element is absent, and the test must fail on null with a message naming the selector and the route.

TRAP 3 — THE VIEWPORT THAT IS NOT THERE. `playwright.config.ts` declares exactly two projects,
mobile at 390 and desktop at 1440. Nothing in the config produces 1920 or 2560. A describe that does
not pin its own viewport measures the project's viewport while claiming to measure another. Pin with
`test.use({ viewport: … })` inside each describe — precedent at `e2e/dashboard-mobile.spec.ts:375-380`,
whose comment explains this exact reasoning.

TRAP 4a — THE SKIP BUDGET IS A PRECONDITION, NOT A CONSEQUENCE. `scripts/gates/e2e-skip-budget.conf`
is `MAX_SKIPS 6` and fails on any UNDECLARED skip title, and issue #686 already records the budget
sitting at 7/6. Every dashboard describe in this spec skips via `skipWithoutVendorPassword()` when the
credential is absent — `e2e/vendor-credentials.ts` defaults it to the empty string DELIBERATELY, so an
unsupplied password is a visible skip rather than a silent 21-second auth failure misread as a product
defect. This spec can therefore push the count over budget merely by being run without a credential.

Do ONE of these two explicitly, and record which in the SUMMARY — do not let a run silently exceed the
budget: (a) state and satisfy the precondition, supplying `E2E_VENDOR_PASSWORD` or sourcing the stack
`.env` for `KC_SEED_USER_PASSWORD` before running, so the describes EXECUTE rather than skip; or
(b) declare each new skip title in `scripts/gates/e2e-skip-budget.conf` and raise the ceiling by
exactly the number declared, with the reason recorded at the conf entry. Option (a) is strongly
preferred: a declared skip is still an unrun assertion, and measurement is this spec's entire purpose.

TRAP 4 — THE SKIP THAT MEANS TWO THINGS. Tag every wide describe `@desktop-only`. The mobile project's
grepInvert then never ENUMERATES them, so they never appear as runtime skips. The config's own comment
is explicit that a skip must mean "nobody checked this" and cannot also mean "not applicable here",
and `scripts/check-e2e-skip-budget.sh` enforces a ceiling on the count.

TRAP 5 — `clientWidth` INCLUDES PADDING, SO THE DENOMINATOR IS THE WRONG BOX. This one would RED a
perfectly correct build on every desktop viewport, and it is the trap this plan came closest to
shipping. A child's border-box width resolves against its parent's CONTENT box, but `clientWidth`
returns the parent's padding box — content plus left and right padding. The dashboard shell band
(`components/dashboard/dashboard-shell.tsx`) carries `p-4 sm:p-8`, so at every viewport at or above the
`sm` breakpoint it holds **64px of horizontal padding**. Measured consequence at 2560: the shell band's
own width is the declared shell value 1700, its `clientWidth` is therefore 1700, and the Index child
inside it renders at 1700 − 64 = **1636**. An assertion reading "the Index band equals the parent's
clientWidth" fails by exactly the padding — 64px — on 1440, 1920 and 2560 alike, on a build that is
doing precisely what the contract asks.

THE RULE, and it applies to EVERY tier in this spec, not only Index: the denominator is the parent's
CONTENT box, computed as `clientWidth − paddingLeft − paddingRight` read from `getComputedStyle`, never
`clientWidth` raw. Compute it once in the shared measurement helper and return it as a named field, so
no individual assertion can pick the wrong box.

This is RESEARCH.md's assumption **A4** — *"`parentElement.clientWidth` is the right 'available width'
denominator on every tier"* — coming due. A4's own mitigation is *"falsify by printing both values"*,
and that mitigation is hereby carried into the behaviour spec rather than left in the assumptions log:
on ANY width failure the message must print the parent's raw `clientWidth`, its resolved content box,
its computed left and right padding, and the measured band width. Without all four, a 64px miss is
indistinguishable from a genuine 64px layout defect, and the next reader "fixes" the product to satisfy
the test.
