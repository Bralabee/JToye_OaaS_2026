<objective>
Give the contract a vocabulary the DOM can be queried on, then apply the Shell tier at the one place
the whole dashboard inherits its width from.

PATTERNS.md finding F-1: `theme.container` is consumed by EXACTLY ONE call site in the tree —
`frontend/components/dashboard/dashboard-shell.tsx:55`. All 21 dashboard routes inherit that one
line; none declares a width of its own. So the Shell tier is a one-line edit, and that is also why
it must be done carefully: everything authenticated depends on it.

PATTERNS.md finding F-3 is why the tier marker exists at all: "Index = fluid to shell" implemented
as "change nothing" produces a contract no assertion can distinguish from the bug. A spec that
measures `/dashboard/orders` at 1700 cannot tell whether the page is deliberately Index-tier or
whether someone forgot to cap it. The `data-width-tier` attribute makes the tier a declaration.

Purpose: this plan is the vocabulary every wave-3 plan applies. It ships before them so they all
speak the same one.

Output: `components/layout/content-tier.tsx` with its test, and a Shell-tiered dashboard shell.
</objective>

<application_doctrine>
Two application shapes, and which to use is not a matter of taste. Every wave-3 plan follows this.

IN PLACE (preferred) — the surface already has a band element carrying `mx-auto max-w-*`. Swap the
max-w class and add the `data-width-tier` attribute on that same element. NO new DOM node, so no
change to any layout, motion or scroll-reveal behaviour, and no risk to the CLS and boundingBox
assertions already in the suite.

WRAPPER (only when there is no band element) — use the `ContentTier` component. A wrapper adds a DOM
node, so it is the shape that can move things; prefer in-place wherever an element already exists.

ONE component, parameterised. Not one per tier. `components/public/public-shell.tsx` records what
this repo already paid for going the other way: "Three copies of this pattern already existed and two
had already drifted apart; a fourth variant would be the drift, not the fix."
</application_doctrine>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| component source -> generated CSS | A tier class literal is only generated if it appears in scanned content; a literal outside the globs ships an uncapped element |
| shared shell -> every authenticated route | One line governs the band for all 21 dashboard routes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-05 | Tampering | `WIDTH_TIER_CLASS` | mitigate | A tier added to the union without a class entry would render uncapped and silently. Mitigated by the union-iterating map-completeness test in Task 1 |
| T-35-06 | Denial of Service | `dashboard-shell.tsx` band | mitigate | This one element wraps every authenticated page; a bad edit blanks the dashboard. Mitigated by an IN-PLACE edit that adds no DOM node, by the enumerated preserved-class assertions, and by ARM C proving those assertions can fail |
| T-35-07 | Spoofing / Elevation | tier value | accept | `tier` is a compile-time member of a closed union, never a runtime string from any external source, so no injected value can select a class. This stays true only while tier is static — if a later plan makes tier dynamic from request data, ASVS V5 becomes live and this disposition must be revisited |
| T-35-08 | Information Disclosure | widened band | accept | The columns a table renders are chosen by the component and gated by the API and Postgres RLS, and are identical at every width. Widening changes only how much of an already-rendered table is visible without scrolling |
| T-35-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install in this plan; nothing new enters the tree |

ASVS L2: V14 applies advisorily — utilities, never `style={{ maxWidth }}`, so the CSP's
`'unsafe-inline'` allowance is not newly leaned on. V2/V3/V4/V6 do not apply; the auth check for
these routes lives in `app/dashboard/layout.tsx` and is untouched.
</threat_model>
