<objective>
Create the one place the four tier widths are declared, and make Tailwind produce utilities from it.

ROADMAP Phase 35 root cause, verbatim: *"No document in the repo declares a width standard — the
number came with the scaffold."* This plan removes the scaffold's number and replaces it with a
declared one that the build, the app and the tests all read from a single file.

Purpose: every later plan in this phase applies a tier. If the tier values live in more than one
place they will drift, and a spec asserting 1700 while the shell renders 1690 is a test that
measures a literal rather than a contract (`frontend/lib/cart-identity.ts` docblock, the repo's own
precedent for this failure).

Output: `frontend/lib/layout-widths.ts`, two Jest suites, and an edited `tailwind.config.ts` whose
`theme.container` block is gone and whose `container` core plugin is switched off.
</objective>

<interfaces>
The contract this plan declares. Values are locked by CONTEXT.md section 4 and are peer-matched,
not invented — do not adjust them.

  SHELL_MAX_PX     = 1700   // dashboard chrome     — Stripe 1690, Square 1680-1720
  DETAIL_MAX_PX    = 1100   // order detail, forms  — Linear 1136, Square 1016, Lightspeed 1100
  MARKETING_MAX_PX = 1280   // landing + marketing  — Stripe marketing 1264
  (index)          = no number, deliberately — "fluid to shell", so there is nothing to declare

LAYOUT_WIDTHS is the px-string view Tailwind consumes, DERIVED from the numbers above (template
literal), never restated — same discipline as perf-budgets.ts's LANDING_BUNDLE_CEILING_BYTES,
which is written as its own arithmetic so the sum cannot drift from its parts.

Three loaders read this file: jiti (Tailwind config), webpack (Next) and esbuild (Playwright).
It must therefore be PURE CONSTANTS WITH NO IMPORTS — no React, no next/*, no DOM-only types.
</interfaces>

</context>

<constraints_from_research>
- MEASURED, both directions: a relative specifier in `tailwind.config.ts` resolves (rc=0, utilities
  emitted); the `@/` alias throws `Cannot find module` (rc=1). jiti does not read
  tsconfig compilerOptions.paths. Use the relative form and prove it with a real build.
- MEASURED, both arms: a class-name STRING living under `lib/` is never generated, because the
  content globs cover only `pages/`, `components/` and `app/`. Numbers may live in `lib/`;
  class-name literals must not. This plan therefore puts no class string in `lib/`.
- MEASURED: deleting `theme.container` does NOT remove the `.container` utility. The core plugin
  falls back to the default screens and emits FIVE media queries instead of one — strictly worse
  than today. The utility is removed by switching the core plugin off, not by deleting the theme
  block. Do both: delete the theme block (so no dead 1400 invites re-use) and disable the plugin.
</constraints_from_research>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build config -> generated CSS | A value read by the Tailwind config at build time becomes a stylesheet shipped to every browser |
| repo source -> shipped bundle | No user input crosses into this plan's surface at all; tier values are compile-time literals |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-01 | Tampering | `frontend/lib/layout-widths.ts` -> Tailwind | mitigate | A class-name string placed in `lib/` is silently never generated (measured, both arms), shipping an uncapped element while everything builds green. Mitigated by holding only NUMBERS in `lib/`, asserted by the purity test in Task 1 and by the static gate in plan 35-10 |
| T-35-02 | Tampering | `tailwind.config.ts` value vs module value | mitigate | Config and constant can diverge silently. Mitigated by the PostCSS drift test (Task 2) which imports the constant, plus its recorded fail arm (Task 3 ARM C) |
| T-35-03 | Denial of Service | `npm run build` | mitigate | An unresolvable config import fails the build for every environment at once. Mitigated by proving the relative specifier with a real build and recording the alias failure (Task 3 ARMs A/B) |
| T-35-04 | Information Disclosure | generated CSS | accept | A max-width value is not secret and reveals nothing about tenants, users or data. No mitigation needed |
