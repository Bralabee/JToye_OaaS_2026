## Decisions Made
- **Runner fix over test-only patching.** Skipping non-PENDING rows in the recompute is the correct semantics (it also protects future webhook-set gates and removes redundant external calls), so I applied the orchestrator/18-04-preferred fix rather than only mocking beans in the failing test.
- **Retire, don't resurrect, the superseded auto-approve submit scenarios.** With three real gate beans materialising on submit, the wave-2 test's manual BUSINESS_VERIFIED seed is a guaranteed UNIQUE collision; the new cross-gate e2e owns the fully-automatic proof, so those two scenarios were removed and the submit test narrowed to its still-valid submit/resubmit HTTP contract.
- **Let `docs/metrics.json` compute the counts.** The old 802/595/96 manifest predated the phase's onboarding tests; `--write` yields 873/666/109 for THIS tree. Per the briefing, main reconciles at PR time — my job was only internal consistency, which check mode confirms.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] GateChainRunner re-evaluated terminal gate rows**
- **Found during:** Task 1 (reconciling the two failing auto-approve integration tests).
- **Issue:** `runAndRecompute` re-evaluated every automatic gate unconditionally, clobbering rows already in a terminal state — the diagnosed root cause of the two `OnboardingSubmitIntegrationTest` failures and a latent bypass surface (T-18-06-T).
- **Fix:** Skip any gate row whose status is not PENDING before (re)evaluating.
- **Files:** `GateChainRunner.java`. **Verification:** GateChainRunnerTest green; full integration suite green. **Committed in:** `1455789`.

**2. [Rule 1 - Directly-caused breakage] Reconciled OnboardingSubmitIntegrationTest**
- **Found during:** Task 1.
- **Issue:** Three concrete gate beans now materialise on submit, so the wave-2 test's manual BUSINESS_VERIFIED seed collides (UNIQUE) and its two auto-approve scenarios are superseded; it also risked real FSA egress on the async thread.
- **Fix:** `@MockBean` the FHRS + Companies House clients (both → MANUAL_REVIEW, hermetic); retire the two auto-approve scenarios (now proven by the new cross-gate e2e); keep the submit/resubmit contract.
- **Files:** `OnboardingSubmitIntegrationTest.java`. **Verification:** 2/2 green. **Committed in:** `1455789`.

**3. [Rule 3 - Blocking build issue] integrationTest fork exhausted native threads**
- **Found during:** Task 1 (running the FULL `:core-java:integrationTest` for the success bar).
- **Issue:** Running the 24-class Testcontainers suite in ONE JVM fork accumulated enough live `RabbitListenerEndpointContainer` / reactive `HttpClient` selector threads (across many distinct per-class Spring contexts) to hit a native-thread `OutOfMemoryError` (exit 99) — deterministically, on a fresh daemon. My added per-class context tipped an already-borderline suite over.
- **Fix:** `setForkEvery(4)` on the integrationTest task recycles the fork, bounding live threads to a few classes' worth. No test behaviour changes (containers are per-class static; tests use fresh random tenants).
- **Files:** `core-java/build.gradle.kts`. **Verification:** full integrationTest BUILD SUCCESSFUL, 129 tests, 0 failures. **Committed in:** `0873fb2`.

**4. [Orchestrator override] ROADMAP.md finalisation omitted**
- **Issue:** The plan's Task 2 + files_modified include `.planning/ROADMAP.md`, but the execution briefing explicitly reserves STATE.md and ROADMAP.md for the orchestrator to update centrally after the wave merges (avoids a merge conflict on the shared file).
- **Fix:** Did NOT touch ROADMAP.md; all other Task 2 artifacts delivered. The orchestrator applies the Phase 18 plan-list / requirement-ID / progress-row update post-merge.
