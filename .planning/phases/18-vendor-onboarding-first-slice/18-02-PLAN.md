<objective>
Deliver the vertical submit slice: a vendor can create an onboarding (`DRAFT`), submit it (`DRAFT → VERIFYING`), and read its live status + per-gate breakdown — driven by an onboarding state machine that mirrors the Order triad and is the **sole writer of `Shop.published`**. This plan also stands up the data-driven gate-chain *registry* (`OnboardingGate` interface + `GateChainRunner`) that 18-03/04/05 plug concrete gates into with zero further edits here.

Purpose: make submit work end-to-end (HTTP → state machine → DB → HTTP) and lock the go-live authority into one guarded transition, so no caller can flip a storefront live outside the onboarding flow.
Output: state-machine config/service, `VendorOnboardingService`, gate-chain registry + runner, the onboarding controller + DTOs, `ShopService.setPublished`, and unit + integration proofs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| vendor client → /onboarding API | Untrusted request body; must not carry tenant_id or a caller-chosen published flag |
| onboarding flow → Shop.published | Only the guarded GO_LIVE/SUSPEND transition may change go-live visibility |
| request thread → @Async gate worker | TenantContext must be re-established or RLS writes silently fail/deny |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-02-T | Tampering | vendor forces go-live outside the flow | mitigate | ShopService.setPublished is the single true-writer, reached only from the GO_LIVE side effect; GO_LIVE guard requires gates PASSED; direct-update hardening lands in 18-05 with a regression test |
| T-18-02-S | Spoofing | request body supplies tenant_id | mitigate | Tenant resolved server-side via CurrentTenant.require(); DTOs carry no tenant_id |
| T-18-02-E | Elevation of Privilege | async gate write under wrong/unset tenant | mitigate | runAndRecompute takes tenantId param, sets TenantContext in try/finally so TenantSetLocalAspect applies the GUC; RLS still enforces |
| T-18-02-D | Denial of Service | guard/transition exceptions leak 500s | mitigate | InvalidStateTransitionException maps to 400 via existing GlobalExceptionHandler; guards return false rather than throw |
| T-18-02-SC | Tampering | new package installs | accept | No new gradle dependencies (Spring StateMachine already used by Order flow); package-legitimacy gate not triggered |
</threat_model>
