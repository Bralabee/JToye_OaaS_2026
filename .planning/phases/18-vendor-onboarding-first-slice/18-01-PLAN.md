<objective>
Establish the persistence + configuration foundation for vendor onboarding: the tenant-scoped `vendor_onboarding` aggregate, its data-driven `vendor_onboarding_gate` child rows, both Envers `_aud` mirrors, the enum vocabulary, JPA entities/repositories, and the `onboarding.*` config surface — all under FORCE RLS so a `DRAFT` onboarding can be built while `Shop.published=false` holds the storefront back.

This is the first (vertical) slice's data layer. After this plan an onboarding aggregate *persists under real RLS*; the submit/state-machine/API behaviour that consumes it lands in 18-02, and the gate evaluators in 18-03/04/05.

Purpose: give every later slice a proven, tenant-isolated aggregate to write against, so no downstream executor has to invent the schema or the config keys.
Output: Flyway V43, 5 enums, 2 audited entities + 2 repositories, `OnboardingProperties` + `application.yml` keys, and a Testcontainers RLS proof.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tenant connection → onboarding tables | Every read/write of vendor_onboarding[_gate] must be tenant-scoped; a cross-tenant read leaks a competitor's compliance state |
| Envers audit writer → _aud tables | Audit rows may carry tenant_id NULL; predicate must admit NULL yet still filter set-tenant reads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01-I | Information Disclosure | vendor_onboarding / _gate SELECT across tenants | mitigate | ENABLE+FORCE RLS + `tenant_id = current_setting('app.current_tenant_id',true)::UUID` policy on all 4 tables; proven by VendorOnboardingRlsIntegrationTest + RlsContractTest sweep |
| T-18-01-T | Tampering | INSERT with a forged tenant_id | mitigate | WITH CHECK clause on every policy rejects tenant_id != GUC; asserted by the cross-tenant INSERT test |
| T-18-01-E | Elevation of Privilege | table-owner/superuser bypass of RLS | mitigate | FORCE ROW LEVEL SECURITY on every table; test downgrades role to NOSUPERUSER to prove it |
| T-18-01-SC | Tampering | new package-manager installs | accept | No new gradle dependencies introduced by this plan (JSONB/@Audited/WebFlux all already present); no install task ⇒ package-legitimacy gate not triggered |
</threat_model>
