<objective>
Add Spring WebSocket/STOMP infrastructure with tenant-isolated channel security to the Core service.

Purpose: Enable real-time bidirectional communication for Kitchen Display System while preventing cross-tenant data leakage. This is the security foundation that Phase 6 (event pipeline) and Phase 7 (KDS UI) build upon.

Output: WebSocketConfig, JwtHandshakeInterceptor, TenantChannelInterceptor, SecurityConfig update, and comprehensive tests proving tenant isolation.
</objective>

<threat_model>
## Threat Model (ASVS Level 1)

### T-01: Cross-Tenant Data Leakage via WebSocket Subscription (HIGH)
**Attack:** Authenticated Tenant A subscribes to /topic/kitchen/{tenantB_id}/{shopId} and receives Tenant B's order events.
**Mitigation:** TenantChannelInterceptor.handleSubscribe() parses the destination path and compares tenantId segment against the JWT-validated session tenantId. Mismatch throws MessageDeliveryException, rejecting the subscription.
**Verification:** TenantChannelInterceptorTest.shouldBlockCrossTenantSubscription()

### T-02: Unauthenticated WebSocket Connection (HIGH)
**Attack:** Client connects to /ws without a JWT token and subscribes to topics.
**Mitigation:** JwtHandshakeInterceptor extracts token from query param. TenantChannelInterceptor.handleConnect() validates the token via JwtDecoder. Missing or invalid token throws MessageDeliveryException, disconnecting the client.
**Verification:** TenantChannelInterceptorTest.shouldRejectMissingToken(), shouldRejectInvalidToken()

### T-03: JWT Token in URL Query Parameter Exposure (MEDIUM)
**Attack:** JWT token in /ws?token=<jwt> may be logged in server access logs or visible in network proxies.
**Mitigation:** Acceptable tradeoff per D-01 -- browser WebSocket API does not support custom headers. Access logs should be configured to redact query parameters in production. Token is short-lived (Keycloak access token expiry).
**Status:** Accepted risk (standard industry pattern for WebSocket auth).

### T-04: TenantContext Not Set in WebSocket Handler (MEDIUM)
**Attack:** If TenantContext is not propagated to @MessageMapping handler threads, RLS queries return wrong data or no data.
**Mitigation:** TenantChannelInterceptor.propagateTenantContext() sets TenantContext from session attributes before handler executes (preSend on SEND). ExecutorChannelInterceptor.afterMessageHandled() clears it after, guaranteed to run on the same thread as the handler.
**Verification:** TenantChannelInterceptorTest.shouldSetTenantContextOnSend(), shouldClearTenantContextAfterMessageHandled()

### T-05: Invalid UUID in Topic Path Causes 500 (LOW)
**Attack:** Client sends SUBSCRIBE to /topic/kitchen/not-a-uuid/foo.
**Mitigation:** UUID.fromString() in handleSubscribe() is wrapped in try-catch. IllegalArgumentException results in MessageDeliveryException("Invalid tenant ID in destination"), not a 500 server error.
**Verification:** TenantChannelInterceptorTest.shouldRejectInvalidTenantIdInDestination()
</threat_model>

    **Create TenantChannelInterceptor (per D-05, D-06, D-10, D-11, Pattern 2+3 from RESEARCH.md, Open Question 2 resolution):**

    Create `core-java/src/main/java/uk/jtoye/core/websocket/TenantChannelInterceptor.java`:
    - `@Component` annotated, implements `ExecutorChannelInterceptor` (which extends `ChannelInterceptor`)
    - Using `ExecutorChannelInterceptor` instead of plain `ChannelInterceptor` per D-11 and RESEARCH.md Open Question 2: `afterMessageHandled()` is guaranteed to run on the same thread as the message handler, ensuring TenantContext cleanup is thread-safe.
    - Constructor injection: `JwtDecoder jwtDecoder`
    - `preSend(Message<?> message, MessageChannel channel)`:
      - Get `StompHeaderAccessor` from message via `MessageHeaderAccessor.getAccessor()`
      - If accessor is null, return message unchanged
      - Switch on `accessor.getCommand()`:
        - `CONNECT` -> `authenticateConnection(accessor)`
        - `SUBSCRIBE` -> `validateSubscription(accessor)`
        - `SEND` -> `propagateTenantContext(accessor)`
        - default -> no-op
      - Return message

    - `authenticateConnection(StompHeaderAccessor accessor)`:
      - Get session attributes: `accessor.getSessionAttributes()`
      - Extract `jwt_token` string from session attributes (stored by JwtHandshakeInterceptor)
      - If null or blank: `throw new MessageDeliveryException("Missing JWT token")`
      - Decode: `Jwt jwt = jwtDecoder.decode(token)` (reuses existing Keycloak JWKS JwtDecoder bean -- handles signature verification, expiry, key rotation)
      - Extract tenantId using same claim preference as JwtTenantFilter: `tenant_id`, `tenantId`, `tid` -- iterate claims, parse UUID
      - If no tenant claim found: `throw new MessageDeliveryException("JWT missing tenant claim")`
      - Store in session: `sessionAttrs.put("tenantId", tenantId)`
      - Set authenticated principal: `accessor.setUser(new JwtAuthenticationToken(jwt))`

    - `validateSubscription(StompHeaderAccessor accessor)`:
      - Get destination: `accessor.getDestination()`
      - If null or does not start with `/topic/kitchen/`, return (allow non-kitchen subscriptions through)
      - Parse destination path by splitting on `/`: expect `["", "topic", "kitchen", "{tenantId}", "{shopId}"]`
      - If `parts.length >= 4`: parse `parts[3]` as UUID (wrap in try-catch for IllegalArgumentException -> throw `MessageDeliveryException("Invalid tenant ID in destination")`)
      - Compare parsed tenantId against `sessionAttributes.get("tenantId")`
      - If mismatch: `throw new MessageDeliveryException("Cross-tenant subscription denied")`
      - Per D-06 and Pitfall 5: validate tenantId only, NOT shopId. RLS handles shop-level isolation on data queries.

    - `propagateTenantContext(StompHeaderAccessor accessor)`:
      - Get tenantId from session attributes
      - If present: `TenantContext.set(tenantId)`

    - `afterMessageHandled(Message<?> message, MessageChannel channel, MessageHandler handler, Exception ex)`:
      - Always clear TenantContext: `TenantContext.clear()`
      - This runs on the SAME thread as the message handler (guaranteed by ExecutorChannelInterceptor contract), so TenantContext cleanup is thread-safe.
      - Clears unconditionally -- safe for CONNECT/SUBSCRIBE/SEND/DISCONNECT. TenantContext.clear() is a no-op if nothing was set.
