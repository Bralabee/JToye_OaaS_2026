<objective>
Build the consent/suppression governance the platform lacks (COMMS-03): the `V54` migration (notification_suppression + marketing_opt_in, ENABLE+FORCE RLS via `current_tenant_id()`), the `NotificationCategory` enum (owned here — categories are a consent concept, D-03), entities/repos, a `ConsentGate` (may-we-send: transactional under legitimate interest with per-category suppression; marketing requires explicit opt-in), a stateless HMAC `UnsubscribeTokenService`, and a no-auth `PublicUnsubscribeController` under `/api/v1/public/unsubscribe`.

Purpose: This is the gate 22-04's dispatch calls before every send, and the public surface that makes one-click unsubscribe real (GDPR/PECR). Fully independent of the email and webhook tracks (own package; the unsubscribe secret is read via `@Value` env-default, NOT the 22-01 properties bean) — Wave 1 parallel.
Output: 1 migration + category enum + 4 data classes + ConsentGate + token service + public controller + RLS/gate/token/integration tests.
</objective>
