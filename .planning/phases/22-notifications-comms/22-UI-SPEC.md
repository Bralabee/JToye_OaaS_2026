# Phase 22 — UI Design Contract

> Visual and interaction contract for the Notifications & Comms frontend surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope (COMMS-06 + COMMS-03 UI halves only):**
> 1. **Webhook subscriptions** — authenticated dashboard: create / list / pause / resume / revoke; rotate signing secret (shown once); per-subscription event-type selection; ACTIVE / PAUSED / AUTO-PAUSED / REVOKED state badges.
> 2. **Delivery-log browser** — authenticated dashboard: per-endpoint table/cards of `webhook_delivery` rows, filterable by event type + status; HTTP code + attempt count; manual **replay** (tagged attempt); auto-pause failure reason surfaced.
> 3. **Public unsubscribe page** — token-based, NO auth, mobile-first; the ONE public/unauthenticated surface (owns SEO basics + no-auth safety).
>
> **Grounding rule (LOCKED):** Extend the EXISTING food-delivery design system (orange / emerald / slate). No editorial/newspaper direction, no serif display type, no new visual language — see memory `feedback_design_direction`. Every token below is quoted from what already ships.

## Typography

Faithful to the shipping dashboard scale (Inter). Mobile-first: page title scales up at `sm`.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display (page H1) | 24px mobile → 30px `sm:` (`text-2xl sm:text-3xl`) | 600 semibold | 1.2 (`leading-tight`) | "Webhooks", "You're unsubscribed" |
| Heading (card / section / dialog title) | 18px (`text-lg`) | 600 semibold | 1.3 | CardTitle, DialogTitle, section headers |
| Body | 14px (`text-sm`) | 400 regular | 1.5 | Table cells, dialog body, descriptions, buttons |
| Label / meta | 12px (`text-xs`) | 400 regular | 1.4 | Field labels, timestamps, HTTP codes, badge text, helper copy |

**Weight contract:** exactly two weights — **regular 400** (body, table cells, labels, meta, timestamps, helper copy) and **semibold 600** (page title, section/card/dialog headings, badge text, emphasis). `badge.tsx`'s built-in `font-semibold` maps to the 600 weight, so status badges stay within the two-weight contract.

**Mono:** HTTP status codes, delivery IDs, endpoint URLs, and signing secrets render in `font-mono text-xs` (matches order-number cells in `orders/page.tsx`).

**375px guard:** the page H1 stays `text-2xl` on mobile and the header stacks (`flex-col sm:flex-row`) so a right-aligned "Add endpoint" CTA never collides with the title. Do NOT copy the legacy `text-4xl` H1 from `orders/page.tsx` (it risks 375px overflow beside a CTA).

## Interaction Contracts

- **Add endpoint:** HTTPS-only Zod validation (`z.string().url().startsWith("https://")` → the non-HTTPS field error). Require ≥1 event type. On submit: POST subscription → response returns the plaintext `signing_secret` **once** → immediately open Secret-Reveal dialog. List refreshes.
- **Event-type selection (D-06):** grouped checkboxes by family — **Orders**, **Onboarding**, **Payments**, **Refunds** — each family expandable to its individual event types with a family-level "select all". At least one required. On mobile the groups stack; each checkbox row is `min-h-11`.
- **Secret reveal:** modal, focus-trapped (radix `Dialog`). Secret in a readOnly `font-mono` `Input`; **Copy** button writes to clipboard and fires a `Copied` toast (aria-live). Dialog cannot be dismissed by backdrop click for this one — only the explicit **I've saved it** button — to reduce accidental loss. Secret is never re-fetchable; UI states this.
- **Rotate secret:** confirm dialog → POST rotate → returns new secret → Secret-Reveal dialog again. Old secret invalid immediately (copy states this).
- **Pause / Resume:** `Button` toggle (no Switch primitive). **Pause delivery** is immediate (no confirm). **Resume delivery** is immediate and resets the consecutive-failure counter server-side; UI reflects the new ACTIVE badge.
- **Revoke:** destructive confirm dialog (`Button variant="destructive"`, red). Terminal — the row shows the Revoked badge and drops its actions afterward.
- **Replay (agent-readiness / idempotent-safe):** confirm dialog → POST replay with a fresh **`Idempotency-Key`** header generated by `crypto.randomUUID()` — **reuse the exact `makeIdempotencyKey()` pattern from `RefundDialog.tsx`** (secure-random, throws if unavailable). Replay creates a NEW delivery attempt row tagged "Replay"; it never mutates the original row's status history. Success toast per Copywriting table.
- **Loading spinners:** `animate-spin rounded-full border-b-2 border-t-2 border-orange-500` (orange, per Phase 20 direction — do NOT copy the legacy `border-blue-600` spinner).
- **Data fetching:** `useEffect` + `useState` + `apiClient` (no react-query). Errors → destructive toast (never a blank screen — see memory `process_retro_user_caught_defects`).

## Accessibility Contract

- **Status is never color-alone:** every badge = tinted background + lucide icon + text label (matches `orders`/`marketing`/`track` precedent). Icon-only action buttons carry `aria-label` (e.g. "Rotate secret", "Revoke endpoint").
- **Destructive/sensitive actions:** Rotate, Revoke, and Replay are radix `Dialog`s (focus-trapped, Esc-to-cancel). Revoke + Rotate confirm buttons use the `destructive`/accent variant with a full-word label (not an icon). The confirm body is linked via `aria-describedby`.
- **Secret reveal:** warning is `role="alert"`; the copy action announces success via an aria-live toast; secret input is `readOnly` with `aria-label="Signing secret"`.
- **Touch targets:** all mobile interactive controls `min-h-11` (44px), matching `mobile-tab-bar`.
- **Focus:** `focus-visible:ring-2 focus-visible:ring-orange-500` on custom controls; shadcn primitives keep their `focus-visible:ring-ring`.
- **Filters:** each `Select` has a visible or `aria-label`ed label; the delivery table has an accessible caption/`aria-label`.
- **Public unsubscribe:** exactly one `<h1>`; all state is real text (SR-readable), not icon-only; full-width `min-h-11` primary button; renders standalone (no nav dependency).
