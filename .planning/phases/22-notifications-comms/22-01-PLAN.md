<objective>
Build the notification channel seam that every new event delivery uses: a `NotificationChannel` provider abstraction, a `MimeMessageHelper` multipart/alternative `EmailChannel` (branded HTML + plain-text), an `EmailTemplateRenderer` returning `{subject, html, text}` per event (D-01), and an INERT-by-default `WhatsAppSmsChannel` stub (COMMS-07). Add all notification + WhatsApp config keys to `application.yml` (GLOBAL_RULE_6).

Purpose: This is the interface-first foundation. The email-dispatch orchestration (22-04) and future channels call these contracts directly, no codebase exploration. It leaves the working order-email path (`EmailNotificationService`) completely untouched — new events ride the new multipart channel (Pitfall 5, path A). Deliberately owns NO shared type consumed by the other Wave-1 plans (NotificationCategory lives in 22-02), so 22-01/22-02/22-03 stay parallel-safe.
Output: Channel interface + email/whatsapp channels + renderer + two `@ConfigurationProperties` classes + config keys + unit tests.
</objective>
