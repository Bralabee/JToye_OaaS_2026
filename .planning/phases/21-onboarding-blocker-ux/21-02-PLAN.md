<objective>
Build the manual-review notification seam: when an onboarding stalls in MANUAL_REVIEW, emit a well-formed event onto the existing V46 transactional outbox — landing all three coupled pieces (exchange bean, publisher, flusher dispatch) together so the shared flusher never poisons the new row.

Purpose: D-01 requires J'Toye to be *notified* when an onboarding stalls, even though the actual reviewer console/webhook delivery is Phase 24. This is the highest-risk plan in the phase (RESEARCH Pitfall 1): writing an onboarding row to the shared `payment_event_outbox` without extending the flusher's hard-coded two-arm dispatch would deserialize it as `PaymentEvent`, poison-dead-letter it, or publish garbage. This plan is deliberately isolated so the atomic (a)+(b)+(c) unit gets full focus.

Output: `onboarding.events` TopicExchange, `OnboardingStateChangeEvent` record, `OnboardingEventPublisher`, the flusher dispatch branch, the `GateChainRunner` emission call, and unit + Testcontainers proofs.
</objective>

| Boundary | Description |
|----------|-------------|
| Async recompute worker -> outbox table | The stall INSERT crosses into RLS-protected storage on a worker thread (no ambient request tenant) |
| Outbox flusher -> RabbitMQ | The row payload is deserialized and published to a topic exchange |
| Event payload -> future J'Toye consumer (Phase 24) | The reason string may surface to a J'Toye-side reviewer |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-21-02-02 | Tampering | Async write without tenant GUC | mitigate | `runAndRecompute` already re-establishes TenantContext from the passed `tenantId` (GateChainRunner ~:113-117) and clears in finally; publishStall is called only inside that guarded scope — no new async path introduced. |
