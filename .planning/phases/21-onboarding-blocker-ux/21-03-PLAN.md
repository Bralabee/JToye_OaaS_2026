<objective>
Make manual-review applications visible to both parties and unstickable: derive the vendor "in review" flag and expose the rejection reason on the vendor DTO, add the admin review queue, and add the gate-resolve control that drives the existing recompute so the state machine advances normally.

Purpose: This is the core of ONBD-03 (the MANUAL_REVIEW black hole) plus the ONBD-05 DTO half. The admin gate-resolve is the "seam" from D-01 — the interim resolver is the tenant's own admin role (documented as interim; a real J'Toye console is a deferred phase). The critical invariant: gate-resolve writes a GATE row and lets `GateChainRunner` advance the state machine — it NEVER writes status/published directly, and it triggers recompute AFTER commit (CR-01 landmine).

Output: widened `OnboardingDto`, `ResolveGateRequest` + `GateDecision`, three new/extended `VendorOnboardingService` methods (`resolveGate`, `listReviewPending`, `toDto` derivation), a repo finder, two admin endpoints, and Testcontainers proofs (advance, Envers audit, 403/404 RLS under NOSUPERUSER).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (tenant admin) -> OnboardingAdminController | Admin-role JWT + gate-resolve body cross here; interim resolver = the tenant's own admin (NOT a cross-tenant operator) |
| Admin request -> another tenant's onboarding | An admin must not resolve/read a foreign tenant's gate |
| resolveGate -> async recompute | The gate write must be visible to the worker; the worker must run under the tenant GUC |
