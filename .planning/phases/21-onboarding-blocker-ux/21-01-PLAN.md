<objective>
Ship the two net-new vendor-facing backend endpoints that make onboarding exits reachable and onboarding data correctable, entirely on existing state-machine and validation machinery, with zero Flyway migrations.

Purpose: ONBD-01 (withdraw) and ONBD-02 (correct company number) are the "reachable exit" and "correctable data" halves of the phase. The `WITHDRAW` event and its five source transitions already exist and are unit-proven; the company-number validation already exists on create. This plan wires the thin endpoint + service layer that was never built, and proves it under Testcontainers + RLS.

Output: `POST /onboarding/withdraw`, `POST /onboarding/company-number`, a new `UpdateOnboardingRequest` DTO, two `VendorOnboardingService` methods, and two Testcontainers integration tests.
</objective>

| Service -> Companies House client | The companyNumber value flows to an external lookup downstream (in resubmit) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01-01 | Tampering | Company-number update endpoint | mitigate | Reuse `@Size(32)`+`@Pattern` bean-validation (ASVS V5) so a malformed value is a clean 400 before it can reach the Companies House client; value is never taken from a client-supplied tenant field. |
| T-21-01-02 | Elevation of Privilege | withdraw / update service methods | mitigate | Tenant resolved via `CurrentTenant.require()` (never request body); `requireOnboarding(tenantId)` loads under RLS FORCE (V43) so a caller can only act on their own onboarding. |
| T-21-01-03 | Tampering | Onboarding lifecycle | mitigate | Withdraw routes through the canonical `transition(...)`; update fires no event and writes only the `companyNumber` data field — neither writes `status`/`Shop.published` directly (SM stays sole writer; verified by the withdraw guard-veto/state-unchanged test). |
| T-21-01-04 | Denial of state integrity | update endpoint out-of-window edit | mitigate | State guard rejects edits outside DRAFT/ACTION_REQUIRED with `InvalidStateTransitionException` -> RFC 7807 400 (proven in the VERIFYING-state test). |
| T-21-01-SC | Tampering (supply chain) | package installs | accept | No npm/pip/cargo installs this phase (RESEARCH Package Legitimacy Audit: N/A — zero new dependencies). No slopcheck gate applies. |
