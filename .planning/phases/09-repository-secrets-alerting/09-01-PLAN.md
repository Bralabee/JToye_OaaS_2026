<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host filesystem → container | `.env` file, template, entrypoint mounted into alertmanager container |
| Container → Slack API | outbound HTTPS POST to `hooks.slack.com` bearing a webhook token |
| Host network → :9093 | `docker compose` publishes 9093 on all interfaces by default |
| Prometheus → Alertmanager | unauthenticated HTTP on the `monitoring` docker network |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Information Disclosure | Slack webhook URL leak via container logs | mitigate | entrypoint.sh uses only `set -eu`, never `set -x`, never echoes `$ALERTMANAGER_SLACK_WEBHOOK_URL`; Task 4 asserts `docker logs` contains no `hooks.slack.com` matches |
| T-09-02 | Information Disclosure | Webhook URL committed to git via rendered `alertmanager.yml` | mitigate | `.gitignore` excludes `infra/monitoring/alertmanager/alertmanager.yml` (rendered); template `alertmanager.yml.tmpl` contains only `__SLACK_WEBHOOK_URL__` placeholder; Plan 02 gitleaks workflow provides defence-in-depth |
| T-09-03 | Tampering | Attacker edits `alertmanager.yml` at runtime to silence alerts | mitigate | Template + entrypoint mounted read-only (`:ro`); rendered config written inside container-only path `/etc/alertmanager/alertmanager.yml`; host cannot reach it without `docker exec` (which requires host root) |
| T-09-04 | Spoofing | Attacker injects synthetic alerts via exposed `:9093` | accept | Dev stack binds 9093 on all interfaces for local debugging; staging/prod must override to `127.0.0.1:9093:9093` when k8s ships in a follow-up phase (deferred per RESEARCH open question 3). No multi-tenant data exposed via this port, so low value target in dev |
| T-09-05 | Denial of Service | Alert flood overwhelms Slack webhook rate limit (1 msg/sec sustained) | mitigate | Alertmanager `group_wait=30s`, `group_interval=5m`, `repeat_interval=12h` (D-09) naturally dampen fan-out; Slack's own rate limits are the backstop |
| T-09-06 | Tampering | Developer sets `repeat_interval` too low and spams Slack, desensitising humans | mitigate | Values locked by D-09 in CONTEXT.md; Plan 03 runbook calls out the risk; alertmanager.yml.tmpl has the values baked in |
</threat_model>
