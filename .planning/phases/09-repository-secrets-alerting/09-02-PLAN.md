Two files, one commit — the CI workflow + the opt-in local hook. Both come from RESEARCH Patterns 6 and 7.

**1. Create `.github/workflows/gitleaks.yml`** verbatim from RESEARCH Pattern 6:

```yaml
name: gitleaks
on:
  pull_request:
    branches: [main]
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pull-requests: write

jobs:
  scan:
    name: gitleaks
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: gitleaks/gitleaks-action@v2
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          GITLEAKS_LICENSE: ${{ secrets.GITLEAKS_LICENSE }}
          GITLEAKS_ENABLE_COMMENTS: true
          GITLEAKS_ENABLE_UPLOAD_ARTIFACT: true
          GITLEAKS_ENABLE_SUMMARY: true
```

Notes:
- `fetch-depth: 0` is required — gitleaks scans history, not just HEAD.
- `GITLEAKS_LICENSE` referenced but OPTIONAL: the repo is personal (`Bralabee`), verified by `gh repo view --json owner` during Plan 01 Wave 0 preflight. Personal repos tolerate an unset `GITLEAKS_LICENSE`; the env-var reference does not fail the step if the secret doesn't exist. If the repo is ever transferred to an org, add a free license key at https://gitleaks.io → repo secret.
- `GITLEAKS_ENABLE_COMMENTS: true` requires the `pull-requests: write` permission above.

**2. Create `scripts/pre-commit-gitleaks.sh`** (D-12) verbatim from RESEARCH Pattern 7:

```sh
#!/bin/sh
# Opt-in local pre-commit hook: scan staged changes for secrets.
# Enable with: git config core.hooksPath scripts

if ! command -v gitleaks >/dev/null 2>&1; then
  echo "gitleaks not installed — skipping. Install: https://github.com/gitleaks/gitleaks#installing"
  exit 0
fi

echo "Running gitleaks on staged changes…"
if ! gitleaks protect --staged --redact --config .gitleaks.toml; then
  echo ""
  echo "gitleaks found a potential secret in your staged changes."
  echo "Fix the issue or add the file to .gitleaks.toml allowlist if it's a false positive."
  exit 1
fi
```

Set executable bit: `chmod +x scripts/pre-commit-gitleaks.sh` (and `git update-index --chmod=+x` or equivalent so the mode lands in git).

Document enablement in the Plan 03 runbook (not here) — developers who want the hook run:
```bash
ln -sf pre-commit-gitleaks.sh scripts/pre-commit
git config core.hooksPath scripts
```
(Symlink because git hook filename must be `pre-commit`, not arbitrary.)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author → main branch | untrusted commits must pass CI before merge |
| Developer workstation → commit | staged changes before `git commit` |
| `.gitleaks.toml` → gitleaks action | allowlist must not silence real secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-07 | Tampering | Attacker PRs a commit containing a real secret to main | mitigate | `.github/workflows/gitleaks.yml` triggers on `pull_request` to `main` and fails the status check; recommend adding a branch protection rule on `main` requiring this check (out of scope for this plan — manual GitHub setting) |
| T-09-08 | Information Disclosure | `.gitleaks.toml` allowlist regex too broad, silences a real secret under CHANGE_ME pattern | mitigate | `regexTarget = "secret"` scopes the regex to the matched secret value only (not full line); allowlist scoped to 4 literal patterns; Task 3 dry-run verifies no unexpected findings |
| T-09-09 | Elevation of Privilege | Gitleaks action with `pull-requests: write` escalates to arbitrary PR modification | accept | `pull-requests: write` is the minimum needed for comment posting; `contents: read` is the only filesystem permission; no `actions: write` or `packages: write` granted |
| T-09-10 | Spoofing | Attacker forks the repo and opens a PR from a fork — `GITHUB_TOKEN` is read-only in that context, PR comments will fail silently | accept | Expected behaviour for forked PRs; the scan still runs and the status check still blocks merge. PR comments missing is cosmetic, not a security gap |
| T-09-11 | Information Disclosure | Gitleaks findings artifact uploaded publicly via `GITLEAKS_ENABLE_UPLOAD_ARTIFACT` leaks the secret itself | mitigate | Gitleaks uploads the SARIF report, not the raw secret; `--redact` is the default in action mode; dry-run in Task 3 uses explicit `--redact` for parity |
</threat_model>
