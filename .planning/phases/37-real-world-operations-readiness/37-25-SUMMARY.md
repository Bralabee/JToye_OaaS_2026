# Phase 37 Plan 25: Per-tenant edge rate limiting with a typed 429 Summary

**The edge no longer has one bucket for everyone. A per-tenant token bucket now sits on the protected group after `jwtMiddleware.Validate()`, keyed on the tenant_id that middleware wrote, so one integrator's burst is refused — with `application/problem+json`, core's `rate-limited` type, code `RATE_LIMITED`, `Retry-After` and the three `X-RateLimit-*` headers — while every other tenant's sync continues; the old process-wide valve stays as a ten-times-larger flood guard and emits the same typed 429. Buckets refill lazily from a clock, live in a bounded map with idle eviction and one overflow bucket, and the whole thing is hand-rolled (no new module). The limits are config in every runtime (`.env.example` x2, compose, k8s configmap + deployment, goldens), the 429 is in the swag contract and asserted by the OpenAPI test, and the env contract passes with the two "the edge does not own this" omissions gone.**
