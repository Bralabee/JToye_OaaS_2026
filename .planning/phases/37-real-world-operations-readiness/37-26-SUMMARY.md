# Phase 37 Plan 26: Order size limits on every writer, and the review shop check Summary

**A 1,000,000-unit line can no longer become a £19 billion order through any door. `OrderLimits` is one bean bound to `jtoye.order-limits.*` (50 per line, 200 units, 50 lines, £1,000; `ORDER_LIMIT_*` in compose, `.env.example` and k8s), called by the storefront checkout inside its reserved idempotency work and by `OrderService.createOrder` — the vendor dashboard, the REST API and the MCP `create_order` tool — and every writer answers the same 422 `order-limit-exceeded` with typed `field`/`value`/`limit`/`productName`. The public shop payload carries `maxLineQuantity` so the stepper stops where checkout refuses. And a review now has to cite an order placed AT the shop reviewed: a buyer of shop A reviewing shop B of the same tenant gets 400 `review-order-shop-mismatch`, with the own-order, COMPLETED and one-per-order gates untouched.**
