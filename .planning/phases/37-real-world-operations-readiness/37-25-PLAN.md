<objective>
Stop anonymous traffic exhausting every vendor's sync, and make edge refusals typed (D-19; RWO-039 UXT-039).

Purpose: the edge has one channel bucket for all routes before auth with an untyped 429 body. This adds per-tenant limiting after
authentication and a typed, header-carrying 429 an integrator can back off from.

Output: the per-tenant limiter and its tests, the typed 429 on both limiters, config wiring, regenerated swag docs.
</objective>

<feature>
  <name>Per-tenant edge rate limiting with a typed 429</name>
  <files>edge-go/cmd/edge/ratelimit_tenant.go, main.go, types.go, handlers.go, docs</files>
  <behavior>
    - tenant A sends burst+1 requests to POST /api/v1/sync/batch -> the last is 429 problem+json type rate-limited with Retry-After > 0 and X-RateLimit-Remaining 0; tenant B's next request -> passes the limiter (core mocked)
    - after Retry-After elapses (fake clock) tenant A passes again (lazy refill)
    - 10,000 distinct tenant ids -> map size never exceeds the configured cap; extra tenants share the overflow bucket
    - anonymous flood on /health is unaffected by tenant buckets; the pre-auth valve still returns a typed 429 when its (larger) budget is spent
  </behavior>
  <implementation>Hand-rolled token bucket keyed by tenant id with a clock interface for tests; middleware reads c.Get("tenant_id").</implementation>
</feature>
