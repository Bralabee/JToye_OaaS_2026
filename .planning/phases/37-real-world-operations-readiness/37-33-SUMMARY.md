# Phase 37 Plan 33: Basket re-validation at submit, composed with the 31.1 allergen refusal Summary

**A customer is never charged a price they were not shown. `placeGuestOrder` now compares the basket the customer saw (37-32's `expectedUnitPricePennies` per line and `expectedTotalPennies`) with the basket the server reads at submit, in the same product loop and transaction that snapshots allergens, and refuses with ONE typed diff: 409 `basket-changed` (`BASKET_CHANGED`) whose `changes[]` carries every change — `PRICE_CHANGED {productId, name, expected, current}`, `UNAVAILABLE`, `SOLD_OUT {requested, available}`, `REMOVED {productId}` (the id only, byte-identical for another shop's product and a non-existent id), `BELOW_MINIMUM {minimum, subtotal, detail}` and `TOTAL_CHANGED {expected, current}`. A body without the expectation is 422 `basket-confirmation-required` (CONTEXT Q4: required, like the allergen acknowledgement). When the acknowledged allergen set also changed, the same problem carries the four 31.1 properties so the client re-renders both panels and re-confirms once; when only allergens changed, the 31.1 `allergen-acknowledgement-stale` problem is thrown unchanged — a break arm routing it through `basket-changed` reds four 31.1 arms. Every refusal is thrown inside the reserved idempotency work, so a corrected resubmit under the same key is 201 and one order exists. UXT-007's repro — Suya rendered at £9.00, repriced to £14.00, submitted at £9.00 — was 201 at £14.00 on the pre-fix tree and is 409 naming `Suya 900 → 1400` after. Full suites on the final tree: unit 1753/0, integration 1137/0.**
