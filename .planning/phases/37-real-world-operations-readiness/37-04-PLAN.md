<objective>
Flip `jtoye.access.strict-scoping` to true in every profile and every runtime (D-06), closing UXT-004 (#780) and the
escalation root of UXT-003 (#779).

Purpose: today every staff login is an implicit tenant-wide Group admin and revoking a last grant escalates. The V57
off-ramp already implements ON; this plan makes it the default, proves it under the shipped default (not by reflection),
and adds a gate so no runtime can quietly override it back.

Output: the default IT, the config flip across compose/env/k8s/goldens, the guard script wired into CI, the rewritten
posture log and comments.
</objective>

<feature>
  <name>Strict scoping ON by default</name>
  <files>application.yml, ShopAccessService.java, StrictScopingDefaultIntegrationTest.java, compose, .env.example, k8s configmap and goldens, scripts/check-strict-scoping-default.sh</files>
  <behavior>
    - ungranted vendor token, default config -> POST a product for a shop -> 403 type shop-access-denied; shop_staff row count for that user unchanged (0)
    - same token -> GET /api/v1/staff/me -> 200 {groupAdmin:false, grantedShopIds:[]}
    - OPERATOR GROUP_ADMIN token -> same write -> 201
    - realm admin token -> same write -> 201
    - tenant with only a JIT GROUP_ADMIN row -> that user keeps access (bootstrap) and the WARN is logged; a second JIT admin user -> 403
  </behavior>
  <implementation>Change the default, then fix whatever the default exposes; never set the switch false in a test.</implementation>
</feature>
