# 37-53: T-37-59 closed. On Kubernetes, ClientIpResolver is the only trust list again

Owner decision 2026-10-15: close T-37-59 in the 37-F PR. Branch `phase-37-ops-readiness`.
Commits: `43e908ae` test (RED), `85b6e190` fix, plus the docs commit that carries this file.

## The hole, measured

`core-java/src/main/resources/application.yml` left `server.forward-headers-strategy` unset, and
said that kept Tomcat's RemoteIpValve off. That is false in Boot 4.1.1 (javap of
`spring-boot-tomcat-4.1.1.jar`, `TomcatWebServerFactoryCustomizer`):

- `getOrDeduceUseForwardHeaders()`: if the strategy is null it returns
  `CloudPlatform.getActive(env).isUsingForwardHeaders()`. Otherwise it returns `strategy == NATIVE`.
- `customizeRemoteIpValve()`: the valve is added if `remoteip.protocol-header` OR
  `remoteip.remote-ip-header` has text, OR the method above returns true. Both properties default to
  null, so these two keys add the valve whatever the strategy says.
- `TomcatServerProperties$Remoteip` defaults: `internalProxies` = 192.168/16, 172.16/12, 169.254/16,
  fc00::/7, 10/8, 100.64/10, 127/8, fe80::/10, ::1. `hostHeader` = `X-Forwarded-Host`.
  `protocolHeaderHttpsValue` = `https`.

So on every k8s pod (KUBERNETES_SERVICE_HOST/PORT present → `CloudPlatform.KUBERNETES` →
`isUsingForwardHeaders()` true), any peer in a private range could set three things: the remote
address, the scheme and the HOST. Compose has no cloud platform, so it never had the valve.

## 3. Fix (`85b6e190`)

- `core-java/src/main/resources/application.yml:682`: `forward-headers-strategy: none`, with a
  comment stating the real Boot 4.1 behaviour. The trusted-proxies comment (`:410`) and the
  `ClientIpResolver` javadoc now say this list is the only one.
- `core-java/src/main/java/uk/jtoye/core/security/ForwardHeadersGuard.java`: a
  `WebServerFactoryCustomizer<TomcatWebServerFactory>`, ordered LOWEST_PRECEDENCE so it runs after
  Boot's order-0 customizer. It refuses startup unless the strategy is `none` (`:46`, `:62`), and it
  refuses any `RemoteIpValve` in the factory's live engine-valve list (`:48`). That covers all
  three doors: an env var outranking the yml, an unset key, and `server.tomcat.remoteip.*`.
- `core-java/src/main/java/uk/jtoye/core/security/TrustedProxyForwardedProtoFilter.java`: believes
  `X-Forwarded-Proto` only when `clientIpResolver.isTrustedProxy(peer)` (`:57`) and there is
  exactly one value, `http` or `https` (`:62`). It restores scheme, isSecure, the default port and
  the request URL. It never takes the host from a header. Registered first in the chain, ahead of
  Spring Security, by `ForwardedProtoFilterConfig.java:22`. That is a `@Configuration`, not a
  `@Component`, so `@WebMvcTest` slices stay unaffected.
- No k8s invariant was added. `k8s/**` is outside core-java's write boundary. The in-app guard is
  stronger anyway: it checks the EFFECT, a valve in the pipeline, at startup, whatever produced it.
  A `check-render-invariants.sh` rule could only see the manifest inputs.
