### 2.10 Found at the gate

1. **An integrator can place an order for a product the shop has switched off, and through MCP it goes straight to
   the kitchen (decide before the 37-E PR merges).** `OrderService.createOrder` checks stock quantity but not
   `available`. That is true on origin/main too (`git show origin/main:…/OrderService.java` has no `getAvailable`),
   so the vendor/REST DRAFT path has always accepted it. 37-42 made agent orders submit, so an MCP `create_order`
   for an unavailable product now lands **PENDING in the kitchen's New lane** with no vendor review in between
   (measured: `ORD-…-C3D21C40`, 201 PENDING, product `available=false`; cancelled).

   The storefront refuses the same line (37-33), and 37-40's stated intent was that "the dashboard, REST API and
   MCP refuse what the storefront refuses". The recommended fix is that `createOrder` refuses an unavailable product
   with the same 404 it gives a shop-less one, at least when `submit` is true. That is a small server change with an
   IT, and it would land as a review-fix commit on the PR branch. Not fixed here: it changes what a vendor may order
   from the dashboard, which is a product decision.

2. **The Developers page header overflows at 768 px (the sidebar layout's 512 px main).** "Create credential" ends
   at x=815 in a 768 viewport, and `main` scrolls 559 in 512, so the primary action is clipped until the reader
   scrolls sideways. The same measure is 512/512 on `/dashboard/webhooks` and `/dashboard/staff`, and it is fine on
   this page at 1024 and 1280 (`dev-header-overflow`; screen `developers-list-768.png`).

   The cause is the header row going `sm:flex-row` with no wrap. A likely fix is `lg:flex-row` or `flex-wrap` with
   `min-w-0` on the title block. Recorded in deferred-items, not fixed at the gate: it is a 37-46 layout defect, and
   a UI change needs its own screens. It is a candidate review-fix on the PR branch.

3. **Revoked credentials stay on the Staff page.** A credential that ever made a call keeps a `user_directory` row
   after it is revoked and its Keycloak user deleted, so the Staff page lists "Integration: {name} · No access" for
   it indefinitely. This run left four such rows on the dev tenant (2.12). This is consistent with 37-45's note that
   `user_directory` is an observation cache. Whether revoke should drop the row is the owner's call; it is not a
   defect against any stated contract.
