<objective>
Let a Group admin invite a person by email with the exact grant they will receive (D-07; RWO-004, RWO-003; closes #452 gap 2).

Purpose: under D-06 a self-registered user has no access; the invite is the only onboarding path, and it must carry its grant,
be tenant-scoped, single-use and expiring, and hold its token only as a digest (V62/V75 rule). Accepting it is 37-08.

Output: V77, the invite model/service/controller, the invite email, config wiring, RLS and behaviour tests, the OpenAPI snapshot.
</objective>

  <files>V77, StaffInvite*, CreateStaffInviteRequest, StaffInviteDto, EmailNotificationService.sendStaffInvite</files>
  <behavior>
    - Group admin POST {email:"New@Example.com ", role:"SHOP_MANAGER", shopId:A} -> 201; row email_normalised "new@example.com", token_sha256 64 hex, expires_at = now+72h; one email to new@example.com containing "/invite/{tenantId}." and no other token copy stored
    - same POST again -> 200 same id, still one email
    - role GROUP_ADMIN with shopId -> 400; shopId of tenant B -> 404 (same body as a random UUID)
    - SHOP_MANAGER token POST -> 403 shop-access-denied
    - GET -> the invite with status OPEN; after expiry (clock moved) -> EXPIRED; DELETE -> 204 then status CANCELLED; DELETE again -> 204
    - resend -> 201 new id; old row revoked_at set
  </behavior>
  <implementation>Token issue copies DsarAccessExportService (SecureRandom 32 bytes, base64url, sha256Hex); email after commit.</implementation>
</feature>
