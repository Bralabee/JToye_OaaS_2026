# Sketch 001: Storefront Theme Punch

## Design Question
The live storefront reads weak: no food imagery, identical gradient vendor banners, grey placeholder boxes, no surfaced trust data (FHRS, ratings, ETA), brand reduced to a "J" square. Which of three art directions fixes that — keeping the food-delivery orange/emerald/slate palette, sans-only type (PR #49 editorial direction was rejected), and a designed no-photo fallback?

## How to View
open .planning/sketches/001-storefront-theme-punch/index.html

## Variants
- **A: Market Heat** — market-stall energy: slate chrome + canopy-stripe brand device, flame wordmark, chunky offset-shadow cards, per-vendor diagonal-stripe banner fallbacks, heavy 900-weight display type.
- **B: Enterprise Marketplace** — professional chrome: white/slate surfaces, orange reserved for CTAs, first-class trust layer (FHRS shield, star rating + review count, ETA, verified tick, allergen-count chips), KPI hero panel, dot-grid banner fallbacks.
- **C: Ember Night Market** — dark-mode-first statement: slate-950 canvas, ember-glow gradients and hover halos, live "kitchens cooking now" pulse, per-vendor ember-gradient banner fallbacks, glassy chips.
- **D: Synthesis (B+A)** — ★ WINNER: Enterprise Marketplace structure + trust layer, with Market Heat's flame wordmark, canopy-stripe brand strip, dashed section rules and awning-notch card tops.

## What to Look For
- Which no-photo fallback stops reading as "broken dev fixture"?
- Does the trust layer (FHRS/rating/ETA) earn the "professional/enterprise" brief — and which variant carries it best?
- Which direction still reads as *food delivery* at a glance (the PR #49 failure mode)?
- Brand device: canopy stripe (A) vs restraint (B) vs flame/glow (C) — which is ownable?
