# Quick Task 260710-u1q — k8s backup hardening (#90 / P1-8)

## Root causes (all confirmed)
1. `postgres:15-alpine` (busybox) can't run GNU `date -d` / `grep -oP` under `set -euo pipefail` → exits non-zero every run.
2. `apk add aws-cli` at runtime inside a default-deny NetworkPolicy namespace → fails.
3. No BYPASSRLS role: pg_dump as the app role under FORCE RLS silently captures **0 tenant rows** (proven live: `jtoye_app`→0 products, superuser/BYPASSRLS→25).
4. CronJob references **non-existent** resources: secret `jtoye-secrets` + configmap `jtoye-config`; real ones are `postgres-credentials` + `app-config`. Pod could never start.
5. No NetworkPolicy egress for the backup pod (default-deny blocks DB + S3).
6. `infra/backups/backup.sh:204` retention arithmetic — already fixed in #139 (now `$((deleted_count+1))`).

## Task 1 — Backup image (`infra/backups/Dockerfile`)
`FROM postgres:15-bookworm` (Debian → GNU coreutils/grep; ships pg_dump/pg_restore matching PG15).
`apt-get install awscli ca-certificates`; COPY `k8s-backup.sh` → `/usr/local/bin/backup`; `USER 1000:1000`;
`ENV HOME=/tmp`; `ENTRYPOINT ["/usr/local/bin/backup"]`.

## Task 2 — Hardened backup script (`infra/backups/k8s-backup.sh`, baked)
`set -euo pipefail`. pg_dump `--format=custom --compress=6 --no-owner --no-acl` to /tmp; capture stderr;
explicit rc check + fail-loud + delete-artifact-on-failure. Verify: size floor + `pg_restore --list` readable.
`aws s3 cp` (optional `--endpoint-url` for MinIO). Prune: capture `aws s3 ls` to a var (guard pipefail on empty
bucket), GNU `date -u -d "-${RETENTION_DAYS} days"`, `grep -oE '[0-9]{8}'`, numeric compare. Env-driven config
(no hardcoded values).

## Task 3 — BYPASSRLS role (`infra/backups/create-backup-role.sql`)
Least-privilege: `CREATE ROLE jtoye_backup LOGIN PASSWORD :'backup_password' BYPASSRLS;` + CONNECT + USAGE +
`SELECT ON ALL TABLES` + default privileges. Run as superuser (NOT a Flyway migration — app user can't grant
BYPASSRLS). Password injected via psql var, never hardcoded.

## Task 4 — Rewire CronJob (`k8s/base/pg-backup-cronjob.yaml`)
New image; drop the inline script + `apk add` (use image ENTRYPOINT); DB creds from `postgres-credentials`
(`host`/`port`/`database` + new `backup-username`/`backup-password`); S3 from new `s3-backup-credentials` secret +
`app-config` S3 keys. Keep securityContext/resources/schedule.

## Task 5 — Secret/configmap keys + NetworkPolicy
- `secrets-template.yaml`: add `backup-username`/`backup-password` to `postgres-credentials`; new
  `s3-backup-credentials` (access-key/secret-key) — all `REPLACE_WITH_*` placeholders (no real secrets).
- `configmap.yaml`: add `s3.backup.bucket`/`endpoint`/`region`/`prefix`.
- `networkpolicies/60-pg-backup.yaml` (new): allow pg-backup egress to Postgres (5432) + DNS + S3 (443).
- Register new files in `kustomization.yaml`.

## Task 6 — Runbook (`docs/runbooks/backups.md`)
Add: BYPASSRLS role setup, the FORCE-RLS trap explanation + the proven row-count evidence, restore procedure
(pg_restore for custom format), and a **restore drill** section with recorded RPO/RTO from the local drill;
mark the prod-cluster drill pending.
