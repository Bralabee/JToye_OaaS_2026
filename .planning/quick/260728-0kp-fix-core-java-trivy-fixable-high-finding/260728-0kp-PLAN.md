## Tasks

### Task 1 — Drop the unused `jasperreports` dependency

**files:** `core-java/build.gradle.kts`

**action:** Delete `implementation("net.sf.jasperreports:jasperreports:6.21.3")` (line 80).

**why removal, not the 6.21.3 → 7.0.7 bump:** the dependency is dead weight.
- `grep -r jasperreports core-java/src --include=*.java` → **0 files**
- `find . -name '*.jrxml' -o -name '*.jasper'` → **0 templates**
- `docs/status/SYSTEMS_ENGINEERING_REVIEW.md:776` already flagged it as an unused dependency and
  recommended removal.
- `dependencyInsight --dependency commons-beanutils` proves jasperreports is the **sole** source of
  `commons-beanutils`, by both paths (direct, and via `commons-digester:2.1`).

Removing it therefore clears **3** of the 7 jar findings (#3 and #6) in one edit, and avoids a major
version bump of an unused library into JasperReports 7.x — which changes artifact coordinates and
licensing for zero benefit.

**verify:** `./gradlew :core-java:dependencyInsight --dependency commons-beanutils
--configuration runtimeClasspath` reports no match; `:core-java:compileJava` succeeds.

**done:** neither `jasperreports` nor `commons-beanutils` appears on the runtime classpath.

### Task 2 — Override the Spring-Boot-managed netty version

**files:** `core-java/build.gradle.kts`

**action:** Add `extra["netty.version"] = "4.1.136.Final"` above the `dependencies` block.

Netty is not declared here — `dependencyInsight` shows every netty artifact as
`(selected by rule)`, i.e. pinned by `io.spring.dependency-management` from Spring Boot 3.5.16's
BOM, reaching the graph via `reactor-netty` (spring-boot-starter-webflux) and
`software.amazon.awssdk:netty-nio-client`. Spring Boot's documented override mechanism is the
`netty.version` property, which re-points the imported `netty-bom` and so moves the whole netty
family coherently — rather than forcing two artifacts out of step with their siblings.

4.1.136.Final is the exact fixed version Trivy names for both findings, and stays on the 4.1.x
line Boot 3.5.16 already manages (4.2.x would be an unrequested minor jump).

**verify:** `./gradlew :core-java:dependencyInsight --dependency netty-codec` reports
4.1.136.Final for all netty artifacts.

**done:** clears findings #4 and #5 (4 CVEs).

### Task 3 — Upgrade the two stale Alpine packages in the runtime stage

**files:** `core-java/Dockerfile`

**action:** In stage 2 (`eclipse-temurin:21-jre-alpine`), upgrade `libexpat` and
`p11-kit`/`p11-kit-trust` in the existing `apk` layer.

Both fixed versions were confirmed present in the Alpine 3.23 `main` repository before choosing
this approach (`apk policy` inside the base image showed `2.8.2-r0` and `0.26.2-r0` available) —
the base image simply ships packages predating the fix. A targeted upgrade of the named packages
is preferred over a blanket `apk upgrade` (which would silently move all 85 packages) and over
waiting for a Temurin base-image respin (which is not in our control and would leave `main` red
indefinitely).

Only stage 2 matters: Trivy scans the final image, so the builder stage is out of scope.

**verify:** `docker run --rm <image> apk list --installed | grep -E 'libexpat|p11-kit'` shows
2.8.2-r0 / 0.26.2-r0.

**done:** clears findings #1 and #2 (4 CVEs).
