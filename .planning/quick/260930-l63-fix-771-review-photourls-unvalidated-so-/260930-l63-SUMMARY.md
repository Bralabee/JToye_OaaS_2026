# Phase quick/260930-l63 Plan 01: #771 review photoUrls can no longer destroy catalogue images — Summary

Erasure now deletes a review photo only when its key is the erasing tenant's `reviews/<that review's orderId>/<plain name>` AND no product, shop or media_asset row in the tenant references it. Review creation refuses any other photo URL with a typed RFC 7807 400. The proof runs under NOSUPERUSER with a real Azurite, and was RED first.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `conda run` does not forward heredoc stdin**
- **Found during:** Task 1, step 1.
- **Issue:** `conda run -n jtoye-ops python - <<'EOF'` exited rc 0 without executing the script: stdin was not forwarded. So the first edit and the first `compileTestJava` "rc=0" were vacuous, and the first `git commit` found nothing staged (rc 1).
- **Fix:** every edit script was written to the scratchpad and run as `conda run -n jtoye-ops python <file>`. A probe script proved that form executes (`ran ['x']`). The test commit was made only after `git diff --cached --name-only` showed the file and a real `compileTestJava` executed (`1 executed`).

**2. [Rule 1 - Test design] Break arm 2 was modelled rather than applied literally**
- **Issue:** the literal break ("prefix = tenant `/reviews/` only") leaves every key's remainder as `<orderId>/<name>`. The one-segment name rule then rejects it, so NOTHING is a review photo, OWN is retained too, and the arm tests a different property.
- **Fix:** the arm took the order segment from the key itself (`tenantId + "/reviews/" + parts[2] + "/"`), which models "bound to the tenant only". It produced exactly the predicted outcome: OTHER alone deleted, ORPH kept, and the other-order unit cases RED.

**3. [Rule 1 - Test bug] Nested Mockito `verify`**
- **Issue:** the first draft of the new GdprServiceTest test called `savedRecord()` (a `verify`) inside another `verify(...)` argument, which gave `UnfinishedVerificationException`.
- **Fix:** hoisted the record id into a local first. Test-authoring defect only.

**4. [Sequencing] StorageService edited before its unit tests existed**
- The `publicKeyOf` edit was written before the Task 1 unit tests. To keep the compile RED honest it was parked in the scratchpad and the file restored to HEAD. The unit tests were then written, the compile RED recorded against HEAD's StorageService, and the parked file copied back. Its sha256 `e4b22f05…` matched before and after.

**5. [Plan figure] Unfixed-tree photosDeleted**
- The plan predicted 8; the measured value is 9. See Task 1.
