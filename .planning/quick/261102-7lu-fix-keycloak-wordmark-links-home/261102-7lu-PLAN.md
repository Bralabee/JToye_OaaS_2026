# Quick 261102-7lu: the Keycloak wordmark links home

## Context

A tester stuck on Keycloak's "Email verification" page had no way back to the site: the
"J'Toye" header wordmark on every Keycloak page is not a link. Verified cause: the `jtoye` login
theme is a CSS-only overlay with no FTL overrides (`theme.properties` header; that decision
stands), and the header text is each realm's `displayNameHtml`, a `<span>`.

## Task 1: prove the sanitiser, then change the templates and their renderers

1. Render the customers realm unchanged (RED) and with the anchor (GREEN); start two throwaway
   `quay.io/keycloak/keycloak:26.8.1` containers with plain `docker run` on ephemeral loopback
   ports, `start-dev --import-realm`, the realm at `/opt/keycloak/data/import/` and
   `infra/keycloak/themes` at `/opt/keycloak/themes` (as compose mounts it). Fetch login,
   register and (after a registration POST, with a throwaway Mailhog for the realm's SMTP host)
   the email-verification page; assert `#kc-header-wrapper` holds `<a href="<origin>"`.
2. If the sanitiser strips the tag or the href: STOP and report; propose a one-file
   `template.ftl` override as a recorded exception.
3. Edit both templates; add `PUBLIC_APP_ORIGIN` to all three compose render sites, `.env.example`
   and `verify-env.sh`; teach `staging-realm.jq` to write the staging origin and the staging
   assertion suite to refuse a header that does not link home (selftest gains that defect in its
   raw-customer arm).
4. Theme CSS: `#kc-header-wrapper a` no underline, hover one ramp step, focus ring.

## Task 2: the gate

`scripts/check-keycloak-wordmark-home.sh` (+ `--selftest`), wired in `ci-cd.yaml` beside
`check-no-create-extension.sh`. Show it RED on origin/main's files and GREEN on the branch; run
`check-gate-enforcement.sh`.

## Task 3: rollout note and records

`docs/runbooks/keycloak-wordmark-home.md` with the exact staging and local update (proven on a
throwaway container), README branding section, CHANGELOG top entry (PR number first, second
commit), SUMMARY, `docs-freshness.sh` and `check-doc-metrics.sh`, `check-branch-behind-base.sh`,
PR against main. No merge, no review, no deploy.

## Threat model (ASVS L1)

| Threat | Mitigation |
|---|---|
| T-7lu-01 HTML/attribute injection through the origin value into a page Keycloak serves | `verify-env.sh` accepts only `^https?://host(:port)?$` (no quote, angle bracket, path or list); staging uses a constant; kcSanitize still runs on the value |
| T-7lu-02 a render site leaves the literal `${PUBLIC_APP_ORIGIN}` (a relative href to nowhere) | the CI gate fails on any realm envsubst list without the variable; the staging suite refuses any surviving upper-case token |
| T-7lu-03 the rollout deletes users | the runbook uses a field-scoped `kcadm.sh update`, not `import --override` / `--recreate`; users proven to survive on the throwaway |
| T-7lu-04 open redirect | none: a static link set by the operator, not derived from request data |
