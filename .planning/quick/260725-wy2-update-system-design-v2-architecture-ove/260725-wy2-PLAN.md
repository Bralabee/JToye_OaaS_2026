# Quick Task 260725-wy2 — Refresh the architecture overview to the live topology

## Why

`docs/architecture/SYSTEM_DESIGN_V2.md` §1 still describes the 2025-12-30 design-phase
picture. It is now wrong in ways that matter to anyone reading it as "how the system is
wired": it shows frontend `:3000`/edge `:8080`/postgres `:5433` against a load balancer,
lists Redis and a message queue as *"(Future)"*, and omits MinIO, Ollama, Mailhog and the
MCP server entirely. It also carries no protocol information at all — no reader can tell
from it which hops are REST, which are AMQP, which are STOMP, or which are SSE.

The published "Backend Communication Topology" artifact was verified against the code on
**2026-07-10** and has since drifted (frontend port, MCP server, media/webhook exchanges,
and — materially — the claim that the production STOMP relay fans KDS out across replicas).
This task makes the repo doc the verified source the artifact is regenerated from.

## Scope

Single file: `docs/architecture/SYSTEM_DESIGN_V2.md`, section 1 only.

1. **§1.1** — replace the stale "Current Architecture (Phase 1)" diagram with a verified
   runtime topology (all 11 compose services, real host ports, protocol on every edge).
2. **§1.3** — correct the service-responsibility table (Next.js 16/React 19, Go 1.25,
   Spring Boot 3.5.16) and add the rows that exist now but are missing: mcp-server, MinIO,
   Ollama, SMTP.
3. **§1.4 (new)** — a communication-topology protocol matrix: every hop, its protocol, its
   auth, and its source-of-truth file. Includes the AMQP exchange inventory, the outbound
   webhook egress path, and the STOMP broker-mode split.
4. **§1.5 (new)** — record the confirmed STOMP relay defect (A3) inline, because §1.4
   would otherwise assert a working relay in staging/production that provably does not work.

§1.2 "Target Architecture (Phase 2)" is left alone — it is a deliberate aspiration, not a
drift, and rewriting it is out of scope for this task.
