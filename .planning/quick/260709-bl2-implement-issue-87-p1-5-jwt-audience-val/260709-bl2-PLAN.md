<objective>
Implement GitHub issue #87 [P1-5]: enforce JWT audience validation on BOTH tiers
(core-java and edge-go), harden the Keycloak realm (brute-force protection +
password policy), and stop leaking the refresh token into the client-visible
NextAuth session.

Purpose: Close the token-confusion hole — today a token minted for any other
client in the same Keycloak realm is accepted, and the realm has no brute-force
protection or password policy. The vendor session also copies the refresh token
into the client-readable session, inconsistent with the customer flow.

Output: Additive audience validation (issuer + role mapping preserved), a
fail-closed edge audience gate, a hardened realm template, a refresh-token-free
vendor session, and tests across all three language suites.
</objective>
