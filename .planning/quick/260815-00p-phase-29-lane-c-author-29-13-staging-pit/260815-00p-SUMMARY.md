## Deviations from plan

**[Rule 3 — blocking] The plan's YAML-parse verify line could not run.**
`python3 -c "import yaml…"` is blocked by `block-base-python.py`: no conda env is declared
for this project and the hook does not guess. Declaring one is a repo change outside this
lane's remit, so it was **not** invented. Replaced by **`actionlint`**, which is *strictly
stronger* — it parses the same YAML **and** validates the Actions schema — and which was
itself shown capable of failing. Recorded here rather than substituted silently.

**[Rule 1 — bug in my own change] My comment re-introduced the token the criterion forbids.**
The first draft of the credential comment named `KUBE_CONFIG_STAGING` in prose, so
`rg -uu -c 'KUBE_CONFIG_STAGING' ci-cd.yaml` returned **1** — the classic "a rule that must
spell the token it forbids fires on its own definition" shape. Rephrased; the exact secret
name now lives in the OWED note, which is where an operator will look anyway. Count is now 0.

**[Rule 2 — missing critical functionality] Added a GHCR login step.**
The digest gate resolves expected digests from a **private** registry; without a credential
it would have VOIDed on every run. Added `docker/login-action` (already SHA-pinned elsewhere
in the file) using `GITHUB_TOKEN` under the job-scoped `packages: read` — the least-privilege
form: per-run, cannot push, expires with the job.

**Hazard 1 handled (not in the plan).** Adding a `check-*.sh` moves
`check-handoff-contract.sh`'s denominator. Re-measured rather than trusting the briefing:
**38 → 39**. Both `EXPECT N x rc=0` anchors (HANDOFF.md lines 12 and 2788) updated **in the
same commit** that added the script. Gate rc=0.

**Hazard 2 handled (not in the plan).** `k8s/DEPLOYMENT.md` is in `check-doc-citations`'
scanned set. The new section was written with **no `path:line` citations**, so the gate's
totals are byte-identical to baseline (80/73/**0 violations**). Lane B's repair is not
regressed.

## Two instrument defects found (both false negatives, both caught by controls)

1. **`rg`/`grep` are Claude Code shell functions and do not exist in a `bash script.sh`
   subprocess** — rc=**127**, zero results. An assertion script consequently reported *"no
   `id-token` grant at all"* on a file that has one. Switched to `git grep` inside scripts.
2. **`git grep -n` prefixes the file path**, so `${line%%:*}` extracted the path, not the
   line number — the scope assertion then called all four occurrences "outside the job".
   Fixed to strip the path and to reject an unparseable reference explicitly.

Neither was a product defect. Suspect the instrument first.
