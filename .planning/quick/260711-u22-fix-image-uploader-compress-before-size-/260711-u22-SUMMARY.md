# Phase quick-260711-u22 Plan 01: Fix Image Uploader Compress-Before-Size-Gate Summary

Reordered the vendor image-upload pipeline so a normal large phone photo (12-20MB) is compressed and uploaded instead of being rejected at a misleading pre-compression 10MB gate; compression now always runs before the authoritative 5MB server-cap check, with honest error copy, PNG->JPEG fallback, and a GIF-specific hard limit.

## What Was Built

**Task 1 — Compress-then-gate pipeline (`image-uploader.tsx`)**
- New named constants: `SERVER_MAX_BYTES = 5 * 1024 * 1024` (mirrors core-java `storage.max-file-size-bytes`/multipart 5MB, documented as server-authoritative), `BROWSER_SAFETY_MAX_BYTES = 50 * 1024 * 1024` (canvas-decoder safety cap, explicitly NOT the upload limit), and `JPEG_QUALITY_LADDER = [0.85, 0.75, 0.65]` (reuses existing `JPEG_QUALITY = 0.85` as the first rung).
- Four exported PURE, DOM-free helpers: `validateFileType`, `preflightSizeGate` (the new door gate — GIF>5MB rejected, >50MB rejected, everything else passes), `chooseEncoding` (GIF->keep, transparent PNG->keep PNG, everything else including non-transparent PNG->JPEG ladder), and `enforceServerLimit` (applied to the compressed result).
- Internal canvas-dependent `hasAlphaChannel` (samples ImageData, true if any alpha byte < 255) drives PNG-keep vs PNG->JPEG.
- `compressImage` rewritten as canvas orchestrator: GIFs pass through untouched (animation preserved), dimensions only ever shrink to 1600px (never upscale), transparent PNGs get a single lossless encode, opaque images step down the JPEG ladder and stop at the first blob <= 5MB (returns the smallest produced if none fit — no upscaling to try harder).
- `handleFile` runs the exact order: validateFileType -> preflightSizeGate -> dimension check -> preview/uploading -> compressImage -> enforceServerLimit (returns WITHOUT posting if still oversized) -> FormData POST. The old `file.size > 10 * 1024 * 1024` block and the self-contradicting "Maximum 10MB (will be compressed before upload)" message are deleted.
- Public `ImageUploader` props are unchanged; both consumers (products/page.tsx, shops/page.tsx) compile clean.

**Task 2 — Jest coverage + docs resync (`__tests__/image-uploader.test.tsx`, `docs/metrics.json`)**

Tests import the pure helpers only — no component render, no canvas.
