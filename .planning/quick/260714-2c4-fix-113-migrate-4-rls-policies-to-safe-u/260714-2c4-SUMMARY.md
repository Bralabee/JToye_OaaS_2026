## Decisions Made
- **Scope = 10 policies, not the 4 named in #113.** V43/V47/V50 reused the same raw cast after the audit; a 4-scoped fix leaves 6 identical latent bugs. The named 4 + regression test (acceptance a) are fully covered.
- **Sweep predicate targets `::uuid`, not all GUC reads.** The safe `tenant_id::text = current_setting('app.current_tenant_id', true)` TEXT-comparison policies (orders/customers/shop_*_write) read the same GUC but never cast to uuid — matching them would be a false positive (see Deviation 1).
- **`doWork` raw-connection for the malformed test** to genuinely exercise `'not-a-uuid'` against the hardened helper (see Deviation 2).
- **Guest-tracking `app.customer_email` GUC DB-guard (#113 third item) DEFERRED** — TEXT comparison, no 22P02 risk; a DB-side guard on GUC values is a new mechanism needing design, out of scope for a quick task. #113 acceptance (a) and (b) both delivered.

### Auto-fixed Issues

**1. [Rule 1 - Bug] pg_policy sweep predicate refined to the `::uuid` cast**
- **Found during:** Task 1 (RlsContractTest sweep)
- **Issue:** The plan's literal sweep pattern `LIKE '%current_setting('app.current_tenant_id'%'` would also match the safe `tenant_id::text = current_setting('app.current_tenant_id', true)` TEXT-comparison policies (V5/V9/V28/V29), which are NOT the 22P02 bug class and are correctly excluded from the plan's own table-of-10 — so the literal predicate would be permanently RED after V51.
- **Fix:** Scoped the predicate to require BOTH `current_setting('app.current_tenant_id'` AND `::uuid` in the rendered expression (aligns with must_haves truth #3: "raw `current_setting()::uuid` cast"). Documented the exclusion in the test Javadoc and V51 header.
- **Files modified:** RlsContractTest.java, V51__rls_uuid_cast_safety.sql (NOTE comment)
- **Verification:** `RlsContractTest` 4/4 green; sweep returns empty against final schema.
- **Committed in:** `5a76666`

**2. [Rule 1 - Bug] Malformed-GUC test moved to raw-connection `doWork` (anti green-by-construction)**
- **Found during:** Task 1 (first integration run — `tenantIsolationPreservedUnderValidGuc` failed: tenant A saw 0 rows)
- **Issue:** `TenantSetLocalAspect.setTenantBeforeDbOps` fires `@Before` every JdbcTemplate call and, when `TenantContext` is empty, runs `SET LOCAL app.current_tenant_id TO DEFAULT` — wiping any manually `set_config`-injected GUC before the assertion query runs. This (a) broke the valid-GUC isolation assertion and (b) silently canonicalized `'not-a-uuid'`/`'default'` to `''`, so the function-hardening claim was green-by-construction.
- **Fix:** Isolation test now drives the GUC via `TenantContext.set()` (production path, valid UUID). Malformed test runs its role-drop + `set_config` + assertions inside `Session.doWork` on the raw transaction connection, which the aspect's JdbcTemplate pointcut does not match — so `'not-a-uuid'` genuinely reaches the hardened helper, plus an explicit `SELECT current_tenant_id()` NULL assertion.
- **Files modified:** RlsUuidCastSafetyIntegrationTest.java
- **Verification:** `RlsUuidCastSafetyIntegrationTest` 3/3 green.
- **Committed in:** `5a76666`
