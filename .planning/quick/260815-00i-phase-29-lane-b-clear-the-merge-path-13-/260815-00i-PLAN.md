<proof_rules>
These are not optional colour. They apply to every task below and the plan is not satisfied without
them. They come from `CLAUDE.md` "Proof Standards" and from measurements this repo has already paid
for.

**P-1 — Commit BEFORE any break arm.** `git checkout` restores from the INDEX, not from HEAD, so an
uncommitted edit made after staging is silently discarded by the restore. Commit, then break.

**P-2 — Verify every restore BY CONTENT.** `git hash-object <file>` before the break and after the
restore; the two hashes must be equal and both must be PRINTED. `git diff --stat` is empty both when
a file is restored and when it was never written, so it proves nothing.

**P-3 — Assert the clean state LAST as well as first.** Every break arm is a triple: clean → broken →
clean again. The closing arm is the only thing that proves the restore happened. This repo has caught
three silently-failed restores with the closing arm and zero with the break arm.

**P-4 — Capture rc on the SAME statement as the command.**
`out=$(cmd 2>&1); rc=$?` — never `echo "$out"; echo "rc=$?"`, which reports the echo's status.

**P-5 — Never `cmd | grep -q X` under `set -o pipefail`.** grep exits on first match, the writer takes
SIGPIPE, pipefail promotes it to 141, and the guard fires on the SUCCESS case. Use a here-string:
`grep -q X <<< "$out"`.

**P-6 — `rg` and `grep` are Claude Code shell FUNCTIONS.** They honour `.gitignore`, and there is no
system ripgrep behind them, so any wrapper that EXECs (`timeout rg`, `xargs rg`, `env -u X rg`, or
`rg` inside a `bash script.sh` subshell) dies rc=127 with ZERO results — indistinguishable from a
clean "not found". Lane A hit exactly this. When a count or a "not found" is EVIDENCE, use `rg -uu`,
print the rc, and run a positive control that is KNOWN to match.

**P-7 — rc=2 is VOID, never pass.** Both gates in this lane exit 2 for "could not evaluate". Treat a 2
as a hard stop and say so; never fold it into a green summary.

**P-8 — A gate certifies what it measures, not what you want.** `check-doc-citations` C-3 asserts that
a strong token from the claim appears on the cited line. A token like `nvidia` or `jtoye-images`
appears on several lines in these files, so a citation can turn the gate green while still pointing
at a comment rather than the definition. Every repaired citation is therefore verified TWICE: the
gate goes green, AND the newly-cited line is read back and confirmed to be the site the claim
describes.
</proof_rules>

The horizon rows live in `infra/dependency-horizons.yaml`; `scripts/check-dependency-horizons.sh` is

**The trap, confirmed by reading the source rather than the docstring.** `--refresh` is NOT a
line-number sweep. Its writer (lines 460-545) rewrites TWO kinds of field:

- `sites:` entries, from a fresh in-file search for the row's `pin` (both inline `[...]` and block
  `- "…"` forms, at any length)
- `eol_date:`, from `catalogue(slug, cycle)`, which reads the JSON that the H-2 stage just fetched
  LIVE from `endoflife.date` into a fresh `mktemp` cache

So a refresh can silently move a real EOL horizon while producing a diff that LOOKS like a
line-number sweep. It must be classified, not skimmed.

**Network is mandatory and its absence is a VOID, not a pass.** The fetch loop (lines 247-266) runs
before the refresh block and VOIDs on: unreachable host, non-200, an unexpected effective host, a
redirect, or empty/unparseable JSON. The cache is a fresh `mktemp -d` per run, so there is no stale
cache to fall back on. If the baseline run does not complete rc=0 with a live fetch, STOP and report
VOID. Do not run `--refresh` from a failed run.
