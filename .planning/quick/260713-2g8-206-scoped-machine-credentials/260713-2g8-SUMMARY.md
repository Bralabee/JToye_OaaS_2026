## Accomplishments
- **Combined role+scope converter (`JwtRolesAndScopesConverter`)** — composes the #83 `KeycloakRealmRoleConverter` (`realm_access.roles → ROLE_*`) with the stock `JwtGrantedAuthoritiesConverter` (`scope → SCOPE_*`), returning their union. The #83 converter had *replaced* Spring's default, discarding all `SCOPE_*` mapping; this restores it additively. Wired into `SecurityConfig` in place of the bare role converter.
- **Positive write-scope gate** on all nine `ProductController` mutations (`create`, `update`, `delete`, `uploadImage`, `addAdditionalImage`, `removeAdditionalImage`, `removeImage`, `bulkImportCsv`, `bulkImportImages`) via `@PreAuthorize("hasAuthority('SCOPE_catalog:write')")`. Reads (list/get/search/template/label/analyze) stay authenticated-only, so a `catalog:read`-only token still lists.
- **Realm catalog scopes + read-only machine client** — `catalog:read`/`catalog:write` (+ `orders:read`/`orders:write`, defined-only) client scopes; `core-api` default-grants both catalog scopes (operators unchanged after re-import); sample `integration-catalog-ro` client (client-credentials, `catalog:read` only, tenant-id + core-api audience mappers) with a SA user carrying a `tenant_id` attribute. `INTEGRATION_CATALOG_RO_SECRET` wired as an envsubst placeholder into all three compose renderers + both `.env.example` + `verify-env.sh`.
- **OpenAPI advertisement + docs** — `catalog-scopes` OAuth2 client-credentials scheme in the regenerated snapshot; `docs/security-scopes.md` (taxonomy, client-credentials recipe, re-import migration note, KC24 managed-attribute trap, #203 MCP feed-forward).
- **Full Java suite green** after the converter swap (foundational bean in every `@SpringBootTest` context); `docs-freshness` resynced 1199 → 1208.

## Decisions Made
- **Scope, not role, is the write discriminator.** Operators carry no distinguishing realm role (`default-roles-jtoye-dev` expands only to `offline_access`+`uma_authorization`), so `core-api` default-grants `catalog:write` rather than inventing/assigning a `vendor` role — smaller, purely additive, keeps AC-2 with zero test edits.
- **Reads authenticated-only.** No `SCOPE_catalog:read` gate on reads, so the read-only machine token (and every existing reader) keeps its 200 with no blast radius.
- **Fail-closed stale-token posture, asserted.** Tokens minted before the realm re-import lack `catalog:write` and 403 on writes until re-login — an explicit test contract (`noScopeTokenForbiddenOnCreate`), same posture as #87/#88.
- **`orders:*` defined-only.** Seeds the [AI-1]/#203 MCP taxonomy without enforcement; enforcing the order surface is a follow-up.
