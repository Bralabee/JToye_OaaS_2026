# Quick Task 260801-hb9: Nightly full-suite E2E workflow (#420 part 1)

## Problem

CI runs `e2e/public-layout.spec.ts` only — **2 of 126 tests**. The other 12 specs need a
full stack (Postgres + Keycloak + core-java + MinIO + RabbitMQ) that the per-PR runner
does not stand up. #404 is the record of what that costs: a broken customer sign-in
shipped and sat undetected because the suite that would have caught it was itself
unwatched.

This closes the **CI-coverage half** of #420. The skip half already landed (#423).

## Decisions (and why — do not re-litigate without reading)

| decision | why |
|---|---|
| **Nightly + `workflow_dispatch`, not per-PR** | The stack build is ~20 min and the suite ~20 min. Per-PR that is an unacceptable tax on every change; nightly catches regressions within a day, which is strictly better than the current *never*. |
| **Exclude `ollama` and `ollama-init`** | `ollama-init` pulls `gemma3:12b` (~8 GB — the runner has ~14 GB total) and `ollama` declares `deploy.resources.reservations.devices: nvidia`, which no GitHub-hosted runner provides. `core-java.depends_on` is postgres/keycloak/redis/rabbitmq only, so the stack is complete without it. Image-analysis is the only surface lost, and no spec asserts on it. |
| **Generate ephemeral secrets in-job** | All 16 `REQUIRED_VARS` are throwaway credentials for a stack that lives ~40 min. `verify-env.sh` rejects weak values (`DENY_EXACT`, `CHANGE_ME*`), so they must be genuinely random — not placeholders. No repository secret is needed, so the workflow cannot leak one. |
| **`DemoDataSeeder` supplies the base fixtures** | It is `@Profile("dev")` + `ApplicationRunner`, and compose sets `SPRING_PROFILES_ACTIVE: dev`, so a fresh DB self-seeds the demo tenant's shops/products/customers on first boot. `seed-e2e-fixtures.sh` then adds only the DRAFT order + promo. |
| **Fail closed at every step** | A stack that does not come up, a report that is absent or contains zero tests, or a non-zero skip-budget rc is a FAILURE. `check-e2e-skip-budget.sh` already exits 2 (VOID) rather than 0 on an absent report; the job must not swallow that. |
| **`continue-on-error` is used NOWHERE** | The entire point is a signal that can go red. |

## Tasks

### Task 1 — `.github/workflows/e2e-nightly.yml`

**files:** `.github/workflows/e2e-nightly.yml` (new)

**action:** Scheduled workflow that:
1. checks out, sets up Node 24 + Java 21;
2. writes an ephemeral `.env` with 16 randomly generated secrets, then runs
   `scripts/verify-env.sh` (credential half only) to prove the file satisfies the contract;
3. `docker compose -f docker-compose.full-stack.yml up -d --build` over an **explicit
   service list** that omits `ollama`/`ollama-init`;
4. waits for core-java `/actuator/health` and the frontend, with a deadline and a
   `docker compose logs` dump on timeout;
5. runs `scripts/seed-e2e-fixtures.sh`;
6. runs the full Playwright suite with `--reporter=json` into
   `frontend/e2e-artifacts/report.json`;
7. asserts the report exists and reports > 0 tests **before** trusting it;
8. runs `scripts/check-e2e-skip-budget.sh`;
9. uploads report + traces + stack logs `if: always()`.

**verify:** `actionlint` parses it; the service list contains no `ollama`; no
`continue-on-error` anywhere in the file.

**done:** Workflow file exists, is valid YAML, and every failure path exits non-zero.

### Task 2 — retire the now-false comment in the skip-budget gate

**files:** `scripts/check-e2e-skip-budget.sh`

**action:** Its header says *"The suite needs the full compose stack, which CI does not
have (#420)"*. Once this workflow exists that is no longer true in general — it is true
of the **per-PR** runner only. Narrow the claim rather than deleting it; the reason the
gate does not run the suite itself is still valid.

**verify:** `bash scripts/check-e2e-skip-budget.sh` still exits 0 on the current report;
`bash scripts/check-claims.sh` still exits 0.

**done:** The comment describes the post-change world accurately.

## Out of scope (stated so it is not mistaken for coverage)

- **The nightly job is not proven green by this task.** It cannot be: it needs a merged
  default-branch workflow and a scheduled or dispatched run. The deliverable is a correct,
  fail-closed workflow plus a `workflow_dispatch` trigger so the first real run can be
  triggered deliberately and watched.
- The 8 declared skips are untouched — 4 of them need Stripe keys or a scaled stack
  (§2.2 of HANDOFF.md), which are environment decisions, not CI work.
