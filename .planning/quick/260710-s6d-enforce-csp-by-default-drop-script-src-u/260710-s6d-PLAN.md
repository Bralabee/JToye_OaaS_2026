# Quick Task 260710-s6d — CSP enforce + nonce (#89 / P1-7)

## Problem
CSP ships as `Content-Security-Policy-Report-Only` unless `CSP_ENFORCE=true`, and even
the enforcing form carries `script-src 'unsafe-inline'` — gutting XSS protection.

## Why this needs middleware (not a config flip)
CSP lives in `next.config.mjs` `headers()`, a **static** header. Dropping
`'unsafe-inline'` without breaking Next's inline bootstrap scripts requires a
**per-request nonce**, which only middleware can produce. Recon confirmed this is safe:
- `/dashboard` is gated **server-side** (`app/dashboard/layout.tsx` `await auth()` + redirect);
  there is **no `authorized` callback**, so broadening the middleware matcher to all routes
  cannot accidentally gate public routes.
- **No app inline `<script>` / `next/script` / `dangerouslySetInnerHTML`** anywhere — the only
  inline scripts are Next's framework bootstrap, which Next auto-nonces from the `x-nonce`
  request header. No per-component nonce threading needed.

## Decisions (locked)
- **Nonce + `'strict-dynamic'`** (Next canonical CSP pattern). `script-src 'self' 'nonce-{n}'
  'strict-dynamic' https://js.stripe.com https://*.js.stripe.com` (+ `'unsafe-eval'` in dev only).
  Modern browsers trust nonce + propagation (Next chunks, and Stripe.js injected by nonced app
  code); the Stripe hosts stay for the unit-test assertion + non-strict-dynamic fallback.
- **`style-src 'unsafe-inline'` STAYS** — the AC only forbids `unsafe-inline` in *script-src*;
  nonce-ing Tailwind/Next inline styles is out of scope and impractical.
- **Enforce by default; report-only becomes an opt-OUT** via `CSP_REPORT_ONLY=true`
  (inverts today's `CSP_ENFORCE` opt-in).
- **`upgrade-insecure-requests` gated behind `CSP_UPGRADE_INSECURE_REQUESTS=true` (default off).**
  The local Docker stack runs `NODE_ENV=production` yet serves over http with MinIO images at
  `http://localhost:9000`; unconditional upgrade would break images + local E2E. Prod sets the flag.
- **CSP moves to middleware; the 3 static headers** (X-Content-Type-Options, Referrer-Policy,
  Permissions-Policy) **stay in `next.config.mjs`**.
- Compose with auth via `export default auth((req) => applyCsp(req))` + broad matcher — keeps the
  dashboard defence-in-depth session resolution, adds CSP everywhere.

## Task 1 — `frontend/lib/security-headers.ts` (new)
Pure `buildCsp({ nonce, isDev, keycloakOrigin, apiOrigin, upgradeInsecure })` → CSP string,
preserving every current directive except: script-src gains `'nonce-{n}' 'strict-dynamic'` and
loses `'unsafe-inline'`; upgrade-insecure-requests gated on `upgradeInsecure`. Derives `wss://`
from apiOrigin (`/^http/→ws`), keycloak form-action + connect-src exactly as today.
**verify:** unit test asserts no `'unsafe-inline'` in script-src, presence of `'nonce-`,
`'strict-dynamic'`, Stripe hosts, keycloak form-action, wss connect-src.

## Task 2 — `frontend/middleware.ts` (rewrite)
Per Next canonical pattern: generate `nonce = base64(crypto.randomUUID())`; set `x-nonce` +
`Content-Security-Policy` on the **request** headers (so Next nonces its scripts); set the CSP on
the **response** (`Content-Security-Policy`, or `-Report-Only` when `CSP_REPORT_ONLY=true`).
Wrap in `auth(...)`; matcher = all routes except `/api`, `_next/static`, `_next/image`, favicon,
and static asset extensions.
**verify:** `npm run build` compiles; live curl shows enforcing CSP with nonce.

## Task 3 — `frontend/next.config.mjs`
Remove the CSP entry + the `cspDirectives`/`cspEnforce` block from `headers()`; keep the 3 static
headers. Leave a comment pointing to `middleware.ts` for CSP.
**verify:** `csp-headers` unit test's static-header assertions pass.

## Task 4 — Rework tests + snapshot
- `__tests__/csp-headers.test.ts`: test `buildCsp()` (new assertions above) + next.config's
  remaining 3 static headers.
- `__tests__/header-snapshot.test.ts` (+ `.snap`): snapshot the static headers (now sans CSP)
  plus a `buildCsp()` string with a fixed nonce. Regenerate with `-u`.
**verify:** `npm test` green; `npm run build` (tsc) green.

## Task 5 — Live E2E proof (the AC gate)
Rebuild the frontend Docker image, restart it, then:
`PLAYWRIGHT_BASE_URL=http://localhost:3100 npx playwright test e2e/csp-no-violations.spec.ts`
Expect: enforcing `content-security-policy` header present, zero violations on homepage /
storefront / dashboard. Spot-check images still render (upgrade-insecure off locally).
**done:** All three specs pass; enforcing header confirmed via curl; no console CSP violations.

## Out of scope
- Removing `style-src 'unsafe-inline'` (nonce-ing styles).
- Enabling `upgrade-insecure-requests` for the local stack (prod-only flag).
