# Quick Task 260830-p2o: The unexamined-defaults audit

## Why (the class, named)

The 1400px container survived every instrument because (a) it was an inherited default no
one declared, so no gate had a contract to hold; (b) it only bound at viewports outside
the tested envelope (390 and 1440 are the ONLY browser windows any instrument uses); and
(c) it was a judgement-class defect camouflaged as intent. This audit hunts the rest of
that class deliberately instead of waiting for the owner's eye.

## Scope — three sweeps, bounded

**A. Static: which defaults are load-bearing and unratified.**
- `tailwind.config.ts` theme delta: everything NOT overridden is Tailwind's default —
  type scale, spacing, radii, shadows, breakpoints. Which of those defaults carry
  owner-visible weight?
- Vendored shadcn components never edited since being added (`git log --follow` count =
  1) — pure upstream defaults running in production UI.
- Known-suspect concrete defaults: toast placement/duration/limit (`use-toast.ts`
  carries shadcn's `TOAST_LIMIT = 1`, `TOAST_REMOVE_DELAY = 1000000` — ~16.7 min),
  dialog/sheet max-widths, table density, focus rings, transition durations.
- Deliberately OUT: palette (#232/#451 ratified), Work Sans (ratified), width tiers
  (Phase 35 ratified), /track 512px (exceptions ledger).

**B. Browser: the envelope nobody tests.**
- Viewport gap: instruments use 390 and 1440 only; the layout spec adds 1920/2560 for
  width only. Probe **768×1024 (tablet portrait), 1024×768 (small laptop)** across:
  `/dashboard`, `/dashboard/orders`, `/dashboard/products`, `/dashboard/orders/<id>`,
  `/`, `/shop`, `/shop/<slug>`. Look for: horizontal document overflow, chrome collisions
  (sidebar vs content), stranded/hugging content, unreadable density.
- Content-shape gap: a REAL product with a ~200-char name + long description via the API
  (cleaned up after), viewed on the dashboard list, the storefront card grid and the
  shop detail — truncation vs overflow vs layout break.
- Persistence check on the toast default: does an error toast auto-dismiss at all?

**C. Report + file.**
- `AUDIT.md` in this directory: one row per finding — surface, the default, evidence,
  classification (RATIFY = fine but should be declared / FIX = defect / OWNER-CALL =
  judgement for Sanmi / N-A = examined, harmless), and for FIX/OWNER-CALL the issue number.
- No product fixes in this task. The deliverable is the honest list.

## Verification

Every browser claim carries a screenshot or a measured number; every "default unmodified"
claim is a `git log` fact; negative results ("examined, harmless") are recorded so the
audit is a sweep, not a highlight reel. Instrument rule: any probe must be shown able to
fail (e.g. the overflow check must fire on a deliberately narrowed container) before its
clean result is believed.
