## Decisions Made

- **Bundle into one migration, not three.** Items 3, 4, 5 share a deployment boundary; partial application would leave the DB in an unsafe state (idempotency without FORCE RLS, or vice versa). LOCKED in 16.1-CONTEXT.md and respected here.
- **No IF EXISTS / IF NOT EXISTS guards.** Forward-only is mandatory per CONTEXT key_constraints — fail loud if state has drifted, don't silently continue with looser policies.
- **processed_stripe_events stays outside RLS.** Stripe event_ids are globally unique; the webhook handler runs before TenantContext is set; pruning of historical rows is deferred to a separate housekeeping phase per CONTEXT decisions.
- **EXISTS subquery layout adjusted to single line.** The plan's `<action>` template wrote the EXISTS subquery across 5 lines for readability; the plan's verbatim acceptance grep `grep -c "EXISTS (SELECT 1 FROM orders"` requires same-line matching. SQL semantics are whitespace-insensitive, so I rewrote the subquery as `AND EXISTS (SELECT 1 FROM orders o WHERE … )` on a single logical line. This is a cosmetic change only — the policy condition is functionally identical to the template. Documented here as a transparency note rather than a Rule 1/2/3 deviation because it does not change behaviour.

## Deviations from Plan

None — plan executed exactly as specified by the LOCKED CONTEXT decisions.

The single SQL-layout adjustment (EXISTS clause onto a single physical line so the verbatim acceptance grep matches) is documented under "Decisions Made" above. It does not change SQL semantics, the policy text, or the runtime behaviour — both layouts produce identical Postgres parse trees.

## Issues Encountered

- Initial run of the acceptance grep `EXISTS (SELECT 1 FROM orders` returned 0 because the literal SQL template in the plan placed `EXISTS (` and `SELECT 1 FROM orders o` on separate lines. Resolved by rewriting the subquery onto a single logical line (whitespace-insensitive in SQL, no semantic change). All 9 acceptance-criteria gates passed on the second run.
