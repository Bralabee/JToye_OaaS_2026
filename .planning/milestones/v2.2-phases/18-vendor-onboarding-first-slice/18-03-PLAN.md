<objective>
Implement the `FOOD_HYGIENE_RATING` gate — the industry's single hard vetting rule — end to end: an `FhrsClient` that queries the free FSA FHRS Open Data API (with the mandatory `x-api-version: 2` header and a `fhrs` circuit breaker) and an `FhrsGate` that maps the result to PASSED / FAILED / MANUAL_REVIEW against the configured `min-rating` (2). Registering `FhrsGate` as a Spring bean auto-plugs it into the 18-02 `GateChainRunner` registry — so on submit it materialises + evaluates with no runner edits.

Purpose: turn the hygiene rating into an automated, config-driven gate with a human fallback, so a vendor is auto-verified without manual review yet is never hard-failed on a fuzzy name/address match.
Output: `FhrsGate`, `FhrsClient` + response mapping type, and unit tests (gate logic + WebClient header/circuit-breaker behaviour) that use only already-present test dependencies.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| core-java → FSA FHRS API (egress) | Outbound HTTP to a fixed, config-supplied base URL; vendor-supplied name/address become query params |
| FSA response → gate decision | A missing version header or a spoofed/empty body must never silently PASS a vendor |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-03-I | Information Disclosure (SSRF) | outbound FHRS URL | mitigate | Base URL comes only from OnboardingProperties (config, not request); vendor input is confined to URL-encoded query params, never the host/scheme — no user-controlled URL, no SSRF surface |
| T-18-03-T | Tampering | empty/garbled FSA body treated as pass | mitigate | Mapping defaults unknown/empty/ambiguous to MANUAL_REVIEW; only an explicit numeric rating >= min-rating or FHIS "Pass" yields PASSED |
| T-18-03-D | Denial of Service | slow/erroring FSA API blocks submit | mitigate | Explicit WebClient timeout + `@CircuitBreaker(name=fhrs)`; runs on the @Async gate worker so the submit request is not blocked; failure degrades to MANUAL_REVIEW |
| T-18-03-SC | Tampering | new package installs | accept | No new gradle dependency — WebClient (spring-webflux) + Mockito already present; tests use an in-memory ExchangeFunction stub, not WireMock; package-legitimacy gate not triggered |
</threat_model>
