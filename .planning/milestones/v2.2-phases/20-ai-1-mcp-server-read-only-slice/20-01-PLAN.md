<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external agent → MCP server (POST /mcp) | Untrusted tool args + opaque Bearer cross here |
| MCP server → core-java (:9090) | Bearer forwarded verbatim; core is the real validator |
| core-java → PostgreSQL (RLS) | tenant_id claim scopes every row (isolation happens here, not in MCP) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | Information Disclosure | core-client.ts / logging | mitigate | Log tool name + core status ONLY; never log the Bearer or response bodies (order/customer PII). Divergence from the Go analog which logs `body`. |
| T-20-04 | Tampering / Info Disclosure | core-client.ts base URL | mitigate | `CORE_BASE_URL` is a fixed compose env (`http://core-java:9090`), never caller-controlled; tool paths built from allow-listed templates only (SSRF guard). |
| T-20-05 | Information Disclosure | errors.ts | mitigate | Map problem+json / bare status → sanitized generic isError text; never forward err.stack, undici internals, upstream body, or the token. |
| T-20-88 | Spoofing / Elevation | forwarded Bearer (audience/expiry) | transfer | MCP performs NO token validation; core-java enforces the `core-api` audience (#88) + expiry/issuer (#87). An audience-less or expired token forwarded verbatim is rejected by core (401/403) and surfaces as a sanitized isError — the MCP server never makes an authorization decision. |
| T-20-RLS | Information Disclosure / cross-tenant | core-java → PostgreSQL | transfer | Cross-tenant isolation is enforced by Postgres FORCE RLS keyed on the token `tenant_id` claim, NOT by MCP code. A confused/hostile agent cannot cross tenants; proven at the live HTTP boundary in 20-05 (`e2e-rls.sh`), never by superuser Testcontainers. |
| T-20-SC | Tampering | npm install (6 packages) | mitigate | Blocking-human package legitimacy checkpoint (Task 1) before first install; slopcheck unavailable → all [ASSUMED], verified on npmjs.com; never auto-approvable. |
</threat_model>
