<objective>
Implement Spring Security 6 response headers per ASVS 14.4.x (SEC-03). Every Spring Boot response carries X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin. HSTS is gated by prod profile via runtime env.getActiveProfiles() check inside the existing single SecurityFilterChain bean — no duplicate bean, no @Profile on the chain itself.

Purpose: close the browser-security header gap flagged in the 2026-04-16 deep audit. Mitigates T-12-01 (clickjacking), T-12-02 (MIME sniffing), T-12-03 (referrer leak), T-12-04 (protocol downgrade).

Output:
- Modified SecurityConfig.java with .headers(...) DSL block
- Three integration tests (baseline + prod-profile + dev-profile)
- Golden snapshot file for regression detection

Spring Security 6 lambda DSL for headers (canonical, PATTERNS.md lines 96-108):

```java
import java.util.Arrays;
import org.springframework.core.env.Environment;
import org.springframework.security.web.header.writers.ReferrerPolicyHeaderWriter;

boolean isProd = Arrays.asList(env.getActiveProfiles()).contains("prod");
http.headers(headers -> {
    headers.frameOptions(frame -> frame.deny())
           .contentTypeOptions(Customizer.withDefaults())
           .referrerPolicy(r -> r.policy(
               ReferrerPolicyHeaderWriter.ReferrerPolicy.STRICT_ORIGIN_WHEN_CROSS_ORIGIN));
    if (isProd) {
        headers.httpStrictTransportSecurity(hsts -> hsts
            .includeSubDomains(true)
            .maxAgeInSeconds(31_536_000L));
    } else {
        headers.httpStrictTransportSecurity(hsts -> hsts.disable());
    }
});
```
